    Create pipeline/commands/parse.py implementing `async def run_parse(args)`.

    The function must follow this sequence:

    1. **Load pipeline_run from DB:**
       Open async session. Fetch PipelineRun by args.run_id. If not found, raise ValueError(f"No pipeline_run with id={args.run_id}").
       If run.status not in ("pending",): print warning "Run {id} already has status {status}; re-running will create new utterance rows" (allow re-run per PIPE-11).

    2. **State transition: pending → running (PIPE-10):**
       ```python
       async with session.begin():
           run = await session.get(PipelineRun, args.run_id)
           run.status = PipelineRunStatus.RUNNING
           run.strategy = "rule_based"  # may be updated to "llm_corrective" after LLM pass
       ```

    3. **Extract pages:**
       Get the PDF path from run.pdf_path. Call extract_pages(Path(run.pdf_path)) to get a list of page strings.

    4. **Rule-based parse pass:**
       Call parse_transcript(pages) from pipeline.parser.state_machine. This returns a list of dicts with sequence, raw_speaker_label, text, is_stage_direction, section_hint, side.

    5. **LLM corrective pass (conditional):**
       Join all pages into a single text string. Call parse_with_llm(pages_text) wrapped in try/except:
       - On success: merge LLM results with rule-based results (LLM output takes precedence for utterances where raw_speaker_label is UNKNOWN or is_stage_direction classification is uncertain)
       - On InstructorRetryException (structural failure): set run.strategy="rule_based", set run.failure_reason=str(exc), set run.status=PipelineRunStatus.FAILED, commit, return early
       - On RateLimitError / APIConnectionError after all tenacity retries: same — set FAILED + failure_reason
       - On success: update run.strategy="llm_corrective"

       **For Phase 1 PoC:** Keep the LLM pass simple — use the rule-based results as the primary output. The LLM pass can be invoked but the merge logic can be: if LLM returns successfully, replace the rule-based utterance list with LLM output (the spike shows the LLM is called once on the full text and returns the complete utterance array). If LLM fails, fall back to rule-based output and log the failure.

    6. **Write utterance rows (PIPE-03, PIPE-04, PIPE-11):**
       For each utterance dict in the final utterance list:
       - Create Utterance(
           argument_id=run.argument_id,
           pipeline_run_id=run.id,
           sequence=u["sequence"],
           raw_speaker_label=u.get("raw_speaker_label"),
           text=u["text"],
           is_stage_direction=u["is_stage_direction"],
           section_hint=u.get("section_hint"),
           side=SideEnum(u["side"]),
           person_id=None,  # null at parse time; Phase 2 populates
           strategy=run.strategy,
         )
       - Add all to session, commit.
       - **Do NOT delete prior run utterances** — new rows link to the new pipeline_run_id (PIPE-11).

    7. **State transition: running → completed (PIPE-10):**
       ```python
       async with session.begin():
           run.status = PipelineRunStatus.COMPLETED
           run.completed_at = datetime.now(timezone.utc)
       ```

    8. **Dry-run mode (--dry-run):** If args.dry_run is True, skip step 6 (utterance writes) and step 7 (completed status). Print the utterance count only. This allows testing the parse logic without writing to DB.

    9. **Print summary:** f"Parse complete. {len(utterances)} utterances written. strategy={run.strategy}"

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Transcript text → LLM (Claude API) | Pre-cleaned transcript text sent to Anthropic API; response validated by instructor |
| LLM response → DB | instructor validates Pydantic schema before any DB write |
| ANTHROPIC_API_KEY | Loaded from .env only; never logged or hardcoded |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | LLM prompt injection via transcript | mitigate | Transcript text is pre-cleaned (normalize_text removes soft hyphens; pdfplumber strips formatting). instructor schema validation rejects any response where utterances don't match ParsedUtterance structure. If transcript contained adversarial content trying to override system prompt, instructor would reject the malformed output and retry up to max_retries=2. |
| T-04-02 | Information Disclosure | ANTHROPIC_API_KEY in logs | mitigate | Key is loaded from .env via load_dotenv(). Never passed as a CLI argument. The parse command prints run status but never the API key. .env is gitignored. |
| T-04-03 | Denial of Service | Tenacity over-retrying on structural failures | mitigate | Structural failures (InstructorRetryException, BadRequestError) are caught and not retried by tenacity. Only transient errors (RateLimitError, APIConnectionError) trigger the outer tenacity loop (stop_after_attempt=5). |
</threat_model>
