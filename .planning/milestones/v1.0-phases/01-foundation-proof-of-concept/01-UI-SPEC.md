# Phase 1 — UI Design Contract

> Visual and interaction contract for the Phase 1 minimal chat view.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — plain Tailwind CSS with bespoke components |
| Preset | not applicable |
| Component library | none (Phase 1 is greenfield; components hand-authored in Svelte 5) |
| Icon library | none (Phase 1 has no icons — text-only speaker labels) |
| Font | system-ui stack (no web font fetch in Phase 1 PoC) |

**Rationale:** No shadcn. SvelteKit's shadcn port (shadcn-svelte) adds a `components.json` dependency layer and a third-party registry for Svelte-adapted Radix primitives. For a PoC with three bespoke components (`ChatBubble`, `StageDirection`, layout wrapper), the overhead is not justified. Tailwind CSS alone is sufficient and keeps the dependency tree minimal. Phase 3 (Full UI) may revisit this decision when component count grows.

**Tailwind installation note:** Scaffold with `npx sv create app` selecting Tailwind CSS when prompted. This produces a working `tailwind.config.js` and `postcss.config.js`.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps within a bubble header (sequence number to speaker name) |
| sm | 8px | Vertical gap between speaker name and utterance text within a bubble |
| md | 16px | Horizontal padding inside a bubble; gap between adjacent bubbles in the stream |
| lg | 24px | Vertical margin between consecutive bubbles (same speaker turn gap) |
| xl | 32px | Vertical margin between speaker turns (different speaker) |
| 2xl | 48px | Top/bottom padding of the chat column; gap before and after a stage direction |
| 3xl | 64px | Not used in Phase 1 |

Exceptions: none.

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px | 400 | 1.6 | Utterance text — transcript prose requires generous line-height for readability |
| Label | 13px | 600 | 1.0 | Speaker name inside bubble header; sequence number |
| Heading | 20px | 600 | 1.2 | Argument title line (case name, for Phase 1 a static heading above the chat) |
| Stage | 14px | 400 | 1.4 | Stage direction text — slightly smaller than body to signal non-speech content |

**Font stack (system-ui):** `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`

No web font is loaded in Phase 1. Transcript content is the focus — system fonts load instantly and are highly legible.

## Color

The palette is derived from the project owner's spike viewer (`viewer.html`) which reveals established aesthetic preferences. The palette is dark-themed to reduce eye strain during long transcript reading sessions.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0f1117` | Page background; the canvas behind all content |
| Secondary (30%) | `#1e293b` | Bubble background (both bench and advocate — identical); stage direction background; heading bar |
| Border / divider | `#334155` | Bubble border (both sides — identical); stage direction border; heading bar bottom rule |
| Text primary | `#e2e8f0` | Utterance body text |
| Text secondary | `#94a3b8` | Speaker label on bench side; sequence number; descriptive metadata |
| Text advocate | `#93c5fd` | Speaker label on advocate side |
| Accent (10%) | n/a | No accent color used for side differentiation — position alone distinguishes sides |
| Stage accent | `#d97706` | Left border stripe on stage direction component only |
| Destructive | n/a | No destructive actions in Phase 1 |

**Apolitical framing enforcement:**

The bench side and advocate side use identical bubble backgrounds (`#1e293b`), identical border colors (`#334155`), identical left border stripes (`#334155`), and identical text weight. The sole differentiation between sides is:
1. Layout position (bench bubbles are right-aligned; advocate bubbles are left-aligned)
2. Speaker label color: bench labels use `#94a3b8` (slate); advocate labels use `#93c5fd` (blue-200). These are the same visual weight — one is warm-neutral, the other is cool-neutral. Neither is "prominent."

No accent color is applied to either side's bubble border. Position is the primary differentiator; label color is secondary and text-level only.

**Phase 4 accessibility note:** `#94a3b8` on `#1e293b` achieves approximately 3.8:1 contrast — below WCAG AA for body text (4.5:1). Speaker labels are 13px at weight 600 — treated as "large text" (3:1 threshold), which this passes. Full WCAG AA audit is scoped to Phase 4 (A11Y-01). Phase 1 is a PoC.

Stage accent reserved for: left border stripe on stage direction component only (`#d97706`). No other use.

## Component Contracts

### Component 1: `ChatBubble.svelte`

**Purpose:** Renders one spoken utterance. Handles both bench and advocate sides.

**Props:**
```typescript
interface UtteranceProps {
  utterance: {
    sequence: number;
    raw_speaker_label: string;
    text: string;
    side: 'BENCH' | 'ADVOCATE' | 'UNKNOWN';
    is_stage_direction: false;  // StageDirection.svelte handles true
  }
}
```

**Layout rules:**
- `side === 'BENCH'`: bubble is right-aligned. Max-width 72% of chat column. Left border `#334155` 3px.
- `side === 'ADVOCATE'`: bubble is left-aligned. Max-width 72% of chat column. Left border `#334155` 3px.
- `side === 'UNKNOWN'`: treat as advocate (left-aligned). This should not occur for Phase 1 Obergefell data.
- Bubble background: `#1e293b` regardless of side.
- Bubble border (top/right/bottom): `1px solid #334155` regardless of side.
- Border radius: `0 6px 6px 6px` (flat top-left corner, rounded elsewhere). This is a common chat-UI convention that implies the bubble "emerges from" the left-border stripe.

**Internal structure (top to bottom):**
1. Bubble header row: sequence number (xs gap) + speaker label
   - Sequence number: 13px, `#475569`, right-padded with `xs` (4px)
   - Speaker label: 13px, weight 600
     - Bench: `#94a3b8`
     - Advocate: `#93c5fd`
2. Utterance text: 16px, `#e2e8f0`, weight 400, line-height 1.6
   - Top margin: `sm` (8px) from header row

**Svelte 5 Runes pattern:**
```svelte
<script lang="ts">
  let { utterance } = $props();
  const isBench = utterance.side === 'BENCH';
</script>
```

Do NOT use `let:` bindings, `$: reactive` statements, or Svelte 4 stores. Runes only.

### Component 2: `StageDirection.svelte`

**Purpose:** Renders a non-speech annotation (e.g., "(Laughter.)", "(10:02 a.m.)"). Visually distinct from all bubbles — not a chat bubble.

**Props:**
```typescript
interface StageDirectionProps {
  utterance: {
    sequence: number;
    text: string;
    is_stage_direction: true;
  }
}
```

**Layout rules:**
- Full width of the chat column (not left- or right-aligned).
- Background: `#1e293b`.
- Left border: `#d97706` 3px (amber — signals non-speech content).
- Border (top/right/bottom): `1px solid #334155`.
- Border radius: 4px all corners (rectangular, no "chat bubble" implication).
- Vertical margin: `2xl` (48px) above and below to visually separate it from surrounding speech bubbles.

**Internal structure:**
- Text: 14px, weight 400, `#fcd34d` (amber-300), line-height 1.4, italic style.
- No speaker label row. No sequence number displayed.
- The text value is displayed verbatim including its parentheses — e.g., "(Laughter.)".

---

### Component 3: Chat layout in `+page.svelte`

**Purpose:** Top-level layout for the argument chat view. Iterates the utterances array and dispatches to `ChatBubble` or `StageDirection` by `is_stage_direction`.

**Page structure (top to bottom):**

```
+---- Page background (#0f1117) ----------------------------------------+
|                                                                         |
|  Argument heading bar (full-width, #1e293b, border-bottom #334155)     |
|  │ "Obergefell v. Hodges" — 20px, weight 600, #e2e8f0                  |
|  │ "No. 14-556 · Argued April 28, 2015 · Question 1"                   |
|    14px, weight 400, #94a3b8                                            |
|                                                                         |
|  Chat column (max-width: 860px, centered, padding: 0 lg)               |
|  │ top padding: 2xl (48px)                                              |
|  │                                                                      |
|  │  [StageDirection or ChatBubble for each utterance in sequence]      |
|  │  Vertical gap between bubbles: lg (24px)                            |
|  │  Vertical gap between speaker turns: xl (32px)                      |
|  │                                                                      |
|  │ bottom padding: 2xl (48px)                                           |
+-------------------------------------------------------------------------+
```

**Chat column width:** max-width 860px, centered (`margin: 0 auto`). This matches the spike viewer's proven readable width for transcript prose.

**Turn-gap logic:** When consecutive utterances share the same `raw_speaker_label`, vertical gap is `lg` (24px). When the speaker changes, vertical gap is `xl` (32px). This creates a visual rhythm that mirrors natural conversation flow without special component logic — implement via Svelte `{#each}` with index comparison.

**Svelte 5 iteration pattern:**
```svelte
{#each utterances as utterance, i (utterance.sequence)}
  {#if utterance.is_stage_direction}
    <StageDirection {utterance} />
  {:else}
    <ChatBubble {utterance} />
  {/if}
{/each}
```

Use `utterance.sequence` as the keyed identifier for `{#each}`.

## Copywriting Contract

Phase 1 has no interactive elements. The only text requiring decisions is the static heading and any data-unavailable states.

| Element | Copy |
|---------|------|
| Page heading (argument title) | Case name as returned from the API (e.g., "Obergefell v. Hodges") |
| Page subheading | "No. {docket_number} · Argued {argued_date formatted as 'Month D, YYYY'} · Question {question_number}" |
| Loading state | "Loading argument..." — centered, 16px, `#94a3b8`, shown while `+page.server.ts` is in flight (SvelteKit handles SSR; this appears only on client navigation) |
| Error state | "Could not load this argument. The server may be unavailable." — centered, 16px, `#94a3b8`. No retry button in Phase 1 PoC. |
| Empty utterances | "No utterances found for this argument." — centered, 16px, `#94a3b8` |
| Primary CTA | None — Phase 1 is read-only; no CTAs exist |
| Destructive confirmation | None — no destructive actions in Phase 1 |

**Argued date format:** Use JavaScript `Intl.DateTimeFormat('en-US', { month: 'long', day: 'numeric', year: 'numeric' })` to format the date string from the API. Example: "April 28, 2015".

**Speaker label display:** `raw_speaker_label` is displayed verbatim in Phase 1. No transformation or abbreviation. "CHIEF JUSTICE ROBERTS" remains "CHIEF JUSTICE ROBERTS". Phase 2 replaces this with resolved person names.

## Constraints and Anti-Patterns

### Apolitical Framing (hard constraint from CLAUDE.md)

- Bench and advocate bubbles MUST use identical background colors. No exceptions.
- Bench and advocate bubbles MUST use identical font sizes and font weights for utterance text. No exceptions.
- Neither side may have a larger bubble, wider max-width, elevated visual depth (heavier shadow), or any design element that implies hierarchical priority.
- Color differences between sides are limited to: speaker label color only (bench `#94a3b8`, advocate `#93c5fd` — both low-contrast, neither bright/prominent). No border accent differentiates sides.
- Side differentiation MUST be conveyed by layout position alone when viewed without color (per A11Y-03, which must be true at Phase 4 and is being architected correctly from Phase 1).
- Do NOT add any badge, icon, tag, or label that says "Justice" vs. "Counsel" — the raw speaker label already conveys role. Phase 2 adds structured role labels when `person_id` is resolved.

### No Dark-Side / Light-Side Visual Metaphor

Do not use white/light background for one side and dark/gray for the other. This is a common chat UI pattern (iMessage-style) that implies one side is "local" and the other is "remote" — an editorial framing not appropriate for a neutral transcript viewer.

### Stage Directions Are Not Bubbles

Stage directions must NOT use the `ChatBubble` layout. They are typographically distinct: full-width, amber accent, italic text, no speaker header, generous vertical breathing room. Rendering a stage direction as a bubble would incorrectly imply it is a spoken utterance.

### No Truncation

Do not truncate utterance text. "Suspiciously long utterances" (flagged in the spike at 300–450 words) must render in full. SCOTUS transcripts contain genuine long utterances — truncation would misrepresent the record.

### Server-Side Data Loading Only

All FastAPI calls go through `+page.server.ts` server load functions. `FASTAPI_BASE_URL` uses `$env/static/private` — never `$env/static/public` or `PUBLIC_` prefix. No client-side fetch in Phase 1.

### Runes Only in Svelte Components

All Svelte components must use Svelte 5 Runes (`$props`, `$state`, `$derived`, `$effect`). No `$: reactive` blocks, no `writable`/`readable` stores, no `export let` props. `+page.server.ts` is plain TypeScript — it does not use runes.

### No hardcoded argument IDs

The `+page.svelte` renders whatever the `+page.server.ts` load function returns. Phase 1 hard-codes the navigation link to Obergefell (in `+layout.svelte` or a nav element), but the argument page itself must be generic and driven entirely by the route params and API response.
