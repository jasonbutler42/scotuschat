<objective>
Make the three offline pipeline commands (`ingest`, `parse`, `resolve`) job-aware so they can be driven by the admin UI via `subprocess.Popen` (D-01/D-02). Each accepts `--job-id`; when set, it writes its own status/current_step/error_message to `admin_jobs` (FastAPI is a reader only). Resolve's interactive terminal prompt is replaced with discrepancy-writing + `status=paused` (D-02/PIPE-15). Ingest gains `--spaces-key` to read uploaded PDFs from DO Spaces.

Purpose: Honor the offline-pipeline constraint (CLAUDE.md) — the pipeline still writes directly to PostgreSQL and is never an HTTP endpoint. The only behavioral change is that progress is recorded in admin_jobs and resolve pauses for browser review instead of prompting the terminal.
Output: `pipeline/__main__.py` and the three command modules, modified. All changes are backward compatible — running a command without `--job-id` behaves exactly as before.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-07-08 | Tampering | `--spaces-key` path traversal | mitigate | spaces_key is server-generated (`uploads/{job_id}.pdf` in Plan 02), not operator free-text; ingest treats it as an opaque object key, never as a local filesystem path for writing outside data/pdfs |
| T-07-09 | Information Disclosure | DEVNULL hides subprocess errors | accept | stdout/stderr discarded per D-03; failure detail is captured in `admin_jobs.error_message` and surfaced in the UI (Plan 05) |
| T-07-10 | Repudiation | unwritten failure state | mitigate | try/except on each command writes FAILED + error_message so a crashed subprocess never leaves the job stuck in running |
