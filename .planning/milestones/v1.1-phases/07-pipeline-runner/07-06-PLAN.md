--- Fix A: use:enhance on the Continue Resolve form (UAT test 12) ---

Gap reason: The resolve form uses native POST (`<form method="POST" action="?/resolve">`). When the operator clicks the button, `onclick` sets `continueSubmitting = true` but the native form navigation destroys and remounts the component before Svelte can re-render with `disabled={continueSubmitting}`. The button never visually disables. Additionally, native form submission does not call `invalidateAll()`, so the load function does not re-run and the UI stays stuck at 'paused'.

Fix: Import `enhance` from `$app/forms` and apply it to the resolve form with a custom callback:

```typescript
import { enhance } from '$app/forms';
```

Replace the form's onclick handler with a use:enhance directive:

```svelte
<form
  method="POST"
  action="?/resolve"
  use:enhance={() => {
    continueSubmitting = true;
    return async ({ result, update }) => {
      if (result.type === 'failure') {
        continueSubmitting = false;
        // error is displayed via form prop (see Fix B)
        await update();
      } else {
        // success: invalidateAll restarts polling and re-fetches job state
        await update({ reset: false });
      }
    };
  }}
  style="margin-top: 24px;"
>
```

With use:enhance:
- `continueSubmitting = true` fires synchronously before the fetch begins — Svelte renders the disabled button state before the network request.
- On success: `update({ reset: false })` calls invalidateAll() which re-runs the load function, refreshing job state. The polling $effect re-evaluates — if job status is now 'running', polling resumes.
- On failure: `update()` populates the `form` prop with the fail() data; `continueSubmitting` resets to false.

Remove the `onclick` handler from the submit button since use:enhance's callback now handles state management.

The button element becomes:
```svelte
<button
  type="submit"
  disabled={continueSubmitting}
  style="..."

</button>
```
