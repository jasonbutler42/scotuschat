<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator browser → SvelteKit save action | Untrusted form input for six new fields; forwarded to FastAPI as JSON |
| SvelteKit server → FastAPI PATCH | `FASTAPI_BASE_URL` is server-only; admin token attached server-side |
| admin route → person record | Person id from the URL param selects which record is edited |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-08 | Information disclosure | `FASTAPI_BASE_URL` | mitigate | Imported only from `$env/static/private`; never `PUBLIC_`; grep-verified absent in Task 1. |
| T-09-09 | Elevation / IDOR | person id route param | accept | The admin section is gated by the HMAC session cookie in `hooks.server.ts` (Phase 6); any authenticated operator may edit any person by design (single trusted operator role). No per-record ownership model exists or is required. |
| T-09-10 | Tampering (form injection) | six text/select inputs | mitigate | Values flow through Pydantic `PersonUpdate` (string fields) and are written via SQLAlchemy parameterized statements (no string-built SQL). The party value is constrained in the UI; the DB stores plain VARCHAR (accepted tradeoff, D-09, admin-only). Svelte escapes interpolated values on render, mitigating stored-XSS on reload. |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | No package installs in Phase 9 (RESEARCH Package Legitimacy Audit: not applicable). |
</threat_model>
