<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| service → database | merge/delete issue destructive bulk writes; must be atomic and orphan-gated |
| caller → upload_photo | raw file bytes reach the filesystem / Spaces; bytes are validated upstream in the router (Plan 02) but the service must not assume a person exists |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Severity | Mitigation Plan |
|-----------|----------|-----------|-------------|----------|-----------------|
| T-12-SELF | Tampering | merge_people | mitigate | high | `source_id == target_id` raises ValueError before any DB write — prevents self-merge data loss (Pitfall 6) |
| T-12-ATOMIC | Tampering / Data Integrity | merge_people | mitigate | high | all 4 UPDATEs + DELETE inside a single `async with db.begin()`; any exception rolls back the whole transaction — no partial-merge state (D-10) |
| T-12-ORPHAN | Tampering | delete_person_if_orphan | mitigate | high | server-side COUNT across all 4 FK tables before delete; returns False (caller → 409) if any rows exist — authoritative regardless of client state (D-06) |
| T-12-IDOR | Elevation of Privilege | merge_people / delete_person_if_orphan / upload_photo | mitigate | medium | fetch-guard returns None for unknown person_id → router returns 404; no write on missing entity |
| T-12-SYNC | Tampering | all bulk UPDATE/DELETE | mitigate | medium | `.execution_options(synchronize_session=False)` on every bulk statement (project-wide rule) prevents identity-map corruption |
| T-12-SC | Tampering | python imports (Pillow, boto3) | accept | low | all packages pre-existing in requirements.txt and pip-confirmed (12-RESEARCH Package Legitimacy Audit); zero new installs in this phase |
</threat_model>
