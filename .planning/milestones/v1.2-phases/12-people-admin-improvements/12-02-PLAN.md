<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /photo | untrusted multipart file bytes + client-supplied content_type cross here |
| client → merge/delete | untrusted person_id and target_id path/body params cross here |
| StaticFiles → filesystem | /uploads/* maps to data/uploads/* on disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Severity | Mitigation Plan |
|-----------|----------|-----------|-------------|----------|-----------------|
| T-12-UPLOAD | Tampering | upload_person_photo | mitigate | high | two-gate validation: content_type startswith("image/") (first, spoofable) + Pillow Image.open/verify (second, server-side truth); non-images → 422; mirrors existing PDF magic-byte pattern |
| T-12-BOMB | Denial of Service | upload_person_photo | accept | low | Pillow raises DecompressionBombWarning at MAX_IMAGE_PIXELS default; admin-only endpoint behind auth — low exposure; explicit pixel cap deferred (out of scope) |
| T-12-AUTH | Broken Access Control | all 4 endpoints | mitigate | high | router-level `dependencies=[Depends(verify_admin_token)]` covers every new route; no anonymous access; no per-route override |
| T-12-SELF | Tampering | merge_person | mitigate | high | service raises ValueError on self-merge → router returns 422 before any write |
| T-12-ORPHAN | Tampering | delete_person | mitigate | high | service performs authoritative server-side orphan COUNT; router returns 409 if not orphaned — client disabled state is defense-in-depth only (D-06) |
| T-12-IDOR | Elevation of Privilege | all 4 endpoints | mitigate | medium | service None-return → router HTTPException(404) for unknown person_id; no leakage of other records |
| T-12-PATHTRAVERSAL | Tampering | upload_photo filename | mitigate | medium | filename is derived server-side as `{person_id}.{ext}` from a validated int path param and a format-map ext — never from the client-supplied filename, so path traversal in the original name cannot reach disk |
</threat_model>
