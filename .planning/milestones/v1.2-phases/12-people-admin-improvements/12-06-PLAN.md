# Phase 12 Plan 06: Gap Fix — Bio Save Independence + Delete Eligibility

## Source Gaps

- **Gap C (UAT test 4):** Saving bio text requires selecting a photo. If no photo is selected, the photo action calls FastAPI with an empty FormData body and receives a 422. Bio should save independently of photo.
- **Gap D (UAT test 8, server layer):** The `can_delete` condition in the load function includes `counts.aliases === 0`, which prevents the delete button from enabling even when the backend (after Plan 05's fix) will accept the delete. Remove aliases from the eligibility check.

## Gap C Root Cause — Bio save tied to photo action

In `app/src/routes/admin/people/[id]/+page.server.ts` `photo` action (around line 287): `outForm` is always posted to FastAPI even when it contains no `photo_file` and no `photo_url`. FastAPI's `upload_person_photo` requires at least one of these and returns 422 when both are absent. Fix: after the bio PATCH, check if `outForm` has any entries; if empty, skip the FastAPI call and redirect(303) directly.

## Gap D Root Cause — Delete eligibility includes aliases

In the load function (around line 121-128): `can_delete` requires `counts.aliases === 0` and `delete_block_count` includes `counts.aliases`. After Plan 05 deletes aliases server-side before the orphan check, a person with only aliases WILL be deletable by the backend — but the frontend still shows the button as disabled. Fix: remove aliases from both conditions.

## Tasks

### Task 1 — Fix photo action: skip FastAPI call when no photo provided

**File:** `app/src/routes/admin/people/[id]/+page.server.ts`

In the `photo` action, after the bio PATCH block and after constructing `outForm` (currently around lines 287-293), add an early-return check before the FastAPI fetch:

```typescript
// If neither a file nor a URL was provided, bio-only save — skip photo upload
if (!outForm.has('photo_file') && !outForm.has('photo_url')) {
    throw redirect(303, '/admin/people/' + params.id);
}
```

Place this check immediately after the `outForm.append(...)` calls and before `let res: Response;`.

Commit: `fix(12-06): skip photo upload call when only bio text is saved`

### Task 2 — Fix delete eligibility: remove aliases from can_delete

**File:** `app/src/routes/admin/people/[id]/+page.server.ts`

In the load function's `can_delete` derivation block (around lines 121-129):

1. Remove `counts.aliases === 0 &&` from the `can_delete` assignment.
2. Remove `counts.aliases +` from the `delete_block_count` assignment.

Before fix:
```typescript
can_delete =
    counts.utterances === 0 &&
    counts.aliases === 0 &&
    counts.appearances === 0 &&
    counts.argument_participants === 0;
delete_block_count = total;
```

After fix:
```typescript
can_delete =
    counts.utterances === 0 &&
    counts.appearances === 0 &&
    counts.argument_participants === 0;
delete_block_count = counts.utterances + counts.appearances + counts.argument_participants;
```

Also update `total` usage: `total` was `counts.utterances + counts.aliases + counts.appearances + counts.argument_participants`. Since `delete_block_count` is now computed directly, `total` can be removed or left as-is (it's only used for `delete_block_count`). Safest: remove `total` and use the explicit sum above.

Commit: `fix(12-06): remove aliases from delete eligibility check`
