# Phase 12 Plan 07: Gap Fix — Bio Card Position + Merge State

## Source Gaps

- **Gap E (UAT test 1):** The Bio & Photo card renders below the Save Changes button instead of above it. User wants bio and photo in a unified card ABOVE Save Changes.
- **Gap F (UAT test 5):** Selecting a second merge target after the first gives "Could not load counts. Try again." Cause: `onchange` reads the `$state` variable which may be stale in Svelte 5 Runes; also no Cache-Control on the proxy response.
- **Gap G (UAT test 6):** After merge redirects to the target person's page, the merge picker still shows the previous target. SvelteKit soft-navigates between `[id]` pages, reusing the component — `$state` variables never reset.

## Gap E Root Cause — Save Changes button above Bio & Photo card

The save `<form>` (action `?/save`) wraps all sections including Basic Info, Court Tenure, Appointment, and its own submit button. The closing `</form>` tag and Save Changes button are at approximately line 534, then the Bio & Photo `<div>` (a sibling) begins at line 536. HTML disallows nested forms, so Bio & Photo cannot move inside the save form.

Fix: add `id="save-form"` to the save form, remove Save Changes from inside the form, then place a Save Changes `<button type="submit" form="save-form">` AFTER the Bio & Photo card using the `form` attribute to associate it with the save form without nesting.

## Gap F Root Cause — Stale $state read + no cache control

Line 678: `onchange={() => fetchMergePreview(mergeTargetId)}` reads `mergeTargetId` from the `$state` closure. In Svelte 5 Runes, `bind:value` and `onchange` both react to the same DOM change event — the `$state` update may not have flushed by the time `onchange` fires, causing the second call to pass the stale previous value. Additionally, the merge-preview proxy has no `Cache-Control` header, so some browsers serve stale cached responses.

Fix: read the value directly from the DOM event: `onchange={(e) => fetchMergePreview((e.target as HTMLSelectElement).value)}`. Add `Cache-Control: no-store` header to the `json()` response in `merge-preview/+server.ts`.

## Gap G Root Cause — Merge $state not reset on soft navigation

SvelteKit soft-navigates between `/admin/people/[id]` routes with different `[id]` params by reusing the existing component instance and updating `data`. The `$state` variables `mergeTargetId`, `mergePreview`, `mergeError`, `mergeLoading` are initialized once at mount and never reset.

Fix: add a `$effect` that tracks `data.person.id` and resets all merge `$state` variables when it changes.
