<objective>
Fix two job-detail-page defects in `[job_id]/+page.svelte`: PIPE-18 (step badges show stale/incorrect state when `current_step` is null mid-transition) and PIPE-19 (native `<datalist>` typeahead has browser-inconsistent filtering). Both changes are confined to this one file.

Purpose: PIPE-18 — the step status cards must reflect actual job state without flashing all badges to pending during the brief window when the DB write between steps leaves `current_step` null. PIPE-19 — replace the unreliable native combobox with a vanilla Svelte 5 Runes custom combobox (no new dependency) that filters the already-loaded people roster.

Output: a `lastKnownStep` `$state` fallback feeding `stepStatus()`; a reduced 1s running poll interval; and a custom `<input>` + filtered `<ul>` combobox replacing the `<input list>` + `<datalist>` block inside the `{:else if s?.correcting}` branch — all other discrepancy-review logic unchanged.
</objective>
