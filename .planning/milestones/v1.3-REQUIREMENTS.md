## v1.3 Requirements (Complete at Archive)

### Speaker Role Accuracy

- [x] **ROLE-01**: The public speaker popover shows the role a Justice held at the time the argument was heard — determined by tenure date-range lookup against the argument's `argued_date`, not the person's current role field
  - **Outcome:** `_tenure_role_name()` in speakers.py performs date comparison against CourtTenure rows; D-14 fallback to most-recent tenure when argued_date is outside all windows (Phase 15)

- [x] **ROLE-02**: Advocate roles (petitioner's counsel, respondent's counsel, amicus curiae) are stored per argument, not per person — a person can hold different roles across different arguments
  - **Outcome:** argument_participants.side stores SideEnum (PETITIONER/RESPONDENT/AMICUS/UNKNOWN) per participant; ADVOCATE_LABEL_MAP renders correct labels in popover (Phase 15)

- [x] **ROLE-03**: Operator can set or correct an advocate's role for a specific argument in the admin interface without affecting that person's role in other arguments
  - **Outcome:** PATCH /api/admin/arguments/{argument_id}/participants/{participant_id} scoped by both argument_id and participant_id (IDOR guard); advocate role dropdowns on argument edit page and pipeline job detail UI (Phase 15)

### Parser Extraction

- [x] **PARSE-01**: Parse step automatically extracts case name and argued date from the transcript PDF and pre-populates argument metadata fields (docket pre-population from PDF deferred to future phase)
  - **Outcome:** cover_extractor.py extracts argued_date and case_name from cover page via regex; UPDATE blocks in parse.py write values after dry-run gate with is_lead guard (Phase 16)

- [x] **PARSE-02**: Parse step automatically detects which side each advocate is arguing (petitioner/respondent/amicus) from the transcript structure and stores it as the initial per-argument role
  - **Outcome:** TOC-based extraction maps ESQ. name pairs to PETITIONER/RESPONDENT/AMICUS; `_update_participant_sides()` matches by normalized last name after step 7b (Phase 16)

### Pipeline Confidence

- [x] **PIPE-21**: Each pipeline stage card shows detailed stats — Ingest shows the source filename; Parse shows utterance count, speaker count, and any extracted case metadata
  - **Outcome:** original_filename stored in admin_jobs (migration 0009); ParseStats schema with COUNT queries in get_job(); Addition A/B in +page.svelte render source file and stat rows (Phase 17)

- [x] **PIPE-22**: Operator can access the original source PDF for any ingested argument directly from the pipeline admin to verify speaker assignments against the transcript
  - **Outcome:** GET /api/admin/jobs/{job_id}/pdf branches spaces_key first (302 to DO Spaces pre-signed URL) then disk fallback; same-origin SvelteKit proxy at /admin/pipeline/{id}/pdf keeps ADMIN_TOKEN server-side (Phase 17)
