<objective>
Fix the "Start anyway" button in the duplicate warning banner. The button currently calls
document.querySelector('form')?.requestSubmit(), which re-fires the submit event and re-enters
handleSubmit from the top. handleSubmit sets submitting=true (disabling the submit button) and
then calls e.preventDefault(), blocking the POST. Svelte flushes the disabled state reactively;
the browser may abort the submission, leaving submitting=true stuck and triggering a fallback
navigation that appears as a logout. In upload mode, formEl.submit() would also bypass file
input serialization.

The correct fix is to set preflightCleared=true and then call formEl.requestSubmit(). This
re-enters handleSubmit, but handleSubmit's first branch immediately returns when preflightCleared
is true — it sets submitting=true and returns WITHOUT calling e.preventDefault(), so the native
form POST proceeds normally with all form data including file inputs serialized by the browser.

Purpose: UAT test 5 ("Duplicate banner — Start anyway proceeds") is the only open gap blocking
phase 19 closure. This is a targeted single-file fix.

Output: +page.svelte with formEl bound via bind:this and "Start anyway" using
preflightCleared=true then formEl.requestSubmit(), relying on the existing early-return branch
in handleSubmit to set submitting=true and allow the POST to complete.
</objective>

Three edits to app/src/routes/admin/pipeline/+page.svelte:

**Edit 1 — Declare the form element ref variable.**

In the script block, after the line `let preflightCleared = $state(false);` (currently around line 31),
add the following declaration on a new line:

  let formEl: HTMLFormElement;

**Edit 2 — Bind the ref to the form element.**

The `&lt;form&gt;` opening tag (around line 212) currently reads:

  &lt;form
    method="POST"
    enctype="multipart/form-data"
    onsubmit={handleSubmit}
  &gt;

Add `bind:this={formEl}` as a new attribute on the form element, so the tag reads:

  &lt;form
    method="POST"
    enctype="multipart/form-data"
    onsubmit={handleSubmit}
    bind:this={formEl}
  &gt;

**Edit 3 — Replace the "Start anyway" onclick with the preflightCleared + requestSubmit() pattern.**

The "Start anyway" button onclick (around line 364) currently reads:

  onclick={() => { preflightCleared = true; duplicateWarning = null; document.querySelector('form')?.requestSubmit(); }}

Replace the entire onclick attribute value so it reads:

  onclick={() => { preflightCleared = true; duplicateWarning = null; formEl.requestSubmit(); }}

Rationale for each change:
- Setting `preflightCleared = true` before calling `formEl.requestSubmit()` causes handleSubmit
  to hit its first branch (`if (!docketInput.trim() || preflightCleared)`), which sets
  `submitting = true` and returns immediately WITHOUT calling `e.preventDefault()`. The browser
  then completes the native POST with all form data correctly serialized — including
  `&lt;input type="file"&gt;` fields that formEl.submit() would bypass.
- Do NOT set `submitting = true` directly in the onclick. The early-return branch in handleSubmit
  already sets it. Setting it in the onclick as well would be redundant and could cause
  double-execution ordering issues.
- `document.querySelector('form')` is replaced with the bound `formEl` ref, removing the
  fragile DOM query and the optional-chain guard that could silently do nothing if the selector
  fails.
- `formEl.requestSubmit()` (not `formEl.submit()`) is used because requestSubmit fires the
  submit event, which is required for handleSubmit's early-return branch to run. formEl.submit()
  skips the submit event entirely, bypassing handleSubmit and preventing submitting=true from
  being set, and also bypassing multipart file serialization in some browsers.

Do NOT change the three requestSubmit() calls inside handleSubmit (lines approximately 57, 65,
and 70). Those calls are made from within a submit event handler that has already called
e.preventDefault(), so they are safe recursive resubmits with a cleared preflightCleared flag.
