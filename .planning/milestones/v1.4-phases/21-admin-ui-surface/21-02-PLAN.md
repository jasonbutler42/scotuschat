<objective>
Deliver pipeline run delete (ADMIN-02): an operator can delete a bad pipeline run (admin_job) from the job detail page via an inline two-step confirm. The delete touches ONLY the admin_job row — the linked argument and all its downstream data survive (the CRITICAL mental model, D-10/D-11).

Purpose: Pipeline runs are disposable scaffolding whose sole purpose is to produce an Argument; once the argument exists it is the permanent record. Operators must be able to remove bad runs without harming the argument (D-10). Data cleanup of a bad argument is handled separately via ADMIN-01 (D-13).
Output: `delete_job` service function, `DELETE /api/admin/jobs/{job_id}` endpoint, `delete` form action, and a Danger Zone delete section on the job detail page.

NOTE: This plan is Wave 2 because it edits `api/routers/admin.py`, which Plan 21-01 also edits. Sequencing avoids a same-file merge conflict.
</objective>
