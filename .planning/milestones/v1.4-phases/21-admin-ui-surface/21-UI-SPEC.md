## Codebase Overrides

The following values exist in the codebase and are documented here as implementation references only. They are NOT spacing tokens and MUST NOT be used on any new component created in this phase.

| Component | Property | Value | Source | Constraint |

|------|------|--------|-------------|

| Text primary | `#e2e8f0` | Headings, input values, primary button labels |
| Text secondary | `#94a3b8` | Labels, nav links (inactive), sub-text, muted button text |

| Destructive | `#ef4444` | Delete button border + label; confirm delete button border + label; error alert text |

Accent (`#93c5fd`) reserved for:
- Primary (non-destructive) action button borders: "Save changes", "Publish", "Save photo", inline "Save" (advocate role)
- Active tab underline (photo upload/URL tab bar)
- Focus ring (`outline: 2px solid #93c5fd` — defined in `app.css`)

Destructive (`#ef4444`) reserved for:
- Delete button border and label (initial state)
- Confirm delete button border and label (revealed state after first click)
- Inline error message text (`role="alert"`)

Admin sub-nav background: `#1e293b` — provides visual separation from public TopNav (`#0f1117`). Same `border-bottom: 1px solid #334155`.

Source: `app/src/app.css` CSS variables + inline styles confirmed across all admin pages.

## Interaction Contract

### Two-Step Inline Delete Confirm Pattern

Applies to: argument delete (ADMIN-01) and job delete (ADMIN-02).

**State 1 — Initial (deleteSubmitting = false, deleteConfirming = false):**
```
[Delete argument]   ← border: 1px solid #ef4444; color: #ef4444; width: 100%; min-height: 44px;
```

**State 2 — Confirming (deleteConfirming = true, deleteSubmitting = false):**
The delete button is replaced in-place (no layout shift) with a two-button row:
```
[Confirm delete]   [Cancel]
```
- "Confirm delete": `border: 1px solid #ef4444; color: #ef4444; background: transparent; border-radius: 6px; font-size: 16px; font-weight: 600; min-height: 44px; flex: 1;`
- "Cancel": `border: 1px solid #334155; color: #94a3b8; background: transparent; border-radius: 6px; font-size: 16px; font-weight: 400; min-height: 44px; flex: 1;`
- Container: `display: flex; gap: 8px;`

**State 3 — Submitting (deleteSubmitting = true):**
"Confirm delete" button shows "Deleting…" and `opacity: 0.7; cursor: not-allowed;`

**Svelte 5 Runes state:**
```ts
let deleteConfirming = $state(false);
let deleteSubmitting = $state(false);
```

First click on "Delete argument/run": sets `deleteConfirming = true` (no form submit).
"Cancel" click: sets `deleteConfirming = false`.
"Confirm delete" click: submits `?/delete` form action; sets `deleteSubmitting = true` via `use:enhance`.

Source: D-01, D-02 from CONTEXT.md; pattern from `admin/people/[id]/+page.svelte` delete section (lines 769–814) — extended to add the two-step confirm reveal (people editor currently submits on first click).

### Blocked Delete State (argument only — ADMIN-01)

When `data.can_delete === false` (argument is published):
```
[Delete argument]   ← border: 1px solid #334155; color: #94a3b8; cursor: not-allowed; opacity: 0.7; disabled;
```
With tooltip text directly below:
```
<p id="delete-tip" style="font-size: 14px; color: #94a3b8; margin-top: 8px; text-align: center;">
  Published arguments cannot be deleted. Unpublish first.
</p>
```
Button uses `aria-describedby="delete-tip"`.

Source: D-04, D-05 from CONTEXT.md; mirrors people editor `{:else}` branch (people/[id]/+page.svelte lines 793–805).

### Post-Delete Redirect

- Argument delete → `throw redirect(303, '/admin/arguments')`
- Job delete → `throw redirect(303, '/admin/pipeline')`

Source: D-06, D-12 from CONTEXT.md.

## Layout Contract

### Admin Layout (post-Phase 21)

```
┌─────────────────────────────────────────────────────┐
│ TopNav (variant="public") — bg #0f1117              │
│ SCOTUS CHAT   Cases   [right] Admin                 │
├─────────────────────────────────────────────────────┤
│ AdminSubNav — bg #1e293b                            │
│ Pipeline Runner   Arguments   People Editor [Logout]│
├─────────────────────────────────────────────────────┤
│ {children} — page content                          │
└─────────────────────────────────────────────────────┘
```

The public TopNav row (`bg: #0f1117`) sits above the admin sub-nav row (`bg: #1e293b`). The darker-to-lighter gradient creates implicit visual hierarchy: public context → admin context → page content.

Login page (`/admin/login`): shows neither TopNav nor AdminSubNav — existing gate in `admin/+layout.svelte` unchanged.

### Delete Section Position

Delete section is the last card on entity edit pages, below all save/publish actions.

Card structure:
```html
<div style="background-color: #1e293b; border: 1px solid #334155; border-radius: 8px; padding: 24px; margin-bottom: 24px;">
  <h2 style="font-size: 20px; font-weight: 600; color: #e2e8f0; margin: 0 0 16px 0; line-height: 1.2;">
    Danger Zone
  </h2>
  <!-- delete button / blocked state / error -->
</div>
```
