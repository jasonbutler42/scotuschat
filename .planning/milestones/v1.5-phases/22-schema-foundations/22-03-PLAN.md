## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PDF file → parser | Untrusted/variable transcript text is parsed for the TOC subtitle line |
| Parser output → DB write | Extracted title strings are written to argument_participants.title |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-07 | Denial of Service | _parse_toc_titles / extract_toc_data on malformed PDFs | medium | mitigate | extract_toc_data wraps the read in try/except and returns empty maps on any failure (D-11); a missing subtitle yields NULL title, never an exception, so a bad PDF cannot halt the parse run |
| T-22-08 | Tampering | title string length | low | accept | title column is VARCHAR(500); a subtitle longer than 500 chars would be rejected by the DB. Real TOC subtitle lines are short (e.g. "Solicitor General"); over-length is not a realistic case and the parse step already tolerates write failures per its existing error handling |
| T-22-09 | Information Disclosure | title reflects only TOC public text | low | accept | The title is verbatim public transcript text; no derived insight or PII beyond what the immutable PDF already contains — consistent with the project's apolitical, identical-treatment constraint |
| T-22-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new packages; reuses existing pdfplumber and sqlalchemy imports. No legitimacy checkpoint required. |
</threat_model>
