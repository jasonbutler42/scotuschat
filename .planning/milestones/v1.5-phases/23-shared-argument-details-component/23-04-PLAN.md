  <name>Task 1 (Gap 3 — backend): Fix source_docket clear in update_argument_metadata service</name>
  <files>api/services/admin_arguments.py</files>
  <action>
    The current guard at approximately line 546 reads:

        if body.source_docket is not None:
            values_to_set["source_docket"] = body.source_docket

    This conflates "field not sent" (None) with "operator cleared all pills" (also None when
    the action sends null). Fix by treating an empty string as an intentional clear-to-NULL.
    The action (Task 2) will send an empty string when all pills are removed.

    Replace the guard with:

        if body.source_docket is not None:
            values_to_set["source_docket"] = body.source_docket or None

    The expression `body.source_docket or None` converts the empty string sentinel '' to
    Python None, which SQLAlchemy writes as DB NULL. Non-empty strings pass through
    unchanged. Truly-omitted fields (Python None from Pydantic default) still skip the key
    entirely via the `is not None` check — no regression to existing WR-01 guard logic.

    Do not change any other logic in this function. Do not change the MetadataUpdate schema
    (source_docket remains Optional[str] = None — this is intentional; '' is the sentinel,
    not a schema change).
  </action>
  <verify>
    <automated>grep -n "source_docket or None" api/services/admin_arguments.py</automated>
  </verify>
  <done>Line matching `values_to_set["source_docket"] = body.source_docket or None` exists
