<objective>
Add a max-count guard to the docket pill UI so a second pill can never be added client-side,
eliminating the server-side CR-02 "Only one docket number is supported" error.

Purpose: The DB schema only supports one source_docket value. The server guard CR-02 already
rejects multi-pill submits, but the frontend was allowing the user to add a second pill first.
This plan closes the UX gap so the invalid state is unreachable.

Output: ArgumentDetailsCard.svelte updated with four coordinated changes — early-return guard in
addPill(), disabled input when a pill exists, Enter-key guard, and inline hint text.
</objective>

  <name>Task 1: Add max-count guard to docket pill input</name>
  <files>app/src/lib/components/ArgumentDetailsCard.svelte</files>
  <action>
    Make four coordinated edits to ArgumentDetailsCard.svelte. All changes are confined to the
    docket input section (lines 41–193 of the current file).

    1. In addPill() (currently lines 41–48): add an early-return guard as the FIRST check inside
       the function body, before the existing duplicate/empty check. The guard is:
       if (pills.length >= 1) return;
       The full function body after the edit should be:
       - if (pills.length >= 1) return;
       - const v = docketInput.trim();
       - if (v and not pills.includes(v)) pills = [...pills, v];
       - docketInput = '';

    2. On the docket text input element (id="docket-input"), update the disabled attribute from
       disabled={readonly}
       to
       disabled={readonly || pills.length >= 1}
       This visually locks the field when a pill already exists.

    3. In the onkeydown handler on that same input element, wrap the addPill() call so it only
       fires when the input is not disabled. Change the handler body from:
         if (e.key === 'Enter') { e.preventDefault(); addPill(); }
       to:
         if (e.key === 'Enter') { e.preventDefault(); if (!readonly && pills.length < 1) addPill(); }
       This ensures pressing Enter on a focused-but-disabled input is a no-op even if focus
       somehow reaches it.

    4. Immediately after the closing </input> tag for docket-input (and before the docket hint
       row div that starts with margin-top: 4px), add a conditional inline hint paragraph:
         {#if pills.length >= 1 && !readonly}
           <p style="font-size: 13px; font-weight: 400; color: #64748b; margin: 4px 0 0 0; font-style: italic;">
             Remove the existing entry to add a different one.
           </p>
         {/if}
       The hint appears only when: a pill exists AND the card is not in readonly mode.
       Do not show the hint in readonly mode because the Remove button is also hidden there.

    No other sections of the file should be touched. The pills $state, removePill(), the hidden
    inputs, the pill list rendering, and all other fields remain unchanged.
