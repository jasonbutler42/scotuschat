| Dominant (60%) | `#0f1117` | Page background (`--color-bg`) |
| Secondary (30%) | `#1e293b` | Card backgrounds, input active surface, dropdown list background (`--color-surface`) |
| Border / tertiary | `#334155` | Card borders, input borders, divider lines, non-accented button borders (`--color-border`) |
| Text primary | `#e2e8f0` | Primary text, input values, headings (`--color-text-primary`) |
| Text muted | `#94a3b8` | Labels, hint text, secondary metadata, placeholder-equivalent (`--color-text-secondary`) |
| Accent (10%) | `#93c5fd` | Reserved exclusively for: primary CTA button borders, focus ring outline, "Save Argument Details" button border, editable docket pill border, combobox active-search input border |
| Input background | `#0f1117` | Text inputs, date inputs, select dropdowns — matches dominant bg to create inset appearance |
| Success | `#4ade80` | Save-success inline confirmation text only |
| Destructive | `#ef4444` | Error messages (`role="alert"`), destructive button border/text — no use in this phase's new component |
| Warning | `#fbbf24` | Not used in ArgumentDetailsCard |

Accent (`#93c5fd`) reserved for: primary "Save Argument Details" button border, editable docket input border when focused, focus-visible outline. Never used for informational text, decorative borders, or secondary buttons.

Hint "Extracted: N/A" state: render in `#94a3b8` (muted) with `font-style: italic` — visually distinct from a real extracted value which uses `#94a3b8` at normal weight. This distinction signals extraction failure at a glance without a separate color.

> Source: `app/src/app.css` CSS custom properties + confirmed across both consumer pages. No new color tokens introduced in this phase.

## Component Inventory

### ArgumentDetailsCard

**File:** `app/src/lib/components/ArgumentDetailsCard.svelte`

**Props:**
```ts
interface ArgumentDetailsCardProps {
  savedValues: {
    dockets: string[];           // ordered array, may be empty
    question_number: string;     // free text, may be empty string
    argued_date: string | null;  // ISO date YYYY-MM-DD or null
  };
  hints: {
    dockets: string[];           // extracted from cover_metadata, may be empty
    question_number: string | null;
    argued_date: string | null;  // ISO date YYYY-MM-DD or null
    case_name: string | null;    // shown in parse stat card, passed through for PJOB-12 cross-check
  };
  action: string;                // SvelteKit form action string, e.g. "?/saveJobMetadata"
  readonly?: boolean;            // default false; when true all inputs are disabled, no save button shown
}
```

> Source: D-03 (CONTEXT.md) — props are separate `savedValues` and `hints` objects, not merged. Shape derived from `cover_metadata` JSONB structure confirmed in `api/models/models.py` (`Argument.cover_metadata`).

**Internal state (Svelte 5 `$state`):**
- `pills: string[]` — current docket pill list; initialized from `savedValues.dockets`
- `docketInput: string` — controlled value of the docket text input; cleared on Enter
- `saving: boolean` — tracks form submit in progress

**Form mechanics:**
- `<form method="POST" {action} use:enhance>` — D-01 (CONTEXT.md)
- Each pill serializes as `<input type="hidden" name="docket[]" value={pill}>` — D-05 (CONTEXT.md)
- On failed save: restore pills from `form.dockets` prop, not from `savedValues` — D-06 (CONTEXT.md)

### Docket Pill/Tag Interaction

**Add a pill:**
- Operator types a docket number into the text input and presses **Enter**
- Input clears; the pill appears immediately in the pill list above the input
- No visible "Add" button — keyboard-first, D-04 (CONTEXT.md)
- Duplicate pills: silently reject (do not add if the exact value already exists)
- Empty string: silently reject on Enter

**Remove a pill:**
- Each editable pill renders an ×/remove button inline
- Click or keyboard (Space/Enter on the × button) removes the pill from `pills` state
- The hidden input for that docket is removed from the DOM immediately

**Editable pill appearance:**
```
┌─────────────────────────────┐
│  22-123  ×                  │  ← background #1e293b, border 1px solid #334155, border-radius 4px
└─────────────────────────────┘
```
- Pill text: 14px, weight 400, color `#e2e8f0`
- × button: 14px, color `#94a3b8`; on hover color `#ef4444`; min touch size 28×28px
- Pill container: `display: flex; flex-wrap: wrap; gap: 8px; margin-bottom: 8px`

**Read-only hint pills (extracted dockets):**
- Same pill shape but: no × button, smaller padding (`4px 8px`), color `#94a3b8`, `font-size: 12px`
- Background `#0f1117` (recessed) rather than `#1e293b`
- Visually communicates "this is data, not an input" — D-09 (CONTEXT.md specifics)
- Container: `display: flex; flex-wrap: wrap; gap: 4px;`

---

### Hint Row Layout

Each editable field (docket input, question number, argued date) is followed by a hint row immediately below it:

```
[Label]
[Input field — full width]
[Hint row: "Extracted: [value]" in muted text]    ← always present
```

- Hint prefix: `"Extracted: "` — literal prefix, D-08 (CONTEXT.md)
- Hint value when extracted: 14px, weight 400, color `#94a3b8`, `margin-top: 4px`
- Hint value when null/empty: render `"Extracted: N/A"` in 14px, weight 400, color `#94a3b8`, `font-style: italic`
- The hint row is **always rendered** — never conditionally hidden — PJOB-04, D-07 (CONTEXT.md)
- Docket hint: render as read-only pills (see above) rather than comma-joined text — D-09

### Parse Stat Card Updates

The existing parse step card on `pipeline/[job_id]/+page.svelte` currently shows `utterance_count` and `speaker_count`. Phase 23 expands it to show all fields in PJOB-10.

**Updated stat rows (shown when parse step `status === 'completed'`):**

| Field | Display label | "N/A" condition |
|-------|--------------|-----------------|
| `utterance_count` | Utterances | never (always a number) |
| `bench_count` | Bench speakers | when null |
| `advocate_count` | Advocate speakers | when null |
| `total_speaker_count` | Total speakers | when null |
| `cover_metadata.case_name` | Case name | when null or empty |
| `cover_metadata.argued_date` | Argued date | when null |
| `cover_metadata.primary_docket` (+ consolidated) | Docket(s) | when empty array |
| `cover_metadata.question_number` | Question number | when null or empty |

- Each row uses the established label/value two-line layout: 14px muted label, 16px primary value
- "N/A" string replaces blank/null — `font-style: italic; color: #94a3b8` — consistent with hint N/A treatment
- Multiple dockets: each docket rendered as a separate read-only pill (same style as hint pills)
- PJOB-12 compliance: case_name, argued_date, dockets, question_number MUST read from `cover_metadata` JSONB — the same source as the ArgumentDetailsCard hints

## Interaction States

### Docket input

| State | Visual |
|-------|--------|
| Default | border `#334155`, bg `#0f1117` |
| Focus | border `#93c5fd`, outline `2px solid #93c5fd` (via `*:focus-visible` in app.css) |
| Filled (pill added) | input clears; pill appears in list above |
| Duplicate on Enter | input does not clear; no pill added; no error message (silent reject) |

### Save button

| State | Visual |
|-------|--------|
| Default | `border: 1px solid #93c5fd; color: #e2e8f0; bg: #1e293b; min-height: 44px` |
| Submitting | `opacity: 0.7; cursor: not-allowed`; label "Saving…" |
| readonly prop true | button not rendered |

### Readonly mode (for Phase 26 argument edit — post-publish)

When `readonly={true}`:
- All inputs have `disabled` attribute
- Pill × buttons are not rendered
- Save button is not rendered
- Hint rows still render (operator retains historic view of extracted values)

## Accessibility Contract

- All inputs have an associated `<label for="...">` — no aria-label substitution
- Pill remove button: `aria-label="Remove docket {value}"` — screen reader identifies which pill is being removed
- Save success/error: rendered in a `role="alert"` paragraph so screen readers announce the outcome
- Parse stat card updates: no change to existing `aria-live="polite"` on the step cards container
- Hint rows: not interactive; no role needed; muted color provides visual distinction (not color-only — italic style provides second differentiator for N/A state)
- Touch targets: CTA buttons 44px min-height; pill × buttons 28px min (not primary actions); date/text inputs 44px min-height via `padding: 8px 12px` + `font-size: 16px`
