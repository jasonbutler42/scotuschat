<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → SvelteKit `load()` | `?status=` query string is attacker-controllable via URL |
| SvelteKit `+page.server.ts` → FastAPI | server-side fetch forwards `status` as a query param (server-only `FASTAPI_BASE_URL`, X-Admin-Token) |
| FastAPI route → service/SQL | `status` string reaches `list_arguments()` and is used to build a `WHERE` clause |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-30.1-01 | Tampering | `status` query param → `list_arguments()` SQL `WHERE` | medium | mitigate | Validate `status` against the `ArgumentStatusEnum` allow-list (`{draft,published,unpublished}` `.value`) BEFORE use; SQLAlchemy binds the enum value as a parameter (no string interpolation). Unrecognized values fall through to the unfiltered base list — never raise, never 422 (Task 1, D-05) |
| T-30.1-02 | Information Disclosure | list route exposure | low | accept | `GET /arguments` is already behind the router-level `verify_admin_token` (X-Admin-Token) dependency; unchanged by this phase. Route-resolution test (Task 3) confirms auth still fires before query handling (401-not-422) |
| T-30.1-03 | Tampering | filtering via unpublished/pipeline status | low | mitigate | The base ALIST-02 filter (`status.in_([DRAFT,PUBLISHED,UNPUBLISHED])`) is retained and applied first; `pipeline` is never a selectable filter value, so pipeline-only rows can never be surfaced on the arguments list regardless of the `status` param |
</threat_model>
