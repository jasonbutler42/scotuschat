<objective>
Close the UAT test 3 blocker: blanking the Question number field in the ArgumentDetailsCard and saving throws an unhandled 500 instead of persisting NULL. Root cause (already diagnosed in 30.1-UAT.md, not re-litigated here): `arguments.question_number` is a NOT NULL column with `server_default '1'` (migration 0001, models.py:186) that was never migrated to nullable — unlike `argued_date`, which migration 0011 made nullable. The service layer (commit 62e5e0e0) already correctly writes NULL on explicit clear; the DB rejects it with an asyncpg IntegrityError, and the router only catches ValueError, so it surfaces as a 500.

Product decision (confirmed with user 2026-07-11, not re-opened): blank question_number means NULL / "unknown", full parity with argued_date. Allow-NULL, not client-side-block.

Purpose: Achieve argued_date/question_number symmetry end-to-end so operators can clear the question number, and harden the metadata endpoint against any future NOT NULL mismatch.
Output: New Alembic migration 0019, a nullable model column, an IntegrityError-tolerant router handler, two schema consumers that accept None, and a regression test.
</objective>
