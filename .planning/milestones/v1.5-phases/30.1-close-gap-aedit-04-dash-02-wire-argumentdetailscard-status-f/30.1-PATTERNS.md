    q = (
        select(
            Argument.id, Argument.argued_date, Argument.resolved_at,
            Argument.published_at, Argument.status, Case.case_name, Case.docket_number,
        )
        .join(CaseArgument, CaseArgument.argument_id == Argument.id)
        .join(Case, CaseArgument.case_id == Case.id)
        .where(CaseArgument.is_lead == True)  # noqa: E712
        .where(

                [ArgumentStatusEnum.DRAFT, ArgumentStatusEnum.PUBLISHED, ArgumentStatusEnum.UNPUBLISHED]
            )
        )

    )

    rows = result.all()
    return [{"id": row.id, ...} for row in rows]

## Shared Patterns

### Optional query-param filter on an existing list endpoint (backend)
**Source:** `api/services/admin_people.py::list_people()` (lines 168-221) + `api/routers/admin.py::GET /people` (lines 595-626)
**Apply to:** `list_arguments()` service + `GET /arguments` route
Both already demonstrate: optional typed param defaulting to `None`/`False`, conditional `.where()` clause only when the value is meaningful, never raising on unrecognized values, passed straight through router → service with keyword args.

### `url.searchParams` → forwarded FastAPI query string (frontend `load()`)
**Source:** `app/src/routes/admin/people/+page.server.ts` (lines 14-48)
**Apply to:** `app/src/routes/admin/arguments/+page.server.ts` `load()`
Read from `url.searchParams`, build a `URLSearchParams` for the outbound fetch, only append params when present, return the raw filter state alongside the fetched data for the component to render the active-filter indicator.

### Segmented button + "Filtering by / Clear filter" active-indicator idiom (frontend component)
**Source:** `app/src/routes/admin/people/+page.svelte` (lines 56-93 segmented buttons; lines 158-179 filter indicator)
**Apply to:** `app/src/routes/admin/arguments/+page.svelte`
`goto()`-based navigation (no full reload), `aria-pressed` on each button, `·`-separated indicator line with an inline text-button "Clear filter" styled in accent `#93c5fd`.

### `ArgumentDetailsCard` consumption contract (component props + save/no-redirect convention)
**Source:** `app/src/lib/components/ArgumentDetailsCard.svelte` (full file) + `app/src/routes/admin/pipeline/[job_id]/+page.server.ts` (`saveJobMetadata`, lines 504-584; `load()`, lines 216-262)
**Apply to:** both the new `load()` savedValues/hints construction and the new `saveArgumentDetails` action in `app/src/routes/admin/arguments/[id]/+page.server.ts`
Critical constraint: the action must return `{ saved: true }` (or `fail(...)` with a `dockets` echo on error) — never `redirect(303, ...)` — because the component's own `use:enhance` handler (lines 66-78 of the component) expects `update({ reset: false })` to run and its own success/error message rendering (lines 212-234) to fire.

### IDOR guard — argument_id sourced only from trusted route param
**Source:** every existing action on `app/src/routes/admin/arguments/[id]/+page.server.ts` (e.g. `updateParticipantSide`, lines 88-116; `save`, `publish`, `unpublish`, `delete`)
**Apply to:** the new `saveArgumentDetails` action
Never read an argument id from form data — always use `params.id`.
