# Phase 30.1 — UI Design Contract

> Visual and interaction contract for `/admin/arguments/[id]` (page restructure — AEDIT-04) and `/admin/arguments/` (status filter — DASH-02). Generated by gsd-ui-researcher from `30.1-CONTEXT.md` (D-01–D-06 + Claude's Discretion) and `30.1-RESEARCH.md`. This is a gap-closure phase, not new-feature design — almost every visual decision below formalizes an existing precedent (Phase 23's `ArgumentDetailsCard`, Phase 26's arguments-page card chrome, Phase 27's People-page filter idiom) rather than inventing new visual language.

**Design system note:** No shadcn, no Tailwind, no `components.json` (confirmed absent again this session) — project is SvelteKit/Svelte 5, not React/Next/Vite, so the shadcn initialization gate does not apply. All values below are read directly from the existing codebase (`ArgumentDetailsCard.svelte`, `arguments/[id]/+page.svelte`, `arguments/+page.svelte`, `people/+page.svelte`) during this research pass, not invented.

## Component & Layout Contract (phase-specific, supplements template)

### Edit page (`/admin/arguments/[id]`) — restructured card order top to bottom

1. **Case** (NEW small card, D-03) — case title + Case docket number + read-only consolidated dockets. Same card chrome as every other card (`background-color: #1e293b; border: 1px solid #334155; border-radius: 8px; padding: 24px;`), `margin-bottom: 24px` (raised from the current 16px so it visually matches `ArgumentDetailsCard`'s own built-in 24px spacing immediately below it — the two top cards should read as one consistent rhythm, not a jump from tight-16 to wide-24). Keeps its existing `?/save` action untouched except the `argued_date` field/input is deleted entirely from this form (Pitfall 2 — not just hidden).
2. **Argument Details** (`<ArgumentDetailsCard>`, second consumer — AEDIT-04) — rendered immediately below the Case card, completely unmodified component (owns its own card chrome, 24px bottom margin already baked in — do not wrap it in an additional card div). Props: `savedValues` derived from `source_dockets`/`source_docket` fallback (Pattern 2/Pitfall 3 in RESEARCH.md), `question_number`, `argued_date`; `hints` derived from `cover_metadata` with `question_number` frozen to `null` (existing project-wide convention, 23-04); `action="?/saveArgumentDetails"`; `readonly={false}` (this page is never read-only — unlike the pipeline page's `already_created` state, an argument's details remain editable regardless of publish status).
3. **Status** (existing — unchanged position and content)
4. **Status history** (existing — unchanged position and content)
5. **Speakers** (existing — unchanged position and content)
6. **Danger Zone** (existing — unchanged position, content, and copy)

Rationale for ordering Case above Argument Details (resolves CONTEXT.md's open discretion item): the Case card is the page's identity anchor — "what argument is this" (title + real docket) — and belongs at the top, exactly where the single combined card used to sit. Argument Details (dockets pills/question number/argued date/hints) is supporting metadata that follows, mirroring the People page's established "Identity card first, supporting-details card(s) after" convention (27-UI-SPEC).

### List page (`/admin/arguments/`) — filter control (DASH-02, D-05)

- **Control shape:** a 4-option segmented button row — "All" | "Draft" | "Published" | "Unpublished" — visually identical in structure to the People page's Bench/Advocate segmented toggle (`min-height: 44px; padding: 8px 16px; font-size: 16px; font-weight: 600`; first button `border-radius: 6px 0 0 6px`, last button `border-radius: 0 6px 6px 0`, middle buttons no radius and `border-left: none` to form one continuous joined row; `aria-pressed={isActive}` on each button, matching the existing ARIA idiom).
- **Selected-state fill:** each button's selected background/border uses its own status color instead of the generic accent blue — "All" selected → `background-color: #93c5fd; border-color: #93c5fd; color: #0f1117"`; "Draft" selected → `background-color: #a78bfa; border-color: #a78bfa; color: #0f1117`; "Published" selected → `background-color: #4ade80; border-color: #4ade80; color: #0f1117`; "Unpublished" selected → `background-color: #fb923c; border-color: #fb923c; color: #0f1117`. Unselected buttons: `background-color: #1e293b; border-color: #334155; color: #e2e8f0` (identical to the People page's unselected-segment style).
- **Placement:** in the page header row, to the right of the `<h1>Arguments</h1>` heading, same visual slot the People page uses for its Bench/Advocate toggle (`display: flex; align-items: center; gap: 16px`).
- **Navigation:** clicking a button calls `goto('/admin/arguments?status=' + value)` for Draft/Published/Unpublished, or `goto('/admin/arguments')` (no query string) for "All" — mirroring the People page's `switchTab()` pattern exactly (`$app/navigation`'s `goto`, not a full page reload).
- **Active-filter indicator + clear control:** rendered directly above the table (or above the empty-state card, when the filtered result is empty), using the exact `Showing: {Status} arguments · Clear filter` construction from the Copywriting Contract above — only rendered when the active filter is Draft/Published/Unpublished (never shown when "All" is selected, since the segmented row itself already makes "All" visually obvious with no ambiguity to clarify). This is the same dual-affordance pattern Phase 27 locked for its missing-field pills (segmented/pill control AND a separate persistent clear-filter text line) — both affordances are present here too, satisfying D-05's "visible filter control with an active-filter indicator" wording precisely.
- **Table columns and row markup:** entirely unchanged (Status | Case Title | Docket | Argued | Created | Publish) — this phase only adds the filter control and the backend `status` query param wiring; it does not alter table structure, badge styling, or row actions.
