<objective>
Second layer of the G-38-6 fix: harden `pipeline/commands/ingest.py`'s own filename and
slug construction so a docket value can never produce a path component containing `/`,
`\`, `..`, or resolve as absolute — independently of whether the API boundary (plan 38-07)
validated it.

This mirrors the codebase's existing two-layer SSRF pattern (`_validate_pdf_url` at the
FastAPI route plus `_validate_url` inside this same ingest module) and covers the direct
CLI invocation path, which does not pass through FastAPI at all.

Purpose: `pdf_filename = f"{primary_docket}-q{args.question}.pdf"` joined onto
`Path("data/pdfs")` is the single confirmed arbitrary-file-write site — `pathlib`'s `/`
operator honors `..` segments at write time and silently discards the base directory when
the right operand is absolute.
Output: a docket path-component guard, a resolved-path containment assertion, and no-DB
unit tests proving both.
</objective>

  <files>pipeline/commands/ingest.py</files>
  <action>
    Import `DocketValueError` and `normalize_docket_value` from `api.domain.docket_values`.
    Importing from `api.domain` inside a pipeline command is already established here —
    `import_convokit.py`, `import_justices_csv.py`, and `seed_aliases.py` all import
    `api.domain.person_names`, and that module is deliberately DB-free and app-free.

    Add a module-level helper, named and documented in the same spirit as the existing
    `_validate_url`, that takes a docket string plus a short context label and raises
    `ValueError` when the value is not a safe single path component. Implement it by
    delegating to `normalize_docket_value` and converting `DocketValueError` into
    `ValueError` with the domain module's message, then additionally asserting the
    structural invariant directly rather than trusting the pattern alone: the value must
    not contain `/` or `\`, must not equal `..` or contain a `..` segment, and
    `Path(value)` must not be absolute and must have exactly one path part. The
    delegation gives one shared rule; the structural assertions are the part that stays
    meaningful even if the shared pattern is ever loosened. Document that contrast in the
    helper docstring, and reference G-38-6 plus the confirmed `pathlib` behaviors it
    defends against (`..` honored at write time; an absolute right operand discards the
    base directory entirely).

    Call the helper in Step 3, immediately before `pdf_filename` is built from
    `primary_docket`, and only on the branch where `primary_docket is not None`. The
    server-generated `job-{id}` and `unknown` fallback filenames are unaffected because
    they are not operator-controlled — but still route the final `pdf_filename` through
    the containment assertion below so all branches share one invariant.

    After `pdf_path = pdf_dir / pdf_filename`, add the containment assertion: resolve both
    `pdf_dir` and `pdf_path` and raise `ValueError` when the resolved `pdf_path`'s parent
    is not the resolved `pdf_dir`. Place it before `pdf_path.exists()` so no branch
    (existing-file skip, local-file copy, Spaces download, or HTTP download) can write or
    read outside `data/pdfs`. Keep `pdf_dir.mkdir(parents=True, exist_ok=True)` where it
    is so the resolve target exists.

    In Step 5, call the same helper on each docket in `all_dockets` before it is used to
    build `case_slug` (both the primary and the consolidated `f"{base_slug}-{docket}"`
    branch). `Case.slug` becomes a public URL segment and `_derive_slug` sanitizes only
    `case_name`, never the appended docket — a separator in a docket value would create a
    phantom path segment there. Skip the check for the synthetic `job-{id}` docket the
    CR-03 block generates (it is server-generated and already conforms), or simply let it
    pass through the same helper since it does conform; do not add a special case that
    weakens the guard.

    Raise `ValueError` (not a bespoke exception type) so `run_ingest`'s existing
    `except Exception` wrapper writes `AdminJobStatus.FAILED` with `error_message=str(exc)`
    — this is what replaces the operator-visible `[Errno 22] Invalid argument` with a clear
    explanation. Do not catch and swallow it, and do not sanitize or rewrite the docket
    value into a different filename: silently renaming would break the documented PDF
    immutability/idempotency contract and would desynchronize the on-disk filename from the
    docket persisted on `Argument.source_docket`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Subprocess argv → ingest filename construction | Docket values arrive as argparse strings and become filesystem path components |
| Direct CLI invocation → ingest | `python -m pipeline ingest` bypasses FastAPI entirely, so the route-level guard does not apply |
| Docket value → `Case.slug` | Slug text becomes a public URL segment |
