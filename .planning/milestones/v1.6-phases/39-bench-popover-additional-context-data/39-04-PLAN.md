<objective>
Rework the public speaker endpoint's contract so the popover has real data to render.

Three already-decided things change together:

1. **The T-14-02 reversal (D-11/D-12).** `appointing_president_party` was deliberately kept
   out of this public schema in Phase 14 on apolitical-framing grounds. Phase 39 reverses
   that: the *appointing president's* party is factual historical data about a president —
   not about the Justice, who has no party — and it renders in plain neutral text,
   identically for every entry. Both stale docstrings must be rewritten in the same commit
   as the code that now includes the field.

2. **The `appointing_president` promote (D-13).** Recorded explicitly here as a **promote,
   not an add-alongside**: the per-`TenureEntry` `appointed_by` field becomes the sole
   representation and the top-level field — hardcoded to `null` since Phase 22 with a comment
   promising a later phase would wire it — is **fully retired**, not kept as a deprecated
   alias. D-13 already made this call; this plan records and implements it. A repo-wide grep
   at planning time confirmed the only consumers of the bare top-level field are
   `SpeakerPopover.svelte` (lines 30, 84-88) and the argument page's `SpeakerDetail`
   interface (`+page.svelte` line 24) — both rewritten by Plan 39-05.

3. **The new person-level fields.** `birthdate`, `death_date` and `bio_text` join the payload.
   `bio_text` needs no new query: Step 2's `select(Person, Role.name...)` already loads the
   whole `Person` row, so the value is available directly on the object in the Step 5 loop.

Purpose: this is where the phase's one genuine policy change lands — deliberately, with its
rationale written into the living decision log rather than left implicit in a diff.
Output: a widened, closed, uniformly-shaped public contract plus the decision record.
</objective>

<assumption_delta_record>
**D-13, singular to plural: PROMOTE (not add-alongside).**

`appointing_president` existed as a single top-level `Optional[str]` on `SpeakerPopoverEntry`,
hardcoded to `None` in the service since Phase 22. Phase 39 moves this concept to a
per-`TenureEntry` `appointed_by` field because a Justice can hold more than one tenure with a
different appointing president each (Rehnquist: Nixon, then Reagan), which a single
person-level value cannot represent.

The transition is a clean **promote**: the per-tenure field becomes the primary and only
representation, and the top-level field is **fully retired** — removed from the schema,
removed from the service's assembly dict, and removed from both frontend interfaces (Plan
39-05). It is not kept as a deprecated co-existing alias.

39-CONTEXT.md D-13 already made this call. This section records it, it does not re-decide it.
</assumption_delta_record>
