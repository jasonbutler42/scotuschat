**Interfaces.** Add `appointed_by: string | null`, `appointing_president_party: string | null`

**Date helper.** Add `function formatShort(iso: string): string` using
`Intl.DateTimeFormat('en-US', { month: 'short', day: 'numeric', year: 'numeric', timeZone: 'UTC' })`.
The `timeZone: 'UTC'` option is mandatory and is a correction to the shape sketched in
39-PATTERNS.md: `new Date('1924-10-01')` parses as UTC midnight, so formatting it in a
negative-offset local timezone without pinning the zone renders the *previous* calendar day.
Every date in this payload is a date-only DB value with no time component, so UTC is the
correct interpretation.

**Layout.** Convert the card from "avatar beside one narrow text column" into a header row
plus full-width stacked sections:
- Header row (horizontal flex, `gap: 16px`): the existing 60px avatar (photo-or-initials
  logic and its `onerror` handler unchanged), then a vertical stack of the name (16px / 600 /
  `#e2e8f0`) and the role pill. This row stays horizontal at every width — delete the
  `@media (max-width: 767px)` block from the scoped style entirely; it was sized for the old
  cramped layout and a 60px avatar never needs to drop below a short name.

  the `#1e293b` background, the `#334155` 1px border and the 8px radius.
- Change `.popover-card` from a horizontal flex container to a vertical one (or a block) so
  the sections below the header row get the card's full width.

**Role pill.** Replace the plain-text `role_name` line with an inline-block pill:
`border: 1px solid`, `border-radius: 9999px`, `padding: 2px 10px`, 12px / 600 /
`line-height: 1.2`. Text and border colour follow the existing bench-vs-advocate side
distinction already used for the avatar background — `#94a3b8` for bench, `#93c5fd` for
advocate. This is a side distinction that predates Phase 39; it is not and must never become

**Advocate descriptor slot.** For non-bench speakers only, directly beneath the role pill and
before the bio paragraph, render a 13px / 400 / italic / `#94a3b8` paragraph containing exactly
the two-word string that this codebase already uses for not-yet-wired fields — the same string
the admin editor's inert inputs carried before Plan 39-03 activated them (39-UI-SPEC.md
§Advocate descriptor placeholder gives the exact copy). Render it unconditionally for every
advocate. Do not invent plausible-looking fake data such as a city or a job title.

**Birth/death line.** Bench only, full width, below the header row. Render only when at least
one of `birthdate` / `death_date` is non-null. Format: `b. {formatShort(birthdate)}` and, when
a death date is known, ` · d. {formatShort(death_date)}`. Omit each half independently when its
value is null; when both are null, omit the line. 13px / 400 / `#94a3b8`, `margin-top: 8px`.

**Bio paragraph.** Both bench and advocate, full width, rendered only when `bio_text` is
non-null and non-empty. 14px / 400 / `line-height: 1.5` / `#94a3b8`. Collapsed state applies
`display:-webkit-box; -webkit-box-orient:vertical; -webkit-line-clamp:3; overflow:hidden;`.
Add `let bioExpanded = $state(false)` following the existing `showInitials` idiom. Render a
`Read more` / `Show less` text button (13px, `#93c5fd`, underlined, no background or border,
`cursor: pointer`, `margin-top: 4px`) carrying `aria-expanded={bioExpanded}`, whose click
toggles the state. Instant show/hide — no animation, no modal, no navigation.
The toggle must only render when the text is genuinely clamped: `bind:this` the paragraph
element and use an `$effect` that, while collapsed, sets a `bioOverflows` `$state` from
`el.scrollHeight > el.clientHeight + 1`. A short bio must never show a toggle with nothing to
expand. (39-UI-SPEC.md permits a conservative character-length threshold instead if the
measurement proves unreliable inside the lazily-mounted popover content; if you fall back to
that, record the choice and the threshold in the SUMMARY.)

**Tenure list.** Bench only, full width, below the bio, keeping the existing single
`border-top: 1px solid #334155` above the whole section as its only framing. Render the tenure
array in exactly the order the API returns it — no client-side re-sort. Each entry is a block
with `margin-bottom: 16px` and no divider rule between entries, containing up to three lines,
all 13px / 400 / `line-height: 1.5` / `#94a3b8`:
1. `{officeTitle(t.office)} — {start year}–{end year or 'present'}` (unchanged from current
   behaviour: year-only granularity via string slice, which is inherently timezone-safe).
2. Only when `appointed_by` is non-null: `{t.appointed_by}`, followed by
   ` · {t.appointing_president_party}` only when the party is also non-null. Render
   `appointed_by` exactly as stored — no surname extraction, no truncation, no name parsing.
   When `appointed_by` is null, omit this line entirely even if a party value exists (never
   render a placeholder for the missing half).
3. Only when `reason_left` is non-null: `{reasonLeftTitle(t.reason_left)}`.

**Omission discipline.** No `N/A`, `Unknown`, `—` or "no data" filler anywhere. A missing value
means a missing line. This mirrors the component's existing `{#if speaker.role_name}` treatment

facts happen to be recorded.

**Uniform treatment.** One style string per line type, applied to every value. Do not branch
on a specific party value or a specific reason value for any visual property. `officeTitle()`
and `reasonLeftTitle()` both already degrade to an empty string on a non-canonical input; keep
that behaviour and let the `{#if}` guards omit the line rather than rendering an empty one.

Do NOT add an "Edit person" link, an edit affordance, or any action button — deferred to
backlog item 999.9 (D-17). Do NOT add an age, a tenure length, or a case count — explicitly
out of scope (ROADMAP criterion 4).
