<objective>
Add the operator-facing half of the feature: a server-gated "Dev Tools" section on the existing
`/admin` dashboard with the two-step confirm, the five interaction states, and the server-side
environment gate that keeps the whole section out of the response outside development.

Purpose: DEVTOOL-01's "from the admin panel" clause and DEVTOOL-02's frontend half. Per
Architecture Rule 2 and D-07 the gate must be a server decision, not a client one — a section
that reaches the browser and is hidden there has already leaked the existence of the capability.

Output: `/admin` renders a Dev Tools section in development, wired to
`POST /api/admin/dev/reset-to-fixture` through a SvelteKit form action, and renders nothing at
all outside development.
</objective>

**Read the environment value server-side, at request time.** Import `env` from
`$env/dynamic/private` and read `env.ENVIRONMENT`. Do NOT use `$env/static/private` for this one
variable, even though `ADMIN_TOKEN` and `FASTAPI_BASE_URL` in this same file use it: values from
`$env/static/private` are inlined by Vite at build time, which would make the gate a build-time
decision and produce different build artifacts for development and production. D-07 explicitly
requires the gate to be "evaluated at app-startup/request-time" with "no separate build artifact
for prod vs dev", so the dynamic module is the correct choice here. Add a comment stating this
deviation and its reason, naming D-07, so a future reader does not "normalize" it back to the
static import. Leave the existing `ADMIN_TOKEN`/`FASTAPI_BASE_URL` static import untouched.

Add `isDevelopment` to the `load` function's return object as a boolean derived from an equality
comparison of `env.ENVIRONMENT` against the literal string `development` — an allow-list, matching
D-02's backend contract, so an unset or misspelled value yields `false` and the section is
omitted. Only the boolean crosses to the client; the raw environment string must never appear in
the return value, and must never be read through SvelteKit's client-visible env module.

Add a `resetToFixture` entry to the existing `actions` object, alongside `logout`. It:

  - Takes no form data. Do not read `request.formData()` for values and do not accept a corpus
    path, a fixture list, or any other parameter — the backend endpoint has no request surface and
    this action must not invent one.
  - Re-checks the gate first: if `env.ENVIRONMENT` is not the development literal, return
    `fail(404, { resetError: <the environment-refusal copy> })` without contacting the backend.
    This is defense in depth — the section is already omitted, so this branch should be
    unreachable, and the backend's unmounted router is the real enforcement.
  - `POST`s to `${FASTAPI_BASE_URL}/api/admin/dev/reset-to-fixture` using the action's own
    `fetch`, with the `X-Admin-Token` header set to `ADMIN_TOKEN`, no request body, following
    `updateParticipantSide`'s shape. Wrap the call in `try`/`catch`.
  - Maps failures to exactly the two locked copies from the UI-SPEC Copywriting Contract and no
    third variant. A 404 response maps to `fail(404, { resetError: 'Reset failed: this action is not available in this environment.' })`.
    Every other non-ok status, plus a thrown fetch (network failure), plus a response body that
    does not parse as JSON, maps to
    `fail(502, { resetError: 'Reset failed partway through — the database may be in an inconsistent state. Check server logs before retrying.' })`.
    Note in a comment that the backend's 503 corpus-missing case also lands on the mid-reset copy
    even though nothing was actually deleted (the backend pre-flights the corpus check before the
    TRUNCATE), because the UI-SPEC locks a two-copy set and the server log distinguishes them.
  - On success, parses the JSON body and returns it as the action result — do NOT `redirect`. The
    UI-SPEC's Success state renders inline on the same page, so the page needs the `fixtures`
    array in `form`. Return the fixtures under a stable key (`{ resetFixtures: body.fixtures }`)
    so `+page.svelte` can distinguish success from the `resetError` failure shape.
  - Also guard against a short list: if the parsed body's `fixtures` array does not have exactly
    four entries, return the mid-reset `fail(502, ...)` rather than rendering a partial success
    list. A partial reseed is an error state, not a shorter success state.

Do not modify any of the seven existing fetches, the existing return fields, or `actions.logout`.
