<objective>
Collapse the Resolve table from five columns to the canonical four, stacking the Bench/Advocate
segmented toggle and the person control inside a single Resolved As cell, and replace the
four-branch confirm/correct/Change/Select-person chain with one always-rendered searchable person
dropdown.

Purpose: this is the largest single change in the Figma reconciliation and every later plan in the
44-05..44-09 set layers copy and behaviour on top of the cell boundaries this plan establishes. It is
sequenced first for exactly that reason (44-FIGMA-RECONCILE.md "Open questions / risks": *"Column
merge (RESOLVE-07/08) is the largest single change; sequence it first, then layer copy/behaviour
fixes on top."*). The load-bearing risk is not the markup — it is whether the confirm/correct state
machine can be deleted without breaking the two save contracts that run through this cell: the
per-row hidden-form `side` write, and the batch `?/resolve` person-match payload. Task 2 proves both
end-to-end before four more plans commit on top of it.

Output: a four-column table, a merged Resolved As cell, one always-editable person dropdown, and a
`RowMatchState` with the disposition machinery removed — with the existing DB-gated save round trips
still green.

Task ordering note: Task 1 rewrites the contract assertions that currently encode the retired
five-column and confirm/correct mechanics, so they go red against today's source before Task 2's
tracer turns them green. This is the tracer's own red-first move, split into its own task because
44-05-RESEARCH.md classifies the contract-file rewrite as a Wave 0 gap in its own right
("Treat this file as requiring an editing pass, not just an addition"), and because folding a
558-line test rewrite into the tracer would make it the largest task in the plan set.

## Deltas resolved here (reconciliation-doc gaps, not re-asks)

1. **Two hints in one cell.** Diff row 4 keeps all four ingestion hints source-aware; canonical
   point 1 merges two columns into one cell. Resolution: within the merged cell each sub-control
   keeps its own hint line immediately below it — toggle, then the side hint, then the person
   dropdown, then the Resolved-As hint. This preserves the established "hint sits directly under its
   control" convention rather than orphaning one hint or silently dropping it. Flagged for the
   Task 3 checkpoint against node 4205:81.
2. **Which rows get the dropdown.** RESOLVE-08 says "always-editable", but the only wire path that
   persists a person match is the batch `?/resolve` payload built from the discrepancy list —
   `ResolveRowUpdate` accepts no `person_id`. Resolution: the dropdown renders for rows in the review
   set (a discrepancy entry exists and the card is interactive); rows outside it, and the read-only
   card, keep the resolved-name display. "Always-editable" is honoured as "no click-to-reveal step",
   which is what the requirement's own second clause ("remove Change/Select links") is about.
   Extending a write path so every row's person is directly editable is a real feature, not part of
   this reconciliation — recorded as a follow-on, not silently dropped.
3. **Where the per-row save error goes.** It currently lives in the retired Bench/Advocate cell.
   Resolution: it moves into the merged cell directly under the toggle's hint, since it reports the
   side/descriptor save that the toggle triggers.
4. **Seeding an already-committed row.** The existing effect seeds `personId` only from
   `auto_match_id`, so a row whose `person_id` is already committed but which still appears in the
   discrepancy list seeds as un-reviewed and blocks Continue forever. Resolution: the effect joins
   against `resolveRows` and falls back to the row's own `person_id`/`full_name`. Without this,
   RESOLVE-15's progress count would contradict what the table shows — the exact condition this
   plan's third prohibition forbids.
