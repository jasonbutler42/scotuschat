<objective>
Scope the person search to the side the operator has chosen, and make every ingestion hint say where
the data actually came from.

Purpose: these are the two data/behaviour items in the reconciliation, and research resolved both from
"may need backend work" to "no backend work at all". `Person.is_justice` already exists and
`GET /api/admin/people` already returns it; the field was only being dropped by two overly-narrow
TypeScript annotations on the way through. `job.source` has been a derived `"pdf" | "corpus"` field on
the job response since Phase 30; it was simply never forwarded to the card. So both requirements
reduce to threading data that already exists, plus one client-side filter — which is why they share a
plan and sit directly after the structural merge that gave the toggle and the dropdown one cell.

Output: a side-scoped candidate list with a documented fail-open rule, and a source-aware hint prefix
replacing the interim hardcoded wording.

Decisions implemented:
- RESOLVE-09 (44-FIGMA-RECONCILE.md canonical point 3, diff row 3) — candidates filtered to the currently-selected side — Task 1.
- RESOLVE-10 (canonical point 4, diff row 4) — source-aware hint prefix, uniform per run — Task 2.
- Supersedes 44-CONTEXT.md D-09's uniform hardcoded prefix, which was itself explicitly interim pending real provenance detection. This resolves provenance at the job level; per-field provenance remains a Deferred Idea and is not built here.
- Claude's discretion, locked (RESEARCH assumption A1): a candidate with no `is_justice` value is shown in both filtered lists (fail open), not hidden — Task 1.
- Claude's discretion, locked (RESEARCH Open Question 2): while the side gate is open the list is not filtered — Task 1.
</objective>

## Deltas resolved here (reconciliation-doc gaps, not re-asks)

1. **Which `source` reference to thread.** Both `data.job` (the load result) and `liveJob` (the
   1s-polled copy) carry `source` — verified: `+server.ts` returns the full AdminJobResponse, so the
   polled shape includes it. Resolution: pass `data.job.source`, because a job's ingestion source is
   immutable for the life of the job and reading it from the load data means the hint prefix cannot
   flicker if a poll tick ever returns a narrower shape. `liveJob` stays the source of truth for the
   status/step fields that genuinely change.
2. **Create-person trigger copy.** Canonical point 3 names `Create new advocate` but shows only an
   advocate frame, so the bench variant has no canonical wording. Resolution: mirror the placeholder
   copy symmetrically — `Create new advocate` on an advocate side, `Create new bench person` on Bench —
   using the existing `triggerLabel` prop with no component change. Flagged for 44-09's final visual
   acceptance to confirm the bench wording.
3. **Where the filter goes.** `getRowCandidates` already merges and de-dupes three lists. Resolution:
   leave it doing exactly that and add `sideScopedCandidates` as a separate named function wrapping it,
   so the merge/de-dupe contract and the filter contract can be asserted independently and the
   fail-open rule lives in one readable place.
