## Column-by-Column Contract (RESOLVE-01 through RESOLVE-06)

Five columns, exact order: **Raw Label | Resolved As | Bench/Advocate | Argument Role | Descriptor.** No Action column.

### 1. Raw Label

New visual treatment (not called out as a numbered delta in CONTEXT.md/seed text, but visible in the mockup and not previously present — flagged here as an in-scope visual delta, not a re-ask):

- Inline-block badge/pill: background `#0f1117`, border `1px solid #334155`, border-radius `4px`, padding `4px 10px`.
- Text: 14px, weight 400, `text-transform: uppercase`, `letter-spacing: 0.02em`, color `#e2e8f0`.
- Content: `row.raw_speaker_label` as-is (the uppercase transform is CSS-only — the underlying string stays normal case, since the Resolved-As hint below re-displays this same field un-transformed).
- No hint under this column (Raw Label is itself the raw source — RESOLVE-05 lists Resolved As, Bench/Advocate, Argument Role, Descriptor only, not Raw Label).

### 2. Resolved As

Collapses the old Confirm/Select/Change/Action-column flow into a single entry point per D-03/D-04.

**States:**
- **Resolved** (person_id set): `personDisplay` snippet unchanged (avatar circle, name, optional role suffix) **plus** a "Change" text link — `font-size: 14px; color: #93c5fd; text-decoration: underline; background: transparent; border: none; padding: 0; margin-left: 8px; cursor: pointer;` — reusing the exact visual language of the existing "Edit person" link, but as a `<button>` (toggles local UI state, not navigation).
- **Unresolved, pre-fill available** (`discrepancy.auto_match_id` present, not yet corrected): combobox opens **pre-filled** with `auto_match_name` as the input value; the top suggestion in the listbox carries a small "Suggested" badge (11px, `#93c5fd`, uppercase, positioned after the candidate name) to visually distinguish it from other candidates — this is the D-03 collapse of "Confirm" into "pick the pre-filled top suggestion." Internal mechanics (exact combobox component structure) are Claude's/executor's discretion per CONTEXT.md; the visual language (pre-filled input + "Suggested" badge) is locked here.
- **Unresolved, no pre-fill / not yet opened**: "🔍 Select person…" — leading inline SVG magnifying-glass icon (16×16, `stroke="currentColor"` `stroke-width="2"`, color `#93c5fd`) + text "Select person…", `font-size: 16px; color: #93c5fd; text-decoration: underline; background: transparent; border: none; cursor: pointer;`.
- **Untouched pre-fill on submit** (D-04): counts as accepted — no visible change to this cell's rendering is required to signal this; it is a submit-time behavior, not a new visual state.

**Hint (RESOLVE-05):** `Imported: {raw_speaker_label}` when the row is resolved (`full_name` present); `Imported: N/A` when unresolved — **not** simply always echoing `raw_speaker_label` (confirmed against the mockup: rows 3–4, both unresolved, show "Imported: N/A" even though their raw labels are non-empty). Rendered via `CopyableExtractedValue` with `prefixLabel="Imported"`, `raw={null}` (no `confidence` prop) so only the single-line "Imported: …" renders — see Component Change section below for why.

### 3. Bench/Advocate — Segmented Toggle (RESOLVE-02)

Replaces the `<select name="side">`. Also reused verbatim as the pre-resolution side-gate (D-07) — same component, no visually distinct "gate mode."

**Structure:** one joined pill container, two buttons sharing a single outer `border: 1px solid #334155; border-radius: 6px; overflow: hidden; min-height: 36px;` with a `1px solid #334155` seam between the two segments (no gap). Each segment: `font-size: 14px; padding: 6px 14px; cursor: pointer (when editable); border: none;`.

**State matrix:**

| State | Bench segment | Advocate segment | Trigger |
|-------|---------------|-------------------|---------|
| Bench active | fill `#4ade80`, text `#0f1117`, weight 600 | transparent fill, text `#94a3b8`, weight 400 | `side === 'BENCH'` |
| Advocate active | transparent fill, text `#94a3b8`, weight 400 | fill `#93c5fd`, text `#0f1117`, weight 600 | `side` is any non-BENCH value (`PETITIONER`/`RESPONDENT`/`AMICUS`/`UNKNOWN`/legacy `ADVOCATE`) and row is not gated |
| Neither active (gate state, D-07) | transparent fill, text `#94a3b8`, weight 400 | transparent fill, text `#94a3b8`, weight 400 | `needsSideGate(row)` true — matches the mockup's "Unknown Speaker" row exactly |
| Disabled (readonly mode / `!row.editable`) | same fill logic as above but `opacity: 0.6`, `cursor: default`, no click handler | — | `!interactive \|\| !row.editable` |

Clicking either segment when editable and not-yet-gate-resolved behaves exactly as the current `confirmSide`/`onSideChange` handlers (extend `pendingSideOverrides`/`sideGateConfirmed`, submit the hidden row form) — no new state model, per CONTEXT.md's explicit instruction to extend rather than replace these.

**Hint (RESOLVE-05):** `Imported: Bench` / `Imported: Advocate` / `Imported: N/A` (gate state only) — a simplified two-value label (never the granular role name), via `CopyableExtractedValue` with `prefixLabel="Imported"`, `raw={null}`.

### 4. Argument Role (RESOLVE-03)

**Bench rows, tenure valid (`!row.missing_tenure`):** locked, read-only display — inline SVG lock icon (14×14, `stroke="currentColor"` `stroke-width="2"`, color `#94a3b8`) + `row.bench_role`, inside a box styled like a disabled input: `background: #1e293b; border: 1px solid #334155; border-radius: 6px; padding: 8px 12px; min-height: 36px;` text `16px #e2e8f0`, icon-to-text gap `6px`. This is the RESOLVE-06 lock affordance — visually distinct from the Missing-tenure state below (bordered/neutral vs. amber-warning).

**Bench rows, missing tenure:** unchanged verbatim from current code — "⚠ Missing tenure" (`#fbbf24`, 14px) + "Edit person" link (`#93c5fd`, 14px, underline) below it. RESOLVE-06 explicitly requires this stays visually distinct from the locked state above (no lock icon, amber color, no bordered box).

**Advocate rows:** real `<select>` matching the existing control style (`background: #0f1117; border: 1px solid #334155; border-radius: 6px; padding: 8px 12px; font-size: 16px; color: #e2e8f0; min-height: 36px;`), 3 real options plus the placeholder-as-first-option (D-01/D-02):

```html
<option value="UNKNOWN">Select case role</option>
<option value="PETITIONER">Petitioner's Counsel</option>
<option value="RESPONDENT">Respondent's Counsel</option>
<option value="AMICUS">Amicus Curiae</option>
```

`UNKNOWN` (fresh toggle, no pick yet) and legacy `ADVOCATE` both map to the first/placeholder option — do **not** use a disabled/empty-value option; `UNKNOWN` is a real, already-supported value, so the placeholder option's `value` is literally `UNKNOWN` (not `""`). Saving without ever touching this control leaves `side=UNKNOWN`, matching D-02 exactly, with no new empty-string sentinel to reconcile server-side.

**Hint (RESOLVE-05)** — state-dependent copy, not a flat echo of `side` (confirmed against all 5 mockup rows):

| Row state | Hint text |
|-----------|-----------|
| Bench, valid tenure | `Imported: N/A - from tenure` |
| Bench, missing tenure | `Imported: N/A - tenure not found` |
| Advocate, role set | `Imported: {ADVOCATE_LABEL_MAP label}` e.g. `Imported: Respondent's Counsel` |
| Advocate, unset (placeholder) | `Imported: N/A` |
| Gate state (neither Bench/Advocate chosen yet) | `Imported: N/A` |

Via `CopyableExtractedValue` with `prefixLabel="Imported"`, `raw={null}`.

### 5. Descriptor (RESOLVE-04 — renamed from Title, always renders)

**Bench rows (any sub-state):** static "–" (`color: #94a3b8`), no input, no placeholder — column never disappears, per RESOLVE-04's literal requirement. Hint still renders below it: `Imported: N/A`.

**Advocate/editable rows (including unresolved/gate rows — Phase 27 CR-01/CR-02 invariant: keep this data-carrying input always in the DOM, never conditionally rendered):** `<input type="text">` matching the existing style (`background: #0f1117; border: 1px solid #334155; border-radius: 6px; padding: 8px 12px; font-size: 16px; color: #e2e8f0; min-height: 36px; width: 100%; box-sizing: border-box;`) plus `overflow: hidden; text-overflow: ellipsis; white-space: nowrap;` so a long value (e.g. "Solicitor General of the United States") truncates with an ellipsis when unfocused, matching the mockup's "Solicitor Gene…" rendering, with placeholder "e.g. Attorney, Location, or Affiliation" when empty.

**Hint (RESOLVE-05):** `Imported: {row.descriptor_hint}` or `Imported: N/A` when empty — via `CopyableExtractedValue` with `prefixLabel="Imported"`, `raw={null}` **(no `confidence` prop)** — this is a deliberate simplification vs. the current Title column's 2-line stacked render (`confidence="Medium" raw={row.title_hint}` today produces a redundant second line "Medium confidence · Raw: {value}"). The mockup shows exactly one hint line for every column including Descriptor — this contract locks Descriptor to the same single-line treatment as the other 3 columns for visual consistency, superseding the pre-existing 2-line stacked mode inherited from Phase 38. Flagged explicitly since it changes existing call-site behavior, not just adds new ones.

## Component Change Required: `CopyableExtractedValue.svelte` (D-09)

Add an optional `prefixLabel` prop, default `"Extracted"`, replacing the hardcoded string at line 111:

```ts
type CopyableExtractedValueProps = {
  value: string | null | undefined;
  copyLabel: string;
  variant?: 'text' | 'pill';
  confidence?: ConfidenceBand | null;
  raw?: string | null;
  prefixLabel?: string; // NEW — default 'Extracted', ResolveCard passes 'Imported'
};
```
```svelte
<span class="prefix">{prefixLabel}:</span>
```

Every existing call site (`ArgumentDetailsCard.svelte`, `DocketPillInput.svelte`, `app/src/routes/admin/pipeline/[job_id]/+page.svelte`, `app/src/routes/admin/people/[id]/+page.svelte`, `app/src/routes/admin/arguments/[id]/+page.svelte`) omits the new prop and is therefore unaffected — default stays `"Extracted"`.

**All four `ResolveCard.svelte` hint usages** pass `prefixLabel="Imported"` and `raw={null}` (never `confidence`) — passing `raw={null}` (not `undefined`) is what activates stacked mode (so the `{prefixLabel}:` prefix renders) while `hasRaw` stays `false` (so the second "confidence · Raw: …" line stays suppressed). Do **not** copy the Title column's old `confidence="Medium" raw={row.title_hint}` pattern verbatim — that produces an unwanted second line, per the Descriptor note above.
