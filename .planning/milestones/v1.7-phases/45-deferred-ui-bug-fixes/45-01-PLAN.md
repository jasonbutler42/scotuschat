<objective>
Close BUG-01: an argument that has not been published must be unreachable from the public
surface — absent from the `/cases/` list (already true via D-06) and returning a plain 404
on direct access to both of its public detail endpoints.

Purpose: this is a real content-exposure gap. `GET /arguments/{id}/utterances` and
`GET /arguments/{id}/speakers` currently return full transcript and speaker data for any
existing argument row regardless of publish status, so an unpublished argument is reachable
by URL even though the list hides it.

Output: the `Argument.published_at.isnot(None)` predicate applied inside both public service
functions (D-02), a plain indistinguishable 404 on both endpoints (D-01), a source-contract
test class plus a DB-gated integration class in `api/tests/test_published_gate.py`, and an
operator-confirmed live publish/unpublish round trip.

Decisions implemented by this plan (45-CONTEXT.md):
- D-01: a plain 404, indistinguishable from a nonexistent argument ID, with no "not published"
  messaging reaching an unauthenticated visitor — Task 1 (utterances, via the pre-existing
  None-to-404 branch), Task 2 (speakers, via the new None-to-404 branch reusing the identical
  detail string), confirmed at Task 3 step 4.
- D-02: the gate applied at BOTH `GET /arguments/{id}/utterances` (Task 1) and
  `GET /arguments/{id}/speakers` (Task 2), keyed on `Argument.published_at` and never on
  `resolved_at`, so no unpublished argument data leaks through either endpoint.
</objective>
