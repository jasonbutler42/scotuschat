<objective>
Close BUG-02: make the scrolling box and the visually-bounded box the same element so the
native scrollbar renders flush inside the speaker popover's rounded card instead of at the edge
of an invisible scroll container.

Purpose: today `Popover.Content` owns `max-height`/`overflow-y` while the visible card surface,
border, and radius live on `.popover-card` inside it. The two boxes are different elements, so
the scrollbar appears outside the card the operator sees.

Output: the box model relocated onto `Popover.Content`, a source-contract regression test locking
single-element ownership and the full Phase 39 field set, and operator-confirmed visual
verification at two viewport heights.

Decisions implemented by this plan (45-CONTEXT.md):
- D-03: move the visible card styling (background, border, border-radius, plus the width bounds
  that define the same box) onto `Popover.Content` itself so the scrolling element and the
  visually-bounded element are one box and the native scrollbar renders flush inside the card —
  Task 1 performs the relocation, Task 2 locks it plus the Phase 39 field set, Task 3 confirms it
  visually. The alternative considered and NOT selected in the same decision — custom scrollbar
  theming — is carried as a prohibition rather than a task.
</objective>
