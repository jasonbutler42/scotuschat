<objective>
Fix the pytest DB-isolation bypass (D-03, folded todo `2026-08-12-pytest-explicit-paths-bypass-db-isolation.md`) definitively, so that no pytest invocation shape can silently run "DB-gated" tests against the live shared dev database.

Root cause (from 46-RESEARCH.md): `tests/conftest.py` is a *sibling* of `api/tests/` and `pipeline/tests/`, not their ancestor. pytest's conftest discovery is strictly hierarchical, so explicit-path invocations under the sibling directories never import it — the `TEST_DATABASE_URL` redirect and the dev-DB row-count tripwire both silently no-op. This wiped the dev DB to 0 rows twice during Phase 45.

The fix is a *location* fix: relocate the redirect + tripwire to a `conftest.py` at the pytest rootdir (repo root, alongside `pytest.ini`), which is an ancestor of every `testpaths` entry by construction, then add a fail-closed sentinel so the sibling conftests refuse to run DB-gated tests if the rootdir conftest is ever not collected again.

Purpose: this is the single highest-stakes item in Phase 46 — it is actively destroying local data, so it ships first, before anything else in the phase touches Postgres or the venv.
Output: a rootdir `conftest.py`, two permanent probe tests, one subprocess-based invocation-shape regression test, fail-closed guards in both sibling conftests, and a CLAUDE.md invariant so the bug class cannot be re-created.
</objective>
