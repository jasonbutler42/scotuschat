  <context>
    46-CONTEXT.md's D-04 rates the relocation **costly**, and the single element that makes it costly rather than merely inconvenient is this one: the pre-relocation checkout is a full duplicate of a repository whose local `main` is 217 commits ahead of `origin`. Until now that duplicate has been the phase's rollback path, deliberately left untouched by every plan.

    Everything that made it a rollback path has now been discharged. Plan 46-04 proved the copy faithful (identical HEAD, identical total commit count, clean `git fsck`, intact remote, byte-identical secrets). Plan 46-05 Task 1 proved the two checkouts have not diverged and fast-forwarded the survivor. Plan 46-05 Task 3 proved the whole stack runs from the new location across two clean start/stop cycles with a live reload observation. Task 1 above has removed the last documentation pointing at the old location.

    Two things remain true and argue against reflexively deleting. First, the duplicate is the only offline second copy of those 217 unpushed commits; `origin` cannot substitute for it. Second, deletion is not undoable — the directory is on a Windows-mounted drive, so it does not go to a recycle bin from a WSL removal, and its untracked contents (`.env`, `app/.env`, the raw corpus and PDF payload) are not recoverable from git.

    Two things argue for removing it. It is a live git repository on `main` that a stray shell, editor window, or scheduled task could still commit into, silently forking history in a way that is expensive to notice late. And it holds the retired `data/pgsql` and `data/pgdata` directories, which is the second "how do I start PostgreSQL" story D-02's discretion note wanted eliminated.

    Whichever option is chosen, Task 3 writes a marker at the old location first and re-proves the survivor's integrity immediately before touching anything.
  </context>

  <options>
    <option id="option-a">
      <name>Delete the pre-relocation checkout now</name>
      <pros>Removes the divergence risk entirely — there is no second `main` to accidentally commit into.
