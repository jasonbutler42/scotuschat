<objective>
Convert the three PDF-lifecycle write paths — ingest, parse, resolve — to the `ImportRun` model
and make each declare its `source` and `method` at row creation, then prove the two
`pdf_pipeline` legs of the D-06 verification guardrail with real end-to-end tests.

Purpose: 47-01 proved the vertical on the corpus path. This plan expands it horizontally to the
remaining write paths so that PROV-05's "every import path stamps provenance at write time" is
literally true rather than true for one path. Without this, two of the three combinations
success criterion 4 requires are unproven.

Output: ingest/parse/resolve stamping `pdf_pipeline` with `normalized`, `rule_based` or
`llm_corrective`; the `strategy` string retired from the parse write loop; and
`pipeline/tests/test_import_run_provenance.py` covering all three D-06 combinations.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI (`python -m pipeline ingest/parse/resolve`) -> PostgreSQL | Untrusted PDF content and a caller-supplied `--url` cross here into `import_run.pdf_url` |
| `parse.py` -> Anthropic API | Transcript text leaves the process; the response drives which `method` is stamped |
| test harness -> Anthropic API | A test that forgets to monkeypatch `parse_with_llm` would make a real, billable call |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-47-07 | Spoofing | `parse.py` method stamping | medium | mitigate | `method` is derived from the actual branch taken (`parse_with_llm` returned vs raised), never from a caller-supplied argument or CLI flag — an operator cannot assert a higher-authority method than the code actually used. Covered by the two Task 3 tests. |
| T-47-08 | Information Disclosure | Test suite calling the live Anthropic API | medium | mitigate | Both Task 3 tests monkeypatch `pipeline.commands.parse.parse_with_llm`; an acceptance criterion greps that the file never imports `anthropic`. |
| T-47-09 | Tampering | `import_run.pdf_url` from `args.url` | low | accept | `pdf_url` is an operator-supplied string stored verbatim for lineage and rendered only in the dev-only admin surface, which is unchanged by this phase. ASVS L1 requires no additional control for an offline CLI argument written by the operator themselves. |
| T-47-06 | Tampering | `import_run.source` / `method` writes from the PDF paths | low | mitigate | The native enum types plus NOT NULL reject out-of-vocabulary and missing values at the storage boundary; a typo in a writer fails loudly at insert rather than silently storing a bad string (ASVS V5). |
| T-47-SC | Tampering | npm/pip/cargo installs | low | accept | No packages are installed this phase — RESEARCH.md records "Package Legitimacy Audit: Not applicable"; no `[ASSUMED]`/`[SUS]`/`[SLOP]` entries exist. |

ASVS level 1; block on `high`. This plan introduces no `high`-severity threat; the two `medium`
threats are dispositioned `mitigate` with in-task controls and matching acceptance criteria.
</threat_model>
