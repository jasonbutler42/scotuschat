<objective>
Convert the FastAPI read layer and the public utterance contract to `ImportRun`, and retire the
`strategy == "convokit_import"` string-equality hack in favour of the declared
`ImportRun.source == ImportSource.CORPUS` comparison.

corpus or was it LLM-guessed from a smudgy PDF?" stops being answered by archaeology across a
free-text column and starts being answered by reading a declared enum. It is also what makes
the `api` package importable again after 47-01's atomic schema change.

`schemas/utterance.py` on the new names; `PIPELINE_RUN_STRATEGY` deleted along with both of its
consumers.
</objective>

<scope_fence>
D-04 keeps `admin_jobs` out of scope for Phase 47. What that fence means concretely here:

**In scope** — the mechanical `PipelineRun` -> `ImportRun` / `pipeline_run_id` ->
`import_run_id` rename in `api/services/admin_jobs.py`, and replacing the two
`PipelineRun.strategy == PIPELINE_RUN_STRATEGY` comparisons with
`ImportRun.source == ImportSource.CORPUS`. Both are forced by 47-01's schema change — the module
does not import, and the column it compares no longer exists.

**Out of scope** — re-pointing the `admin_job` table to `import_run`, changing the `step`-based
query semantics, collapsing the per-step run grain, or altering the `get_run_id_for_step`
ordering. All of that belongs to the later "Path rework" phase.

**Grain decision, recorded here for the file:** `import_run` keeps today's per-step grain — one
row per ingest / parse / resolve — rather than collapsing to one row per argument. The
row-count-preservation constraint that would have forced per-step is gone (D-01), so this was a
genuinely open modelling choice. It is decided per-step because the alternative forces query
rewrites in exactly the three modules this plan is trying to leave semantically untouched:
`api/services/arguments.py` filters `step == "parse"` and takes `MAX(id)` to select which
utterances a visitor sees; `api/services/admin_jobs.py` derives `parse_stats` and step-specific
run ids from `step`; `api/services/admin_arguments.py` cascades on the FK ordering. Preserving
`step` is what actually honours D-04's intent. CONTEXT.md's Deferred Ideas already tracks
per-argument grouping (`import_batch`) as a later possibility — that is where the re-architecture
belongs.
</scope_fence>
