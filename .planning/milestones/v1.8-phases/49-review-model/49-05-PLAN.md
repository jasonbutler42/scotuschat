<planner_decisions>
**Four UI-SPEC considerations were left `unresolved` for the planner. All four are resolved here rather than carried forward as assumptions** (each is now an explicit `must_haves` truth above):
- **E5 `empty`** — a published-but-degraded argument with zero flagged constituents still gets the "Show details" toggle; the expanded panel renders `summarize_tier_blockers`' breakdown sentences through the existing `blockerSentence` helper. Rationale: 49-CONTEXT.md's own integration note says the queue's needs-attention summary should read from `summarize_tier_blockers` rather than recompute the reasons, and an argument in the queue for a real reason must be able to say what that reason is.
- **E7 `overflow`** — the action row wraps (`flex-wrap: wrap`). An unresolved-speaker constituent that has already been confirmed genuinely co-renders all four actions.
- **E8 `empty`** — at 0, the StatCard shows the count with non-link muted text instead of an accent link into an empty queue.
- **E8 `zero-one-many`** — the link text pluralizes.

**Two UI-SPEC claims are overridden by verified source; source wins.**
1. **The StatCard grid does NOT absorb a fifth card.** `app/src/routes/admin/+page.svelte:240` is `grid-template-columns: repeat(4, 1fr);` — a literal four-column grid, not `auto-fit`. RESEARCH Pitfall 3 caught this. This plan changes it to `repeat(5, 1fr)` explicitly.
2. **`/admin/arguments/{id}` has no Resolve card, and `SpeakerPopover` is not a person-assignment control.** UI-SPEC says the Arguments-tab "Edit" action deep-links to `/admin/arguments/{id}` and anchors to "the Resolve card row for that constituent". Verified: `ResolveCard.svelte` is mounted only on `/admin/pipeline/[job_id]`; `/admin/arguments/[id]` has its own "Speakers" card that edits `side` and `descriptor` but **cannot change `person_id`**; and `SpeakerPopover.svelte` is the public case-page bio popover, not a person picker (the picker is `ResolveCard` + `CreatePersonPopover`). The Edit deep-link is therefore routed by what the operator needs to change: a **person-link** edit goes to `/admin/pipeline/{job_id}` for the argument's linked `AdminJob` (where the person-search / assign / create stack actually lives), falling back to `/admin/arguments/{argument_id}` when the argument has no linked job; a **People-tab** row edit goes to `/admin/people/{person_id}`. The queue's list payload must therefore carry the argument's `admin_job_id` (nullable) so the link can be built server-side.
</planner_decisions>
