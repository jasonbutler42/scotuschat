<planner_decisions>
**D-33a's mechanism, made concrete.** The locked decision says a dev-only direct-insert mechanism gated the same way `reset_to_fixture` is, with no analog to copy. The concrete shape chosen here: a second service function and a second endpoint in the **existing** `admin_dev` module and router, not a new module — that router is already the project's one environment-gated surface and `api/main.py` already mounts it conditionally, so reusing it means the gate has exactly one implementation. The seeder does not insert a synthetic participant from nothing; it takes an existing fixture argument's advocate participant and nulls its `person_id`, which produces the same row shape the PDF MISS path would and keeps the fixture representative rather than fabricated.

**Rejected alternatives, recorded so they are not re-proposed:** a synthetic corpus `FIXTURE_SET` entry (would require `_resolve_person` to grow a give-up branch — a production behavior change for a test need), and pytest-only coverage with the live fixture deferred (leaves D-33 unproven end to end, which is the entire objection D-33 exists to answer).
</planner_decisions>
