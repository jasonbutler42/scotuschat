<decision_record>
**OQ-3 (operator, 2026-08-25) — LOCKED.** The comparison digest is read from the latest `step="parse"` run — the run the public read path actually serves. When it differs, a NEW `step="parse"` run carrying the new digest is written. Reconcile runs are minted lazily per D-06 and carry no comparison digest.

**PD-14 — the compare-set walk order, fixed and documented.** The pass walks fields in exactly this order, and the order is part of the contract because it determines the order `value_discrepancy` rows are created in and therefore the order they render in (`ValueDiscrepancy.id` ASC is the queue's stable render key):
1. `Argument.argued_date`, 2. `Argument.question_number`, 3. `Argument.source_docket`,
4. lead `Case.case_name`, 5. lead `Case.docket_number`,
6. for each paired participant ordered by `ArgumentParticipant.id` ASC: `person_id`, then `side`, then `descriptor`,
7. for each `Person` reached through a paired participant, ordered by `Person.id` ASC and visited at most once: `first_name`, `middle_name`, `last_name`, `name_suffix`.
`slug`, `term_year`, `CaseArgument.is_lead` and `Person.is_justice` are OUT of the compare set (D-02).

**PD-15 — D-03's no-opinion rule lives in the gate, not in the caller.** Plan 50-02 put the blank-incoming pre-check inside `apply_argument_value_change` / `apply_case_value_change`, and PD-13's gap-fill rule inside all four gates. The reconcile pass therefore does NOT re-implement either — it passes every compare-set field to the gate and interprets a `None` return as "no opinion, nothing happened". Two implementations of "is this value blank" is exactly how the two writers start disagreeing about what "the same input" means.

**PD-16 — D-07's restamp is a second statement, not a gate change.** `apply_participant_value_change` never touches `source`/`method` (verified: its only `.values()` call sets the target field). The one existing restamp precedent in the codebase is backfill-only, gated on the row having never been stamped, and would silently fail D-07 if copied. The reconcile pass issues its own restamp after every accepted write, unconditionally.

**PD-17 — the batch counter names.** `arguments_reconciled`, `arguments_unchanged` (both introduced by plan 50-01), plus `values_accepted`, `values_rejected`, `discrepancies_recorded`, `utterance_sets_replaced`, `published_writes_skipped`. All whole-batch totals; no per-speaker or per-person breakdown of any kind.
</decision_record>

`_replace_utterance_set(ctx, incoming_rows)`:
1. Mint a NEW `ImportRun` with `argument_id`, `step="parse"`, `status=ImportRunStatus.COMPLETED`, `source=ImportSource.CORPUS`, `method=ImportMethod.DIRECT`, `external_id=conversation_id`, and `content_digest` set to the incoming digest. Flush to obtain its id.

3. Source each row's `person_id` from the POST-reconcile paired `ArgumentParticipant`, never from the raw corpus speaker mapping (D-11). The participant row is where operator resolve work lives and is authority-protected, so operator corrections survive a re-import for free; sourcing from the corpus directly would silently discard every operator reassignment, a direct IMPORT-04 violation.
4. Delete nothing. Superseded rows and their runs are retained (D-12); `pipeline prune-runs` in plan 50-07 is the only thing that removes them.
5. Increment `utterance_sets_replaced`.

Steps 1 and 2 MUST occur in the same transaction, with no intervening commit. A `step="parse"` / COMPLETED run with no utterance rows makes that argument's public chat page render empty, because the read path deliberately selects the newest such run rather than a max over utterances. This is the single hardest constraint in the phase; state it in the function docstring, not only here.

Handle the empty-incoming case explicitly: when the incoming row set is empty and the stored set is not, do NOT write an empty replacement run. Increment `conversations_errored`, print a WARNING naming the conversation id and the stored row count, and leave the argument untouched — an empty corpus turn list is far more likely to be a load or filter defect than a genuine claim that a real oral argument has no utterances, and the blank-page hazard makes the failure mode catastrophic and silent.
