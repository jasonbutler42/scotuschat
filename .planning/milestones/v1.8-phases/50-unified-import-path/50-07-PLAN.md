**PD-22 — the prune-runs safety rule.** A run is a prune candidate only when it is NOT the run `api/services/arguments.py`'s `MAX(ImportRun.id) WHERE step='parse' AND status='completed'` select would return for its argument. That select is the exact definition of "the run the public currently sees", so reusing its shape is the only way the two can never disagree. `step="reconcile"` runs are separately prunable once they carry no open `value_discrepancy` rows.

**PD-23 — prune-runs and the discrepancy FK.** `value_discrepancy.import_run_id` is a hard FK to `import_run.id`. A run with attached discrepancy rows is refused by default with a counted, printed line naming the run and the open-row count — never silently skipped and never cascaded. `--include-resolved-discrepancies` opts into deleting the RESOLVED discrepancy rows attached to a prunable run; open rows are never deleted by this command under any flag, because an open row is an operator's outstanding work item.
</decision_record>
