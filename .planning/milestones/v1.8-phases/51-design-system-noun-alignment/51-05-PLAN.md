## Same-wave plans execute serially in one working tree

`.planning/config.json` sets `workflow.use_worktrees: false`, so this project has no
worktree-isolated parallel execution: same-wave plans run one after another against the same
checkout and the same `app/node_modules`.

This plan is a READER of the resolved dependency tree — every task runs
`npm --prefix app run check` and `npm --prefix app run build`. Plan 51-03, in the same wave, is a
WRITER of `app/package.json` and `app/package-lock.json` (it removes the Tailwind dependencies and
refreshes the lockfile). Practical consequence for the executor: if a `check` or `build` here fails
on a missing or half-removed module, confirm first that plan 51-03's dependency removal completed
and that `npm --prefix app install` was re-run — do not start debugging the component move.

The assumption is recorded rather than the ordering changed. The coupling runs through the
resolved dependency tree, not through a shared file, so the `files_modified` overlap check cannot
see it and an artificial `depends_on` edge would inflate the wave graph for a race that does not
exist under serial execution. If this project ever enables worktrees or genuinely concurrent
same-wave execution, this pair must be re-examined — a lockfile rewrite landing mid-`npm run
build` is a real race. An unstated assumption is the defect; the ordering itself is fine.
</execution_assumption>
