## Design System

| Property | Value |
|----------|-------|
| Tool | none — **shadcn is not applicable to this project.** shadcn's component preset generation is built on Tailwind; D-01 removes Tailwind entirely (operator: *"I kind of hate tailwind"*). CSS custom properties are the token layer instead. |
| Preset | not applicable |
| Component library | `bits-ui` (headless primitives — already a dependency, currently used only by `SpeakerPopover`) + a new hand-rolled primitive set (`Button`, `Badge`, `Input`, `Card`) in `lib/primitives/` per D-17 |
| Icon library | **Undecided — see "Dependency Candidates (D-18)" below.** No icon library exists today; the codebase has near-zero icon usage (2 files touch an SVG/icon concept at all). Operator decision needed before Wave 1 component work. |
| Font | `system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif` — unchanged, already declared once in `app/src/app.css`, inherited everywhere via `font-family: inherit` |

### Figma & Token Architecture (D-02, D-05, D-06, D-07)

- **Figma first, code follows.** The token set and component library are designed in Figma before implementation lands. Work happens in the operator's personal "Jason Butler's team" (Full seat) — never in "Offen Petroleum Design Team" (View-only, and this is a personal project, not Offen work).
- **Figma Variables (not Styles)** hold color/space/type, because Variables export cleanly to CSS custom properties.
- **Figma pages mirror the code layout, verbatim:**

| Figma page | Code destination |
|---|---|
| `Tokens` | `app/src/app.css` `:root` |
| `Primitives` | `app/src/lib/primitives/` |
| `Public` | `app/src/lib/public/` |
| `Admin` | `app/src/lib/admin/` |

- A component's Figma name equals its file name, so drift is visible rather than silent.
- **Two-layer token architecture (D-02):** a primitive palette (raw hex, private to the token file) feeds semantic role names (what components actually reference). Only semantic names are ever written in component code — never `--color-slate-800`, always `--color-surface`.
- **Dark only, structured for light later (D-02).** Ship only dark values this phase. The two-layer structure is what makes adding a light theme later a contained addition (a second value set) rather than a rewrite — do not collapse to a flat single-layer token set.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between pills/chips/badges; tight inline flex gaps |
| sm | 8px | Label-to-input gap; gap between inline buttons; table cell horizontal padding |
| md | 16px | Field-to-field vertical margin within a card; margin between stacked cards |
| lg | 24px | Card internal padding; heading-to-content margin |
| xl | 32px | Layout gaps between major page regions (new — not yet a named token, but already implied by existing spacing math; formalize it) |
| 2xl | 48px | Page content top/bottom padding |
| 3xl | 64px | Page-level spacing for the largest public reading surfaces (new — reserved for the redesigned public listing/transcript vertical rhythm per D-09; not required for admin) |

Exceptions: touch targets — buttons and inputs are `min-height: 44px` (WCAG 2.1 AA), except compact per-row inline buttons inside dense admin tables, which stay at `min-height: 36px`. This exception is carried forward unchanged from the existing system; do not regress it during token conversion.

## Typography

D-03 locks a **tight named type scale of ~5 semantic steps**: caption / body / lead / heading / display. Today's 9 raw sizes (11, 12, 13, 14, 16, 18, 20, 28, 32px) and 3 weights (400/500/600) collapse onto this scale and 2 weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Caption | 14px | 400 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Lead | 18px | 400 | 1.6 |
| Heading | 20px | 600 | 1.2 |
| Display | 32px | 600 | 1.2 |

**Weights: exactly 2 — regular (400) and semibold (600).** No 500 anywhere at phase end.

**Collapse mapping (executor reference, not exhaustive per-instance — verify each site visually during conversion):**

| Today | Collapses to |
|---|---|
| 11px, 12px, 13px | Caption (14px) — these three were already tightly clustered meta/label sizes |
| 14px | Caption (14px) |
| 16px | Body (16px) — unchanged |
| 18px | Lead (18px) — unchanged; reserved for public reading surfaces (see below) |
| 20px | Heading (20px) — unchanged |
| 28px, 32px | Display (32px) |
| weight 500 (2 sites, both in `ResolveCard.svelte`) | weight 600 — verify visually, since 500 may have been intended as a deliberate mid-weight; if the operator disagrees on sight, it becomes a D-08 "surfaced artifact," not a silent revert |

**Where Lead is used:** Lead (18px/400/1.6) is reserved for the redesigned public reading layer per D-09 — transcript utterance body text and term-list case names on the public listing. It is not an admin size; admin draws from the small end of the scale (Caption/Body/Heading), public from the full range (Caption through Display).

**Where Display is used:** page-level titles only — an argument's case name headline on the transcript page, an October Term heading on `/arguments/term/{year}`. Not used in admin.

## Dependency Candidates (D-18)

D-18 is a standing rule: identifying candidates is Claude's job; adopting a dependency is the operator's call. Present tradeoffs, do not decide.

### Icon library — needed for Wave 1 primitives (chevron/disclosure on term rows, popover close affordance, nav hamburger, admin action icons D-08 may surface)

| Candidate | Tradeoffs |
|---|---|
| **`lucide-svelte`** | ISC (corrected 2026-08-28; originally recorded here as MIT — see `51-DESIGN-DECISIONS.md` D-18 amendment), ~1,500 tree-shakable Svelte icon components, actively maintained, zero CSS-framework coupling (fits post-Tailwind D-01). Matches the "one SVG per icon" shape the two existing hand-rolled icon sites already use. Adds one new dependency; each imported icon is its own small component so bundle cost scales with actual usage, not the whole set. **Note: adopted as the scoped successor package `@lucide/svelte` — see the D-18 amendment.** |
| **`@iconify/svelte`** | Access to effectively every open icon set through one dynamic component. Heavier for this project's actual need (a handful of icons): the dynamic-lookup model is less tree-shakable per-icon than `lucide-svelte`'s discrete components, and pulls in a runtime resolver this project doesn't otherwise need. |
| **Continue hand-rolled inline SVG (status quo, zero new dependency)** | Consistent with today's near-zero icon footprint (2 files) and D-01's anti-bloat spirit. Scales worse if D-08's admin-refactor surfacing pass turns up many action icons across the 15 existing components — each one becomes a hand-maintained inline `<svg>` block with no shared sizing/stroke convention. |

**Non-binding lean:** if the primitives pass (`Button`, `Badge`, `Input`, `Card`) needs more than ~5 distinct icons (loading spinner, chevron, close/X, external-link arrow, checkmark), `lucide-svelte` is the better fit. Below that, hand-rolled stays proportionate. Raise this at the Wave 1 checkpoint rather than deciding silently either way.

### Popover / overlay primitives — already resolved, no new decision needed

`bits-ui` is already a dependency and already proven on `SpeakerPopover` for exactly the case D-18 names as legitimate: focus management, keyboard navigation, and ARIA state that are genuinely hard to hand-roll under the project's WCAG 2.1 AA commitment (Phase 4). Continue using it for any **new** focus-managed control this phase introduces — a disclosure/toggle on the D-16 advocate-name row variant, if the visual decision needs one, is the most likely candidate. Do not hand-roll a second focus-trap implementation.

## Visual Hierarchy & Icon Accessibility

Added 2026-08-27 to close the checker's Dimension 2 FLAG. Not new design direction
— these are contracts the Figma pass (D-05) must satisfy and the checker found
undeclared.

### Icon-only controls — accessible name is mandatory

WCAG 2.1 AA is a standing project commitment (Phase 4). An icon-only control with
no accessible name is a conformance failure, not a style preference. Every
icon-only control MUST carry a programmatic name by one of these, in order of
preference:

1. A visible text label beside the icon. Preferred wherever space allows — it
   serves sighted users too, and needs no ARIA.
2. `aria-label` on the control, when the icon must stand alone (nav hamburger,
   popover close affordance, dense admin row actions).
3. `aria-labelledby` pointing at existing visible text, when the control's
   meaning comes from a nearby label (a disclosure chevron whose row already
   names the term).

Additional rules:

- The icon itself is `aria-hidden="true"` whenever the control is already named
  by 1–3 above. Otherwise screen readers announce the name twice.
- A `title` attribute is NOT an acceptable substitute — it is unreliable across
  screen readers and invisible to touch users.
- Tooltips are a supplement, never the accessible name.
- The 44px touch-target rule applies to icon-only controls unchanged (36px only
  for dense in-table admin rows). An icon smaller than its target gets padding,
  not a smaller hit area.
- This applies to every icon-only control regardless of which option D-18's icon
  library decision selects. It binds `lucide-svelte`, `@iconify/svelte`, and
  hand-rolled inline SVG identically.

### Focal points — one primary anchor per screen

The Figma deliverable must declare, for each screen, which element the eye lands
on first and what carries secondary weight. These are the contracts; the visual
means of achieving them is the Figma pass's work.

| Screen | Primary focal point | Secondary | Deliberately quiet |
|---|---|---|---|
| `/arguments` (term index) | The term identifier (e.g. "October Term 2019") — this is what a visitor scans for | Argument count per term | Any chrome, nav, or page furniture |
| `/arguments/term/{year}` | The case name on each row — the thing a person recognizes | Argued date, then docket number | Row affordances (chevrons, hover states) |
| `/arguments/{slug}` (transcript) | The utterance text itself. Per D-09 the reading layer is the redesign target, and reading must win over every other element on the page | Speaker identity at each turn change | Section rail, popover triggers, all navigation |

**Cross-cutting rule for the transcript screen:** the apolitical constraint
extends to visual weight, not just data. Justices and advocates must receive
identical typographic treatment, identical emphasis, and identical prominence at
a speaker change. Differentiation may encode *side* (bench vs advocate) as a
neutral factual attribute — it may never encode importance. Any Figma frame where
one speaker class reads as more prominent than another fails this contract.
