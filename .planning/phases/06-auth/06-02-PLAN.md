## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser form POST → server action | Untrusted username/password crosses here; compared constant-time, never echoed |
| server → Set-Cookie | Signed session issued only after both credentials match |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-06 | Information Disclosure | login error message | medium | mitigate | Single generic "Invalid username or password." for all failure modes — no user enumeration (D-13, Task 1) |
| T-06-07 | Spoofing | credential timing oracle | medium | mitigate | `timingSafeEqual` constant-time comparison for both username and password; length-mismatch handled before the throw (Task 1) |
| T-06-08 | Tampering | session issued on partial match | high | mitigate | Cookie set only when BOTH username AND password match; failure path returns fail() and never calls cookies.set (Task 1) |
| T-06-09 | Information Disclosure | credentials in client bundle | high | mitigate | ADMIN_USERNAME/ADMIN_PASSWORD imported only via `$env/static/private` in `.server.ts`; never referenced in `.svelte` (Task 1, Task 2) |
| T-06-10 | Repudiation | empty-credential bypass | low | mitigate | Server requires non-empty matches independent of client `required` attribute; empty input falls into the generic 401 path (Task 1) |
| T-06-SC | Tampering | npm/pip/cargo installs | low | accept | No new package installs — uses @sveltejs/kit and node:crypto already present; no supply-chain surface added |
</threat_model>
