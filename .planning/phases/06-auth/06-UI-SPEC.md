## Interaction Contract

### Login Form Submission

- Form submits via SvelteKit form action (standard `method="POST"`, no client-side fetch override). Progressive enhancement applies.
- On submit: button shows no spinner (standard browser behavior for form POST); page reloads with error or redirects.
- On invalid credentials: page re-renders with error message visible; form fields retain their values except Password (cleared by browser default for `type="password"`).
- On success: `redirect(302, '/admin')` — operator lands on admin dashboard.
- The form MUST NOT submit with empty username or password. Use `required` attribute on both inputs (browser-native validation, no custom JS needed).

### Session Cookie

- Cookie name: `scotus_admin_session`.
- Cookie flags: `HttpOnly; SameSite=Strict; Secure; Max-Age=86400; Path=/admin`.
- `SameSite=Strict` is appropriate — the admin area is never linked to from external sites; no cross-site navigation use case.
- `Secure` flag is always set (operator accesses admin over HTTPS; local dev runs without HTTPS but cookie will still be set without Secure in dev — SvelteKit dev server is localhost-exempt).
- Set in `+page.server.ts` form action via `cookies.set(...)` from `@sveltejs/kit`.

### Route Guard

- `hooks.server.ts` intercepts all `/admin/*` requests except `/admin/login` (GET and POST).
- Guard logic: parse `scotus_admin_session` cookie → verify HMAC signature → check `exp` timestamp → if any check fails, `throw redirect(302, '/admin/login')`.
- Login page (`/admin/login`) passes through unconditionally.
- Guard runs before any layout or page `load` function, protecting `+server.ts` endpoints as well as pages.

### Logout

- Logout is a `<form method="POST" action="/admin?/logout">` (SvelteKit named action on the admin layout's `+layout.server.ts`).
- Action deletes cookie via `cookies.delete('scotus_admin_session', { path: '/admin' })` then `throw redirect(302, '/admin/login')`.
- The logout button is inside a `<form>` — no JavaScript required.

### Focus Management

- On login page initial load, focus is placed on the Username input (`autofocus` attribute).
- On error state, focus remains on the submit button (browser default after form POST re-render); error message is adjacent and visible without scroll.

## Accessibility Notes

- All form inputs have associated `<label>` elements (not aria-label) with explicit `for`/`id` linking.
- Error message container uses `role="alert"` so screen readers announce it on re-render.
- Disabled nav items use `aria-disabled="true"` and `aria-label="{name} (coming soon)"` on the `<span>`.
- Logout `<form>` button has `type="submit"` explicitly.
- Color contrast ratios:
  - `#e2e8f0` on `#1e293b` = 10.2:1 (AAA, passes AA).
  - `#94a3b8` on `#1e293b` = 4.7:1 (passes AA for normal text at 14px+ only; labels are 14px — verify at final size).
  - `#ef4444` on `#1e293b` = 4.6:1 (passes AA for normal text).
  - `#93c5fd` on `#1e293b` = 7.5:1 (AAA).
