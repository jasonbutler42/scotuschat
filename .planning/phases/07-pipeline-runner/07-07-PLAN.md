<objective>
Close two UAT-major gaps in the discrepancy review table (Test 10 + Test 11):

1. **HIT-row UX (Gap 1, part a):** Auto-matched rows currently render the same Confirm + Correct buttons as MISS rows because `rowStates` ignores `auto_resolved`. Change them to start pre-dispositioned (`confirmed`) and render a single "Change" button.
2. **Empty HIT typeahead (Gap 1, part b):** When an operator clicks Change on a HIT row, the typeahead must list ALL existing people so a wrong auto-match (e.g. Ginsberg vs Ginsburg) can be corrected. Today HIT rows carry `candidates: []`, so the only datalist option is "Add new person". Fix by loading the full people list in `+page.server.ts` `load()` and merging it into `getRowCandidates()`.
3. **Save Person silent fail (Gap 2):** `handleAddPerson` uses a raw `fetch` that returns an HTML response (missing `Accept: application/json`) and parses it with `res.json()` instead of devalue, so `envelope.data.person` is always undefined and the form never dismisses. Replace the raw fetch with a `use:enhance` form that handles headers and devalue deserialization idiomatically.

Purpose: Make the discrepancy review table usable — operators can confirm auto-matches with one click, correct wrong auto-matches against the full roster, and add new people inline.
Output: Updated `[job_id]/+page.svelte` and `[job_id]/+page.server.ts`.
</objective>
