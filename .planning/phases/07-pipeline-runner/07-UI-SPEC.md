**Accent (`#93c5fd`) reserved for:**
1. Focus ring outline (already global via `app.css` `*:focus-visible` — do not override)
2. "Continue Resolve" primary action button background or border (the single highest-stakes CTA on the status page)
3. Active step spinner indicator (the currently-running step card only)
4. Nothing else — do not use accent for all interactive elements

**Status badge color map** (all use secondary surface `#1e293b` as background):

| Status | Text Color | Border Color | Icon/Glyph |
|--------|-----------|-------------|------------|
| pending | `#94a3b8` | `#334155` | `–` (em dash or bullet) |
| running | `#93c5fd` | `#93c5fd` | Spinner (CSS animation or Unicode `◌`) |
| completed | `#4ade80` (green-400) | `#4ade80` | `✓` |
| paused | `#fbbf24` (amber-400) | `#fbbf24` | `⏸` or `!` |
| failed | `#ef4444` (red-400) | `#ef4444` | `✗` |

**New color introduced — green-400:** `#4ade80` for completed state. No other green uses exist in the project. Scoped to status badges only.
**New color introduced — amber-400:** `#fbbf24` for paused state. No other amber uses exist in the project. Scoped to status badges only.

## Component Inventory

### New components (Phase 7 only — hand-authored, no library)

**StepCard**
- Container: `background-color: #1e293b; border: 1px solid #334155; border-radius: 8px; padding: 24px;`
- Layout: flex row, step number + step name on left, status badge on right
- State variants: pending (muted), running (accent border-left `3px solid #93c5fd`), completed (default border), paused (amber border-left `3px solid #fbbf24`), failed (red border-left `3px solid #ef4444`)
- Active step only: left border accent override (3px) indicates current step at a glance
- Step stack: three cards in a vertical column with `gap: 16px`

**StatusBadge**
- Inline element: `border: 1px solid {color}; border-radius: 4px; padding: 2px 8px; font-size: 14px; font-weight: 400;`
- Color per status — see Color section badge map above
- Never use filled background for badges; always use `#1e293b` surface + colored border + colored text

**ModeToggle (URL / Upload)**
- Two buttons side-by-side: "Enter URL" and "Upload File"
- Container: `background-color: #0f1117; border: 1px solid #334155; border-radius: 6px; padding: 4px; display: inline-flex;`
- Active tab: `background-color: #1e293b; border-radius: 4px; color: #e2e8f0; font-weight: 600;`
- Inactive tab: `background-color: transparent; color: #94a3b8; font-weight: 400;`
- Both tabs: `font-size: 14px; padding: 8px 16px; border: none; cursor: pointer; min-height: 36px;`
- Note: 36px is acceptable for a mode-switch control (not a primary action); primary action submit buttons still require 44px

**DiscrepancyTable**
- Container inside the paused Resolve step card, below step header
- Table: `width: 100%; border-collapse: collapse; margin-top: 16px;`
- Header row: `font-size: 14px; font-weight: 400; color: #94a3b8; border-bottom: 1px solid #334155; padding: 8px 0;`
- Data rows: `font-size: 16px; color: #e2e8f0; border-bottom: 1px solid #334155; padding: 12px 0;`
- Column 1: "Raw label" (raw_speaker_label) — 35% width
- Column 2: "Resolved as" (auto-resolved name + role, or dropdown if correcting) — 45% width
- Column 3: "Action" (Confirm / Correct buttons) — 20% width
- Row state after confirmation: Confirm button replaced by `✓ Confirmed` text in `#4ade80`
- Row state after correction: dropdown collapsed, selected person shown, button replaced by `✓ Corrected` in `#4ade80`

**ActionButtons within DiscrepancyTable**
- Confirm button: `font-size: 14px; font-weight: 400; color: #e2e8f0; background: transparent; border: 1px solid #334155; border-radius: 4px; padding: 6px 12px; cursor: pointer; min-height: 32px;`
- Correct button: same styling as Confirm; clicking it replaces the resolved-name cell with the searchable dropdown
- Note: 32px acceptable for table row action buttons; these are not the primary CTA

**PersonSearchDropdown** (appears when "Correct" clicked)
- Replaces the resolved-name cell inline (not a modal — per Claude's Discretion)
- `<select>` or custom `<datalist>` input: `background-color: #0f1117; border: 1px solid #93c5fd; border-radius: 6px; padding: 6px 10px; font-size: 16px; color: #e2e8f0; width: 100%;`
- Accent border (`#93c5fd`) on the active dropdown input only — not on the Confirm cells
- Includes "— Add new person —" as the last `<option>`

**AddNewPersonForm** (appears inline below dropdown when "Add new person" selected)
- Two fields only: Full Name (text input) + Role (text input or short select)
- Same input styling as login page: `background-color: #0f1117; border: 1px solid #334155; border-radius: 6px; padding: 8px 12px; font-size: 16px; color: #e2e8f0;`
- "Save person" button: `font-size: 14px; font-weight: 600; color: #e2e8f0; background: transparent; border: 1px solid #93c5fd; border-radius: 6px; padding: 8px 16px; min-height: 36px;`
- On save: form collapses, new person appears selected in the dropdown

**HistoryTable** (on `/admin/pipeline` below the start form)
- Simple table: status badge | step | created date | link
- `margin-top: 32px;` below start form
- Column headers: 14px/400/`#94a3b8`
- Rows: 16px/400/`#e2e8f0` for status and step; 14px/400/`#94a3b8` for date; link in `#93c5fd` underline

## Interaction States

### Start Form

| State | Trigger | UI Response |
|-------|---------|------------|
| Default | Page load | URL tab active; URL input visible; Upload input hidden |
| Mode switch | Click "Upload File" tab | Upload tab becomes active (bg `#1e293b`); file input replaces URL input; no page reload |
| Submitting | Form POST in flight | Start Run button text becomes "Starting…"; button `disabled` attribute set |
| Success | FastAPI returns job_id | SvelteKit redirect 303 to `/admin/pipeline/{job_id}` — no JS required |
| Form error | FastAPI 4xx or SvelteKit validation | Inline error paragraph below input, above button; `role="alert"` |

### Status Page

| State | Trigger | UI Response |
|-------|---------|------------|
| Initial load (running) | Page load, job active | Step cards render with current status; `$effect` starts 2.5s poll |
| Polling tick | 2.5s interval | `invalidateAll()` re-runs `+page.server.ts` load; step cards update from new `page.data` |
| Step advances | Ingest completes → Parse starts | Ingest card badge changes to "Completed"; Parse card badge changes to "Running" + accent left border |
| Resolve pauses | `status = paused` | Poll stops; Resolve card expands to show DiscrepancyTable; "Continue Resolve" button not yet visible |
| Row confirmed | Click "Confirm" | Button replaced by "✓ Confirmed" (`#4ade80`); row frozen |
| Row corrected | Click "Correct" → select person | Dropdown collapses; button replaced by "✓ Corrected" (`#4ade80`); row frozen |
| All rows dispositioned | Last row confirmed/corrected | "Continue Resolve" button appears below step cards |
| Continue Resolve submitted | Click "Continue Resolve" | Button text becomes "Submitting…"; button disabled; POST to FastAPI |
| Job completes | `status = completed` | All step cards show "Completed" badge; poll stops; no further UI action needed |
| Job fails | `status = failed` | Failed step card shows red badge + error panel with `error_message`; poll stops |
| Resume after browser close | Operator reopens `/admin/pipeline/{job_id}` | SSR load fetches current `admin_jobs` row; page renders correct state; poll starts if status is not terminal |

## Accessibility Contract

All constraints carried forward from Phase 4 (WCAG 2.1 AA) and Phase 6 (admin UI baseline).

| Requirement | Implementation |
|-------------|---------------|
| Touch targets | All primary buttons: `min-height: 44px` (WCAG 2.5.5) |
| Focus ring | Global `*:focus-visible` rule in `app.css` — `outline: 2px solid #93c5fd; outline-offset: 3px` — do not override |
| Live region for step status | Step card container: `aria-live="polite"` so screen readers announce step changes as polling updates |
| Error announcement | Error paragraphs and form errors: `role="alert"` (already established in Phase 6 login) |
| Disabled controls | Buttons in "Submitting" state: `disabled` attribute set (not just `opacity: 0.5`); do not disable with only visual cues |
| Mode toggle semantics | ModeToggle uses `<button type="button">` elements, not `<a>` tags; active tab gets `aria-pressed="true"` |
| Discrepancy table | `<table>` with `<thead>`, `<tbody>`, `<th scope="col">` for column headers |
| Spinners | CSS animation or Unicode glyph must include `aria-label="Running"` on the badge element; do not rely on animation alone |
