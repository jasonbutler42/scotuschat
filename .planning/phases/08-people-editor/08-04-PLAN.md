From Plan 08-02 (Wave 2, must be complete):
- `GET /api/admin/people/{id}` returns PersonDetail: `{id, full_name, role_id, role_name, bio_text, photo_url, tenures: [{seat, start_date, end_date}]}` — dates are ISO strings ("YYYY-MM-DD") or null.
- `GET /api/admin/people` returns `list[PersonListItem]` (used here only if a roles list is not separately available — but roles come from a dedicated source; see below).
- `PATCH /api/admin/people/{id}` accepts JSON `{full_name, role_id, bio_text, photo_url, tenures: [{seat, start_date, end_date}]}` and returns PersonDetail. Omitting `tenures` means "leave unchanged"; sending `[]` deletes all. This form ALWAYS sends the full tenures array (full edit form, Pattern 4).
- `POST /api/admin/roles` accepts `{name}` and returns `{id, name}` (find-or-create; 201).
- There is no dedicated GET /api/admin/roles endpoint. Obtain the role list by deriving distinct roles from the PersonListItem set is NOT acceptable. Instead: the load function fetches the roles via `GET /api/admin/people` is also NOT the source. Roles for the dropdown must be loaded — see Task 1 action for the exact source decision.

Established SvelteKit patterns (verified in `app/src/routes/admin/pipeline/[job_id]/+page.server.ts`):
- `$env/static/private` for ADMIN_TOKEN, FASTAPI_BASE_URL; server-side fetch only.
- Named actions: `export const actions: Actions = { save: async (...) => {...}, createRole: async (...) => {...} }`.
- `fail(status, {...})` for validation/error returns; `throw redirect(303, ...)` for success (re-runs load — no stale data).
- `use:enhance` on forms (RESEARCH Pattern 3; STATE [07-06]/[07-07] notes).
- Browser cannot call FastAPI directly — role creation MUST proxy through a SvelteKit named action (RESEARCH Pattern 3 critical constraint).
- Svelte 5 Runes: `$state<T[]>` array push/splice for tenure rows (RESEARCH Pattern 1, Pitfall 2 — use a stable key in the keyed each block).
</interface_context>
