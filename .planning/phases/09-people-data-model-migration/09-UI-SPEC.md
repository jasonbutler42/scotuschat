## Component Inventory

### Modified component (Phase 9 extension of Phase 8 PersonEditForm)

**PersonEditForm — extended** (`/admin/people/[id]`)

Phase 8 established three sections. Phase 9 adds inputs to Section 1 and adds a fourth section. The form container, card styles, heading styles, and Save button are unchanged.

**Section 1 — Basic Info (extended):**

```
Row 1: full_name — full-width text input (unchanged from Phase 8)
Row 2: name-parts grid
  [first_name] [middle_name] [last_name] [name_suffix]
Row 3: role <select> + AddRoleInlineForm (unchanged from Phase 8)
```

Name-parts grid layout:
- Container: `display: grid; grid-template-columns: 1fr 1fr 1fr 80px; gap: 16px; margin-bottom: 16px;`
- Responsive breakpoint at 640px: `grid-template-columns: 1fr 1fr;` — suffix wraps to the second row alongside last_name
- Each cell contains a `<label>` + `<input>` using the FormInput pattern from Phase 8
- All four inputs: `type="text"`, same FormInput styling (`background-color: #0f1117; border: 1px solid #334155; border-radius: 6px; padding: 8px 12px; font-size: 16px; color: #e2e8f0;`)
- `name_suffix` input: no `<select>` dropdown — free text input; the 80px column width on desktop signals it is a short field (Jr., Sr., II, etc.)

**Section 4 — Appointment (new, 4th section):**


## Interaction States

### `/admin/people/[id]` — Edit Form (Phase 9 additions only)

| State | Trigger | UI Response |
|-------|---------|------------|
| Default load — has name parts | Page load, person has first_name/last_name | Name-parts grid pre-filled with stored values |
| Default load — no name parts | Page load, person has only full_name | Name-parts inputs render empty; full_name input pre-filled as before |
| Default load — has appointment data | Page load, person has appointing_president | "Appointed by" input pre-filled; party dropdown pre-selected |
| Default load — no appointment data | Page load, advocate record | Appointment section renders with empty input and blank "— No party —" dropdown |
| Save changes | Submit main form | All six new fields included in PATCH payload; server derives full_name from parts if first_name is non-empty (D-04/D-05); page reloads with updated data on success |
| Save — first_name non-empty | Server-side derivation on save | `full_name` updated to derived value; form reloads with derived full_name in the full_name input |
| Save — first_name empty | Server-side behavior | `full_name` not overwritten; remains unchanged (D-05) |
| Save error | FastAPI 4xx | `role="alert"` error paragraph above Save button; button re-enabled |

All other interaction states (toggle, breadcrumb, tenure add/delete, role add) are unchanged from Phase 8.

## Accessibility Contract

Carried forward from Phase 8 with additions for new form fields.

| Requirement | Implementation |
|-------------|---------------|
