## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (MobileNavBar button padding: 6px 14px) |
| md | 16px | Nav horizontal item gap (`gap: 16px` in both existing navs); button padding left/right |
| lg | 24px | Nav bar horizontal padding (`padding: 12px 24px` in both existing navs) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Nav bar vertical padding: 12px (between sm=8 and md=16 — matches existing nav exactly; do not change)
- Logout button min-height: 44px (WCAG 2.5.5 touch target minimum — carry from admin layout)
- Logout button padding: 8px 16px (vertical sm, horizontal md)

Source: Measured from `+layout.svelte` (both root and admin) and `MobileNavBar.svelte`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Nav wordmark | 14px | 600 (semibold) | 1.2 (single-line label) |
| Nav link | 14px | 400 (regular) | 1.2 (single-line label) |
| Button label (logout) | 14px | 400 (regular) | 1.2 (single-line label) |
| Nav label (small variant, if needed) | 13px | 400 (regular) | 1.2 |

Design decision (Claude's discretion from CONTEXT.md): **Use 14px for all nav links.** The public nav currently uses 13px for the "Cases" link while the admin nav uses 14px for all links. Phase 10 standardizes on 14px across both variants — consistent with the admin nav, which has more links and uses 14px throughout.

Wordmark letter-spacing: 0.05em (carry from both existing navs).

Source: `+layout.svelte` (root: `font-size: 13px` on Cases link), `admin/+layout.svelte` (all links at `font-size: 14px`). Standardized to 14px per Claude's discretion.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0f1117` | Page background; also `public` variant nav background (`--color-bg`) |
| Secondary (30%) | `#1e293b` | `admin` variant nav background; cards, surfaces (`--color-surface`) |
| Accent (10%) | `#93c5fd` | Focus ring on interactive nav elements; "Cases" link in public nav (existing token `--color-text-advocate`) |
| Muted text | `#94a3b8` | Wordmark, nav links (default/rest state), logout button (rest state) (`--color-text-secondary`) |
| Active/hover text | `#e2e8f0` | Logout button hover state color (`--color-text-primary`) |
| Border | `#334155` | Nav bottom border; logout button border (rest state) (`--color-border`) |
| Destructive | not applicable | No destructive actions in this phase |

Accent (`#93c5fd`) reserved for:
1. Focus rings on all interactive nav elements (`:focus-visible` — global rule in `app.css`)
2. "Cases" link text in the public nav variant (existing pattern carried forward)
3. Active border on MobileNavBar section pills (existing pattern — unchanged by this phase)

Accent is NOT used for: wordmark, admin nav links, logout button, admin nav borders.

Background is variant-driven (Decision D-08):
- `variant="public"` → `background-color: #0f1117`
- `variant="admin"` → `background-color: #1e293b`

Both variants share: `border-bottom: 1px solid #334155`

Source: `app/src/app.css` CSS custom properties; both layout files; CONTEXT.md D-08.

## Component Inventory

### TopNav.svelte (new)

**File location:** `app/src/lib/components/TopNav.svelte`

**Props:**
```ts
let { variant }: { variant: 'public' | 'admin' } = $props();
```

**Structure:**

```
<header>
  <nav aria-label="...">               <!-- "Site navigation" | "Admin navigation" -->
    <span>SCOTUS CHAT</span>            <!-- wordmark — public: plain span; admin: plain span -->
    <!-- public variant -->
    <a href="/cases">Cases</a>          <!-- accent color #93c5fd -->
    <a href="/admin" style="margin-left:auto">Admin</a>  <!-- muted #94a3b8 -->
    <!-- admin variant -->
    <a href="/admin/pipeline">Pipeline Runner</a>
    <a href="/admin/people">People Editor</a>
    <form method="POST" action="/admin?/logout" style="margin-left:auto">
      <button type="submit">Log out</button>
    </form>
  </nav>
</header>
```

**Conditional rendering guard:** Login page suppression stays in `admin/+layout.svelte` — TopNav does not read `$page` or any URL state.

**Variant-driven background derivation (inside component):**
```ts
const bgColor = variant === 'admin' ? '#1e293b' : '#0f1117';
```

### Wordmark link behavior (Claude's discretion from CONTEXT.md)

The "SCOTUS CHAT" wordmark in the public nav is a **plain `<span>`** (not a link) — matching current behavior. Reason: the argument chat pages are the primary content; adding a home link creates a navigation path users do not need on this read-only site.

### Active-link styling (Claude's discretion from CONTEXT.md)

No active-link styling is added. Both current navs have none; adding it is deferred per CONTEXT.md. TopNav remains stateless with respect to the current URL — no `$page` reads, no `aria-current` on links.

## Interaction Contract

### Logout button hover

```
rest:  color #94a3b8, border-color #334155
hover: color #e2e8f0, border-color #e2e8f0
```

Implementation: inline `onmouseenter`/`onmouseleave` handlers mutating `style` directly — carry exactly from current `admin/+layout.svelte` (Decision D-06).

### Focus ring (all interactive elements)

All `<a>` and `<button>` elements in TopNav inherit the global `:focus-visible` rule from `app.css`:
```css
outline: 2px solid #93c5fd;
outline-offset: 3px;
border-radius: 4px;
```

No component-level focus style override needed.

### Keyboard navigation

Tab order (public variant): Cases link → Admin link
Tab order (admin variant): Pipeline Runner link → People Editor link → Log out button

All interactive elements are natively focusable (`<a href>`, `<button type="submit">`). No `tabindex` manipulation needed.

## Layout Contract

Nav bar layout: `display: flex; align-items: center; gap: 16px; padding: 12px 24px`

Right-alignment: rightmost element in each variant uses `margin-left: auto`:
- Public: "Admin" link
- Admin: logout `<form>` wrapper

`<header>` wraps `<nav>` in both cases — matches existing markup and provides landmark for assistive technology.
