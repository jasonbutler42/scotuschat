## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Badge internal padding (vertical), minor gap adjustments |
| sm | 8px | Label-to-input gap, field-to-field gap within a row, button internal padding (vertical), badge internal padding (horizontal) |
| md | 16px | Field margin-bottom, nav gap between links, header padding (vertical), section internal row spacing |
| lg | 24px | Section padding, header padding (horizontal), page content padding (horizontal) |
| xl | 32px | Card internal padding (used in some cards), gap between major layout sections |
| 2xl | 48px | Page content padding-top (main content area top padding) |
| 3xl | 64px | Not used in admin pages — reserved for public pages only |

Exceptions:
- Touch-target minimum height: 44px on all interactive elements (buttons, "Log out") — WCAG 2.5.5
- Max-width containers: 860px for the pipeline runner list page, 640px for single-record edit forms; new argument edit page uses 640px; argument list page uses 860px

Source: Measured from existing pipeline and people editor admin pages.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / input value | 16px | 400 | 1.5 |
| Label / meta text / badge | 14px | 400 | 1.5 |
| Section heading (h2) | 20px | 600 | 1.2 |

Notes:
- h1 and h2 share the same size/weight (20px 600) — this is the established admin pattern; page identity is established by placement and context, not font size escalation.
- No 28px+ display size exists in admin pages. Admin UI is data-dense; headings are structural, not decorative.
- All typography values sourced from existing admin Svelte pages (`+page.svelte`, `[id]/+page.svelte`, pipeline pages).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0f1117` | Page background (`<main>`), input/select/textarea fill, code-like inner backgrounds |
| Secondary (30%) | `#1e293b` | Card backgrounds, header/nav bar background, modal-like sections, toggle pill fill |
| Border / divider | `#334155` | All borders (card, input, button, table row separator), nav bottom border |
| Body text | `#e2e8f0` | Primary text: headings, input values, button labels |
| Muted text | `#94a3b8` | Labels, table column headers, nav links (inactive), metadata, secondary copy |
| Accent (10%) | `#93c5fd` | Reserved-for list below |
| Destructive | `#ef4444` | Error message text, destructive icon buttons (remove/trash), validation errors |

Accent (`#93c5fd`) reserved for:
1. Primary save/submit button border (e.g. "Save changes", "Publish" CTA)
2. Hyperlinks within the public nav ("Cases" link in public variant of TopNav)
3. "View" links in the pipeline history table
4. Status badge color for "running" pipeline jobs
5. "Ready to publish" CTA section highlight border/text accent on the job detail page

Status badge colors (additional semantic palette — read-only display only):
- Pending: `#94a3b8` (muted — matches body text/muted)
- Running: `#93c5fd` (accent blue)
- Completed / Published: `#4ade80` (green)
- Needs review / Paused: `#fbbf24` (amber)
- Failed: `#ef4444` (destructive red)
- Resolved (new for Phase 11 — argument has resolved_at but not published_at): `#a78bfa` (violet — distinct from Completed/Published; communicates "pipeline done, awaiting publish decision")

Source: Extracted from `pipeline/+page.svelte` `badgeStyle()` function; Resolved badge color is at Claude's discretion per 11-CONTEXT.md.

## Interaction Contract

### Arguments List — Publish Toggle

- Publish toggle is a `<form method="POST" action="?/publish">` or `?/unpublish` per row (same `use:enhance` pattern as all admin forms)
- No JavaScript confirmation dialog for publish/unpublish — these are reversible, low-risk actions
- After action completes, page reloads via `invalidateAll()` or SvelteKit default form redirect to reflect updated badge

### Argument Edit — Save

- `<form method="POST" action="?/save" use:enhance>` — identical pattern to people editor
- Save button shows "Saving…" while submitting; `disabled` attribute set (not just opacity)
- On success: page reloads showing updated values
- On slug collision (D-11): server returns 422-equivalent form failure; display: `"This title generates a URL slug that conflicts with an existing case."` in the form error slot (role="alert")

### Argument Edit — Publish / Unpublish

- Publish button only rendered when `resolved_at IS NOT NULL AND published_at IS NULL`
- Unpublish button only rendered when `published_at IS NOT NULL`
- Both are separate named form actions (`?/publish`, `?/unpublish`) — not the same action as save
- Both use `use:enhance` with submitting state (button shows "Publishing…" / "Unpublishing…")
- No confirmation modal — these are intentional operator actions with a clear recovery path (unpublish is always available)

### Consolidated Dockets (D-10)

- Non-lead dockets rendered as a read-only `<ul>` below the editable fields inside the "Argument Details" card
- Labeled: "Consolidated dockets" (14px 400 #94a3b8)
- Only shown when `cases.length > 1`; hidden entirely when argument has only one case

## Date Format Contract

All argued dates and timestamps displayed using:

```js
new Date(iso).toLocaleDateString('en-US', {
  year: 'numeric',
  month: 'short',
  day: 'numeric',
})
// → "Oct 6, 2014"
```

Source: Established in `pipeline/+page.svelte` `formatDate()` function. Phase 11 reuses the same function or an identical copy.

Docket number input: plain `<input type="text">` — not a date input. Docket numbers follow formats like "14-556" and must accept free text.

Argued date input: `<input type="date">` — stores as ISO date string; displayed formatted in list/preview.

## Accessibility Contract

- All `<input>`, `<select>`, `<textarea>` elements have a corresponding `<label for="...">` with matching `id`
- Form-level errors use `role="alert"` so screen readers announce immediately
- Publish/unpublish buttons carry descriptive text that reflects current state (not "Toggle")
- All buttons: `min-height: 44px` (WCAG 2.5.5 touch target)
- `<table>` uses `<th scope="col">` for all column headers (WCAG 1.3.1)
- Back-navigation link renders as `<a>` not `<button>` (href navigates)
- "Edit argument metadata" link renders as `<a>` not `<button>`
