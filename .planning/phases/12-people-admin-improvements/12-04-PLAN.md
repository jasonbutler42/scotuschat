<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → photo form | file/URL input submitted as multipart to the ?/photo action |
| operator → merge/delete forms | target_id and delete intent submitted to ?/merge / ?/delete |
| client JS → merge-preview proxy | count fetch over same-origin relative URL (token injected server-side) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Severity | Mitigation Plan |
|-----------|----------|-----------|-------------|----------|-----------------|
| T-12-CLIENTGATE | Tampering | delete button disabled state | mitigate | medium | client `disabled` on `!can_delete` is defense-in-depth only; the DELETE endpoint (Plan 02) re-checks orphan status server-side and returns 409 — bypassing the disabled button cannot delete a non-orphan (D-06) |
| T-12-SELFPICK | Tampering | merge target picker | mitigate | medium | picker is bound to `data.people` which load already filtered to exclude the current person; the merge endpoint additionally rejects self-merge with 422 (authoritative) |
| T-12-XSS-PHOTO | Cross-Site Scripting | photo preview img src | mitigate | low | photo_url_full is rendered only in an `<img src>` attribute (Svelte auto-escapes attribute values); URL value in src is not executable; server-side Pillow validates uploaded bytes |
| T-12-TOKENLEAK | Information Disclosure | client merge-preview fetch | mitigate | high | client fetches the same-origin relative `/admin/people/[id]/merge-preview` proxy; ADMIN_TOKEN never appears in client code or network response (Plan 03 proxy injects it server-side) |
| T-12-COUNTFIDELITY | Tampering | merge count display | mitigate | medium | counts rendered as exact integers from the API with no rounding/paraphrasing — these are audit-relevant transfer counts the operator relies on before an irreversible merge |
</threat_model>
