## Component Inventory

New UI elements introduced by Phase 12 on `/admin/people/[id]`:

### Photo Widget (replaces standalone photo_url input — PADM-01)

Located inside the existing "Bio & Photo" card section.

Structure:
1. **Photo preview** — if `photo_url` is set: `<img>` element, 80px × 80px, `border-radius: 50%`, `object-fit: cover`, `border: 1px solid #334155`. If no photo: a styled initial-letter circle, 80px × 80px, `background-color: #334155`, `color: #94a3b8`, `font-size: 28px`, `font-weight: 600`, centered initials (first letter of `full_name`).
2. **Tab bar** — two tab buttons side by side: "Upload file" | "Enter URL". Active tab: `border-bottom: 2px solid #93c5fd; color: #e2e8f0`. Inactive: `border-bottom: 2px solid transparent; color: #94a3b8`. Tab buttons are `type="button"` (do not submit the form). Tabs are Svelte `$state`-driven — no page reload.
3. **Upload file tab panel** — `<input type="file" accept="image/*" name="photo_file">`. Full width. `min-height: 44px`.
4. **Enter URL tab panel** — `<input type="text" name="photo_url" placeholder="https://…">`. Full width. Matches existing input style: `background-color: #0f1117; border: 1px solid #334155; border-radius: 6px; padding: 8px 12px; font-size: 16px; color: #e2e8f0`.

The photo widget is part of the main `save` form action. Photo submission uses a separate `photo` named action with `enctype="multipart/form-data"` on a nested form (or the main form gains `enctype="multipart/form-data"`). Use a dedicated `photo` form action to avoid breaking the existing `save` action which does not handle file uploads.

### Merge Section (PADM-03, PADM-04)

A new card section appended after the "Appointment" section, before the Delete section.

Card header: "Merge into another person" — `font-size: 20px; font-weight: 600; color: #e2e8f0`.

Structure:
1. **Target picker** — a `<select>` listing all people records except the current person (fetched server-side in the load function). Sorted `last_name NULLS LAST`. Label: "Merge this person into". Option format: `{full_name}` (or `{last_name}, {first_name}` if structured names are set). Blank first option: `"— Select a person —"`. Matches existing select style: `background-color: #0f1117; border: 1px solid #334155; border-radius: 6px; padding: 8px 12px; font-size: 16px; color: #e2e8f0`.
2. **Merge preview panel** — shown only after a target is selected and the count fetch completes. Triggered immediately on `onchange` of the select (no separate "Check counts" button — counts fetched eagerly per CONTEXT.md specifics). Display: a `<div>` with `background-color: #0f1117; border: 1px solid #334155; border-radius: 6px; padding: 16px`. Content:
   - Heading (14px, `#94a3b8`): "This will transfer from **[source full_name]** to **[target full_name]**:"
   - Count list (14px, `#e2e8f0`): "N utterances · N aliases · N appearances · N argument participants"
   - If all counts are 0: "No records to transfer. This person has no associated data." (same styling, `#94a3b8`)
3. **Confirm Merge button** — shown only when a target is selected and counts are loaded. Full-width, `min-height: 44px`, `border: 1px solid #93c5fd`, `border-radius: 6px`, `font-size: 16px; font-weight: 600; color: #e2e8f0; background: transparent`. Label: "Merge [source name] into [target name]" — dynamic, uses actual names. Submits `merge` named form action.
4. **Merge submitting state** — button label changes to "Merging…", `opacity: 0.7`, `cursor: not-allowed`.

The merge section uses a dedicated `<form method="POST" action="?/merge" use:enhance>` nested inside the main page.

### Delete Section (PADM-02)

A new card section appended at the bottom of `/admin/people/[id]`, after the Merge section.

Card: `background-color: #1e293b; border: 1px solid #334155; border-radius: 8px; padding: 24px`. No section heading — the delete action is self-describing.

Structure:
- **Delete button** — full-width, `min-height: 44px`, `border-radius: 6px`, `font-size: 16px; font-weight: 600`.
  - When orphaned (0 FK rows): enabled. `border: 1px solid #ef4444; color: #ef4444; background: transparent; cursor: pointer`. Label: "Delete person".
  - When not orphaned (has FK rows): disabled. `border: 1px solid #334155; color: #94a3b8; background: transparent; cursor: not-allowed; opacity: 0.7`. Label: "Delete person".
- **Disabled tooltip** — when the button is disabled, a `<p>` element below the button (not a native tooltip): `font-size: 14px; color: #94a3b8; margin-top: 8px; text-align: center`. Copy: "Cannot delete — this person has N utterance(s) or appearance(s)." (See Copywriting Contract for exact wording.)
- **Confirmation approach** — no modal. The delete button submits a `delete` named form action directly. Server-side orphan check enforces safety; the disabled button is the UI guard. No intermediate confirmation dialog (the delete can only succeed for orphaned records, which have no data loss risk).

The delete section uses a dedicated `<form method="POST" action="?/delete" use:enhance>` nested inside the main page.

## Interaction States

### Photo Upload Tab

| State | Visual |
|-------|--------|
| Upload file tab active | Tab label `#e2e8f0`, bottom border `2px solid #93c5fd` |
| Enter URL tab active | Tab label `#e2e8f0`, bottom border `2px solid #93c5fd` |
| Inactive tab | Tab label `#94a3b8`, bottom border `2px solid transparent` |
| File input idle | Standard file input, full width, `min-height: 44px` |
| Upload submitting | "Saving photo…" on the photo save button, `opacity: 0.7` |
| Upload success | Photo preview refreshes to new image; no full-page reload (enhance handles) |
| Upload error | `<p role="alert">` below the widget, `color: #ef4444; font-size: 14px` |
| Invalid file type | Server returns 422; display: "The uploaded file is not a valid image." |

### Merge Section

| State | Visual |
|-------|--------|
| No target selected | Preview panel hidden; Confirm button hidden |
| Fetching counts (after target selected) | Preview panel shows "Loading…" in `#94a3b8` at 14px |
| Counts loaded | Preview panel shows transfer summary; Confirm button appears |
| Fetch error | Preview panel shows "Could not load counts. Try again." (`#ef4444`, 14px) |
| Merge submitting | Confirm button label: "Merging…", `opacity: 0.7`, disabled |
| Merge success | Redirect to `/admin/people/[target_id]` — server-side redirect via enhance |
| Merge error | `<p role="alert">` below Confirm button, `color: #ef4444; font-size: 14px` |

### Delete Section

| State | Visual |
|-------|--------|
| Person is orphaned | Button enabled, `border: 1px solid #ef4444; color: #ef4444` |
| Person has FK rows | Button disabled, `opacity: 0.7; color: #94a3b8; border-color: #334155`; tooltip paragraph shown below |
| Delete submitting | Button label: "Deleting…", `opacity: 0.7` |
| Delete success | Redirect to `/admin/people` |
| Delete rejected (409) | `<p role="alert">` "This person cannot be deleted — they have associated records." (`#ef4444`, 14px) |

## Layout

Page: `/admin/people/[id]`

```
<header>  background #1e293b, border-bottom #334155, padding 16px 24px
  ← People  (14px, #94a3b8, back link)
  {full_name}  (20px, semibold, #e2e8f0)

<main>  background #0f1117, min-height 100vh
  <div>  max-width 640px, margin 0 auto, padding 48px 24px

    [Section 1: Basic Info]         card — existing, unchanged
    [Section 2: Bio & Photo]        card — photo_url input replaced by photo widget
    [Section 3: Court Tenure]       card — existing, unchanged
    [Section 4: Appointment]        card — existing, unchanged

    <Save Changes button>           full-width, accent border — existing

    [Section 5: Merge]              card — new, accent-bordered Confirm button
    [Section 6: Delete]             card — new, destructive-bordered Delete button
```

Section order rationale: Save changes (main form) comes first — it is the most common action. Merge and Delete are destructive/irreversible and are visually separated at the bottom, below the primary save button.

The Merge and Delete sections each have their own `<form>` elements with named actions. They are outside the main save `<form>` to avoid accidental co-submission.

## Accessibility Notes

- All interactive elements carry `aria-label` or associated `<label>` elements.
- Photo preview `<img>` carries `alt="{full_name} profile photo"`.
- Photo placeholder circle carries `aria-hidden="true"` (decorative).
- Merge Confirm button disabled until target selected + counts loaded — `aria-disabled="true"` while in loading state.
- Delete button when disabled: `disabled` attribute set; tooltip paragraph uses `id` and `aria-describedby` on the button.
- All error paragraphs carry `role="alert"`.
- Focus ring: `outline: 2px solid #93c5fd; outline-offset: 3px; border-radius: 4px` (inherited from `app.css` global).
- Merge section and Delete section each have a visible heading or label identifying the action zone — no unlabeled action clusters.
