## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding (2px 4px → rounded to 4px token), inline text gap |
| sm | 8px | Label-to-input margin, list item padding, button padding (6px 12px uses 8px base) |
| md | 16px | Default element spacing, field margin-bottom, card inner padding rows |
| lg | 24px | Card padding, section margin-bottom, CTA margin-top |
| xl | 32px | Section breaks between cards (margin-top 32px) |
| 2xl | 48px | Page content padding-top (padding: 48px 24px) |
| 3xl | 64px | Not used at this scale — reserved |

Exceptions:
- Status badge padding is `2px 8px` (intentional — matches all existing badges; do not change to 4px).
- Touch-target minimum for primary action buttons: 44px min-height (WCAG 2.5.5 — already established in all admin CTAs).
- Inline warning banner uses `12px` vertical padding (between sm and md) — match existing inline alert patterns in pipeline job detail.

Source: inline styles throughout `app/src/routes/admin/pipeline/[job_id]/+page.svelte` and `app/src/routes/admin/arguments/[id]/+page.svelte`.

## Interaction Contracts

### Approve Action (pipeline job detail)

1. "Create Argument" button is always visible when `argument.status === 'pipeline'`, regardless of whether any discrepancies remain.
2. Clicking submits `?/approve` form action via `use:enhance`.
3. On success: page reloads; job shows read-only state; "Re-run with same source" button appears; "Create Argument" button is gone.
4. On failure: `role="alert"` error message at 14px, color `#ef4444`, below the button.

### Re-run Action (pipeline job detail — post-approval read-only state)

1. Button shows "Re-run with same source" at 14px weight 400, muted border.
2. First click: button label changes to "Confirm re-run — this starts a new pipeline run"; "Cancel" link appears inline to the right.
3. Second click (confirm): submits `?/rerun` form action; new pipeline job starts; user is redirected to the new job's detail page.
4. Cancel click: resets back to "Re-run with same source" state.
5. No modal. Inline two-step pattern identical to conceptual pattern used for dangerous inline actions throughout this admin.

### Advocate Role Dropdown (both locations)

1. Dropdown is always editable while the argument is in `draft` or `published` state.
2. On the pipeline job detail page: dropdown is only editable while `argument.status === 'pipeline'`. Post-approval: show role label as read-only text (same `#94a3b8` secondary color), no dropdown.
3. Change is saved immediately on `change` event (no separate save button) via a PATCH to `argument_participants.side` — or grouped with the form save on the argument edit page per the existing save-button pattern.
4. On the argument edit page: the "Advocate Roles" section uses a Save button consistent with the existing "Save changes" CTA pattern — not auto-save on change.

### Tenure Gap Warning (argument edit page)

1. Shown for each bench speaker where `argued_date` is outside all their tenure rows.
2. Rendered below the argument metadata fields, above the publish/unpublish buttons.
3. Visible for both `draft` and `published` arguments.
4. "Edit person" link navigates to `/admin/people/{person_id}`.

### People Directory Tenure Gaps Filter

1. Toggle follows exact pattern of existing "Show incomplete only" toggle.
2. URL param: `?tenure_gaps=1`.
3. When active: table shows only people where at least one argument's `argued_date` is not covered by any of their `CourtTenure` rows.
4. Empty state when filter active and no results: "No Justices with tenure gaps found." (14px, `#94a3b8`).

## Accessibility Contract

| Requirement | Implementation |
