<objective>
Add advocate side detection (PARSE-02) to the parse step. Extend
`pipeline/parser/cover_extractor.py` with `extract_advocate_sides(pdf_path)` that
scans the TOC page (the page containing `C O N T E N T S`) for `ESQ.` name lines
paired with `On behalf of ...` / `amicus curiae` lines, builds a
`{last_name_upper: SideEnum_value}` map, and updates matching
`argument_participants.side` rows from `UNKNOWN` to the detected side.

Purpose: Each advocate arrives with an initial per-argument role so the operator
corrects edge cases via the Phase 15 advocate role dropdown rather than assigning
every side from scratch. Closes PARSE-02.

Output:
- `pipeline/parser/cover_extractor.py` (extended) — `extract_advocate_sides`, `_toc_last_name`, TOC regex constants
- `pipeline/commands/parse.py` (modified) — `extract_advocate_sides` call before the session; `_update_participant_sides` + `_normalize_label_last_name`; UPDATE call after step 7b
- `pipeline/tests/test_cover_extractor.py` (extended) — unit tests for TOC parsing and last-name matching
</objective>
