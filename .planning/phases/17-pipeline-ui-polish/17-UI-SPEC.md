## Component Inventory

New UI elements Phase 17 adds to `+page.svelte`. No new Svelte components are created — all additions are inline in the existing page file, matching the established inline-style pattern.

### 1. Source Identifier Row (Ingest Stage Card)

Added inside the Ingest stage card `<div>`, below the status badge row. Only shown when `data.job.original_filename` or `data.job.pdf_url` is non-null.

```
Label:   "Source file"                    → 14px/400, #94a3b8, display:block, margin-bottom:4px
Value:   <filename> or <url>              → 16px/400, #e2e8f0
```

- For upload-mode jobs: display `data.job.original_filename` (e.g. `transcript.pdf`)
- For URL-mode jobs: display `data.job.pdf_url` verbatim (full URL string)
- When neither is set (pre-migration rows): row is hidden entirely (`{#if}` gate)
- Long URLs: allow natural line-wrap; do not truncate — operator needs the full URL for verification
- Margin above this row: `margin-top: 12px` to separate from the status badge row

### 2. Parse Stat Rows (Parse Stage Card)

Added inside the Parse stage card `<div>`, below the status badge row. Only shown when the parse step status is `completed` (D-10 from CONTEXT.md).

Three stat rows, each following the label-above-value pattern:

```
Label: "Utterances"          → 14px/400, #94a3b8, display:block, margin-bottom:4px
Value: <count>               → 16px/400, #e2e8f0

Label: "Distinct speakers"   → 14px/400, #94a3b8, display:block, margin-bottom:4px
Value: <count>               → 16px/400, #e2e8f0

Label: "Case name"           → 14px/400, #94a3b8, display:block, margin-bottom:4px
Value: <case_name or "—">    → 16px/400, #e2e8f0

Label: "Argued"              → 14px/400, #94a3b8, display:block, margin-bottom:4px
Value: <formatted date or "—"> → 16px/400, #e2e8f0
```

- Row spacing: `margin-bottom: 12px` between rows (matches argument preview card pattern)
- When parse step is pending/running/failed: stat rows are entirely absent — no placeholder, no loading skeleton
- Wrapper: `margin-top: 12px` below the status badge, wrapping `<div>` with `display: flex; flex-direction: column;`
- Date format: `toLocaleDateString('en-US', { year: 'numeric', month: 'short', day: 'numeric' })` — matches existing `formatArgDate` function

### 3. Source PDF Link

Placed below the Argument metadata preview card and above the stage cards container. Shown for all jobs regardless of step status (as long as the job has a PDF source). This mirrors where the "Edit argument metadata" link sits conceptually.

Implementation: standalone `<div>` styled as a secondary surface card, below the argument preview card.

```html
<div style="background-color: #1e293b; border: 1px solid #334155; border-radius: 8px;
            padding: 24px; margin-bottom: 24px;">
  <a href="/api/admin/jobs/{data.job.id}/pdf"
     target="_blank"
     rel="noopener noreferrer"
     style="font-size: 14px; color: #93c5fd; text-decoration: underline;">
    View source PDF
  </a>
</div>
```

- Opens in a new browser tab (`target="_blank"`, `rel="noopener noreferrer"`)
- Always calls the unified backend endpoint (`/api/admin/jobs/{job_id}/pdf`) — frontend never branches on storage mode
- Link only shown when job has either `spaces_key` or `pdf_url` set (i.e. when a PDF source exists)
- No download button — the browser's native PDF viewer provides save/download capability

## Copywriting Contract

| Element | Copy |
|---------|------|
| Source file label (Ingest card) | `Source file` |
| Utterances stat label | `Utterances` |
| Distinct speakers stat label | `Distinct speakers` |
| Case name stat label | `Case name` |
| Argued date stat label | `Argued` |
| PDF link CTA | `View source PDF` |
| Empty/null stat value | `—` (em dash, consistent with existing argument preview card pattern) |

**No empty-state heading needed** — when parse stats are absent, the rows are simply not rendered; the existing status badge communicates state.

**No error-state copy needed** — stat load failures degrade silently to null/absent rows; the existing job error_message display handles error communication at the job level.

**No destructive actions in Phase 17.** No confirmation dialog required.

**Apolitical framing constraint:** Do not add any derived insight, summaries, or interpretive labels to the stats. The utterance count and speaker count are raw numbers only. The case name and argued date are reproduced verbatim from the database — no annotations.

## Interaction Contract

### Stat Display Logic (Svelte 5 Runes)

Use `$derived()` for the conditional display gate — do not use `$:` blocks (legacy Svelte syntax is disallowed):

```svelte
// In the step card loop, inside the Parse card branch:
{#if step === 'parse' && status === 'completed' && data.job.parse_stats}
  <!-- stat rows -->
{/if}

// In the step card loop, inside the Ingest card branch:
{#if step === 'ingest' && (data.job.original_filename || data.job.pdf_url)}
  <!-- source identifier row -->
{/if}
```

### PDF Link (No Client-Side Fetch)

The "View source PDF" link is a plain `<a href>` — not a button with a fetch call. The backend endpoint handles storage-mode routing transparently (302 redirect for Spaces, `FileResponse` for disk). The link always points to `/api/admin/jobs/{data.job.id}/pdf`.

### No Loading States for Stats

Stats are included in the existing `GET /api/admin/jobs/{job_id}` response payload (no separate sub-request). The page's existing polling interval (`1000ms`) already keeps the job detail fresh. No additional loading skeleton or spinner is needed for stats.

### Accessibility

- The `aria-live="polite"` region already wraps the stage cards container — stat additions inside cards are automatically announced to screen readers when the parse step completes during a polling cycle
- The "View source PDF" link must have descriptive text (not "click here") — `View source PDF` satisfies WCAG 2.4.6 link purpose
- `target="_blank"` links must include `rel="noopener noreferrer"` — already specified above
- Focus ring: inherited from global `:focus-visible` rule in `app.css` (`outline: 2px solid #93c5fd`)
