<objective>
Fix the "Start anyway" button in the duplicate warning banner. The button currently calls
requestSubmit() on the form, which re-fires the submit event and re-enters handleSubmit.
handleSubmit sets submitting=true (disabling the submit button) before the browser finalizes
the POST. Svelte flushes the disabled state reactively; the browser aborts the submission
because the submit button is disabled, leaving submitting=true stuck and triggering a fallback
navigation that appears as a logout.

Purpose: UAT test 5 ("Duplicate banner — Start anyway proceeds") is the only open gap blocking
phase 19 closure. This is a targeted single-file fix.

Output: +page.svelte with formEl bound via bind:this and "Start anyway" using formEl.submit()
instead of requestSubmit(), so the submit event is not re-fired and handleSubmit is bypassed.
</objective>

Three edits to app/src/routes/admin/pipeline/+page.svelte:

**Edit 1 — Declare the form element ref variable.**

In the script block, after the line `let preflightCleared = $state(false);` (currently around line 31),
add the following declaration on a new line:

  let formEl: HTMLFormElement;

**Edit 2 — Bind the ref to the form element.**

The `&lt;form&gt;` opening tag (around line 212) currently reads:

  &lt;form
    method="POST"
    enctype="multipart/form-data"
    onsubmit={handleSubmit}
  &gt;

Add `bind:this={formEl}` as a new attribute on the form element, so the tag reads:

  &lt;form
    method="POST"
    enctype="multipart/form-data"
    onsubmit={handleSubmit}
    bind:this={formEl}
  &gt;

**Edit 3 — Replace requestSubmit() in the "Start anyway" onclick with formEl.submit().**

The "Start anyway" button onclick (around line 364) currently reads:

  onclick={() => { preflightCleared = true; duplicateWarning = null; document.querySelector('form')?.requestSubmit(); }}

Replace the entire onclick attribute value so it reads:

  onclick={() => { submitting = true; preflightCleared = true; duplicateWarning = null; formEl.submit(); }}

Rationale for each change:
- `formEl.submit()` dispatches a native form POST directly to the browser without firing the
  submit event. This means handleSubmit is NOT called again, so submitting is not set a second
  time from within handleSubmit. There is no reactive flush that disables the submit button
  before the POST is initiated.
- `submitting = true` is set explicitly in the onclick before calling formEl.submit() so the
  button label still changes to "Starting…" as expected.
- `document.querySelector('form')` is replaced with the bound `formEl` ref, removing the
  fragile DOM query and the optional-chain guard that could silently do nothing.

Do NOT change the three requestSubmit() calls inside handleSubmit (lines approximately 57, 65,
and 70). Those calls are made from within a submit event handler that has already called
e.preventDefault(), so they do not re-enter handleSubmit recursively. Only the "Start anyway"
button onclick triggers a brand-new submit event — that is the only site being fixed here.
