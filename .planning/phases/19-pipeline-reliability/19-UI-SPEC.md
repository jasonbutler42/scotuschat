## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps, badge padding-block |
| sm | 8px | Label-to-input gap, field margin-bottom default, button padding-block |
| md | 16px | Default field margin-bottom, section header margin-bottom, gap between form rows |
| lg | 24px | Card padding, between-card margin-bottom, form sections |
| xl | 32px | History section margin-top, between major cards |
| 2xl | 48px | Page container top/bottom padding (`padding: 48px 24px`) |
| 3xl | 64px | Not actively used in admin |

Exceptions:
- Touch targets for all interactive buttons: `min-height: 44px` (WCAG 2.5.5 — existing pattern for Start Run, Continue Resolve, Create Argument, Save metadata)
- Inline action buttons inside cards (e.g., Cancel, Start anyway): `min-height: 36px` acceptable when rendered inline alongside other elements — consistent with existing Change/Confirm/Select button pattern in the resolve table

Source: measured from `app/src/routes/admin/pipeline/+page.svelte` and `[job_id]/+page.svelte`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.4 |
| Heading (card section) | 20px | 600 | 1.2 |
| Display (page h1) | 20px | 600 | 1.2 |

Notes:
- Body (16px) applies to: all text inputs (`<input type="text">`, `<input type="date">`), input values, error/alert messages, submit button text, metadata field displayed values
- Label (14px) applies to: `<label>` elements, secondary/muted hint text ("Extracted: [value]"), optional field placeholder indicators, docket field placeholder text, table column headers
- Heading and Display share the same spec (20px / 600 / 1.2) — matches existing `<h1>` and `<h2>` usage in pipeline pages
- No size above 20px is used anywhere in the admin UI

Source: inline styles in `app/src/routes/admin/pipeline/+page.svelte` and `[job_id]/+page.svelte`.

## Color

All values are the existing CSS custom properties from `app/src/app.css`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0f1117` | Page background, input/select fill, combobox dropdown hover base |
| Secondary (30%) | `#1e293b` | Card/section backgrounds, header bar, duplicate warning banner background |
| Border | `#334155` | All card borders, input borders, table row dividers, docket field idle border |
| Text primary | `#e2e8f0` | All body text, input values, heading text, button labels |
| Text secondary | `#94a3b8` | Labels, field hints ("Extracted: [value]" hint text), optional field labels, table column headers, Q-number selector label |
| Accent (10%) | `#93c5fd` | See reserved list below |
| Warning | `#fbbf24` | Duplicate warning banner border + icon glyph; existing paused-step left-border pattern |
| Destructive | `#ef4444` | Inline form errors rendered as `role="alert"`; duplicate-match DB failure error message |
| Success | `#4ade80` | Not introduced in this phase; existing completed-step color — do not add new usage |

Accent (`#93c5fd`) reserved for:
1. Save Metadata button border (`border: 1px solid #93c5fd`) — primary action on metadata card
2. The `:focus-visible` outline on all interactive elements (2px, offset 3px, from `app.css`)
3. Duplicate warning "Start anyway" button border — signals it is the primary path forward, not a safe default
4. Existing: Continue Resolve button border, Create Argument button border (carried forward, unchanged)

The duplicate warning banner uses `#fbbf24` (warning amber) for its border — NOT accent — because it signals a non-fatal caution state, consistent with the existing paused-step left-border treatment.

Source: `app/src/app.css` + full scan of admin Svelte pipeline files.

## Component Inventory

New UI elements this phase must follow existing inline-style patterns exactly. No new component abstractions, no new dependencies.

### 1. Docket Input Field (new — pipeline start form, `/admin/pipeline`)

- Element: `<input type="text" name="primary_docket" id="primary_docket" placeholder="e.g. 14-556 (optional)">`
- Placement: After the URL/upload input row, before the Submit button — within the "New Run" card form
- Wrapper: `<div style="margin-bottom: 16px;">`
- Label: `<label for="primary_docket" style="display: block; font-size: 14px; font-weight: 400; color: #94a3b8; margin-bottom: 8px;">Docket number</label>`
- Input style: identical to existing URL input — `background-color: #0f1117; border: 1px solid #334155; border-radius: 6px; padding: 8px 12px; font-size: 16px; color: #e2e8f0; width: 100%; box-sizing: border-box;`
- NOT `required` — the field is optional; omitting it skips preflight
- Source decision: CONTEXT.md D-03, Specifics section ("placeholder text 'e.g. 14-556 (optional)'")

### 2. Question Number Selector (new — pipeline start form, `/admin/pipeline`)

- Element: `<select name="question_number" id="question_number">` with options `<option value="1">Q1</option>` and `<option value="2">Q2</option>`
- Placement: Immediately after the docket input, before the Submit button
- Default selection: Q1 (value "1")
- Label: `<label for="question_number" style="display: block; font-size: 14px; font-weight: 400; color: #94a3b8; margin-bottom: 8px;">Question number</label>`
- Select style: `background-color: #0f1117; border: 1px solid #334155; border-radius: 6px; padding: 8px 12px; font-size: 16px; color: #e2e8f0; min-height: 44px; width: 100%; box-sizing: border-box;`
- Source decision: CONTEXT.md D-03

### 3. Duplicate Warning Banner (new — pipeline start form, inline)

- Trigger: JS preflight fires on form submit when docket field is non-empty; if a match is found, the banner appears above the Submit button and the submit is suppressed
- Placement: Directly above the "Start Run" button, inside the form, below the question_number selector
- Container: `<div role="alert" style="background-color: #1e293b; border: 1px solid #fbbf24; border-radius: 8px; padding: 16px; margin-bottom: 16px;">`
- Warning icon + heading row: `<p style="font-size: 16px; font-weight: 600; color: #e2e8f0; margin: 0 0 8px 0;">⚠ Argument already exists</p>`
- Body copy: `<p style="font-size: 14px; color: #94a3b8; margin: 0 0 12px 0;">Docket [DOCKET] Q[N] already has an argument. <a href="/admin/arguments/[id]" style="color: #93c5fd; text-decoration: underline;">View existing argument →</a></p>`
- Action row: `<div style="display: flex; gap: 8px;">` containing Cancel + Start anyway buttons
- Cancel button: `font-size: 14px; font-weight: 400; color: #94a3b8; background: transparent; border: 1px solid #334155; border-radius: 6px; padding: 8px 16px; min-height: 36px; cursor: pointer;`
- Start anyway button: `font-size: 14px; font-weight: 600; color: #e2e8f0; background: transparent; border: 1px solid #93c5fd; border-radius: 6px; padding: 8px 16px; min-height: 36px; cursor: pointer;`
- Source decision: CONTEXT.md D-04, D-05, D-06, Specifics section

### 4. Argument Metadata Card (new — job detail page, `/admin/pipeline/[job_id]`)

- Placement: Between the existing "Argument" preview card and the PDF source card in the job detail layout; always shown once `argument_id` is set on the job
- Container: `<div style="background-color: #1e293b; border: 1px solid #334155; border-radius: 8px; padding: 24px; margin-bottom: 24px;">`
- Heading: `<h2 style="font-size: 20px; font-weight: 600; color: #e2e8f0; margin: 0 0 16px 0; line-height: 1.2;">Argument Metadata</h2>`
- Uses a `<form method="POST" action="?/saveMetadata" use:enhance>` for submission — follows existing resolve/approve form patterns
- Fields: case name (text), docket (text), argued date (date input)
- Per-field layout: label on top, input below, optional hint text below input
- Hint text ("Extracted: [value]") style: `display: block; font-size: 14px; font-weight: 400; color: #94a3b8; margin-top: 4px;` — rendered only when `cover_metadata` contains a value that differs from the current field value (operator-entered conflict)
- Source decision: CONTEXT.md D-13, D-14, D-15, Specifics section

### 5. Metadata Field — Case Name (within card above)

- Element: `<input type="text" name="case_name" id="meta_case_name">`
- Label: `<label for="meta_case_name" style="display: block; font-size: 14px; font-weight: 400; color: #94a3b8; margin-bottom: 8px;">Case name</label>`
- Input style: same as all existing admin text inputs
- Pre-populated from `cover_metadata.case_name` when field is null; hint text shown when operator value differs from extracted value
- Source decision: CONTEXT.md D-09, D-14

### 6. Metadata Field — Docket (within card above)

- Element: `<input type="text" name="source_docket" id="meta_docket">`
- Label: `<label for="meta_docket" style="display: block; font-size: 14px; font-weight: 400; color: #94a3b8; margin-bottom: 8px;">Docket</label>`
- Input style: same as all existing admin text inputs
- Source decision: CONTEXT.md D-09, D-14

### 7. Metadata Field — Argued Date (within card above)

- Element: `<input type="date" name="argued_date" id="meta_argued_date">`
- Label: `<label for="meta_argued_date" style="display: block; font-size: 14px; font-weight: 400; color: #94a3b8; margin-bottom: 8px;">Argued date</label>`
- Input style: same as all existing admin text inputs (date input renders with browser native picker)
- Empty when null — operator sees blank field, not "—"; field emptiness is the signal (D-11)
- Source decision: CONTEXT.md D-08, D-11

### 8. Save Metadata Button (within card above)

- Element: `<button type="submit">` inside the metadata form
- Style: `display: block; width: 100%; min-height: 44px; background-color: #1e293b; border: 1px solid #93c5fd; border-radius: 6px; font-size: 16px; font-weight: 600; color: #e2e8f0; cursor: pointer; margin-top: 8px;`
- Idle label: `Save metadata`
- Submitting label: `Saving…` with `disabled` + `opacity: 0.7`
- Source decision: CONTEXT.md D-15

## Interaction States

| Element | State | Visual Change |
|---------|-------|---------------|
| Docket input | idle | border `#334155` |
| Docket input | focus | `outline: 2px solid #93c5fd; outline-offset: 3px; border-radius: 4px` (app.css global) |
| Docket input | filled | JS preflight enabled on submit |
| Docket input | empty | No preflight; submit proceeds normally |
| Duplicate warning banner | hidden (default) | Not rendered |
| Duplicate warning banner | visible (preflight hit) | Rendered above Start Run button; Start Run button suppressed |
| "Cancel" in warning | clicked | Banner dismissed; form returns to idle; Start Run button restored |
| "Start anyway" in warning | clicked | Form submits despite duplicate warning; banner dismissed |
| Start Run button | submitting | `disabled`, `opacity: 0.7`, label → "Starting…" |
| Metadata card fields | pre-populated (auto) | Input has value from extraction; no hint text |
| Metadata card fields | conflict (operator vs extracted) | Input shows operator value; hint text "Extracted: [value]" below in `#94a3b8` |
| Metadata card fields | both empty | Input shows empty string; hint text absent |
| Save Metadata button | idle | "Save metadata", full opacity |
| Save Metadata button | submitting | "Saving…", `disabled`, `opacity: 0.7` |
| Save Metadata button | error | `role="alert"` paragraph in `#ef4444` below form |
| Any input | focus | `outline: 2px solid #93c5fd; outline-offset: 3px` |

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Duplicate warning announcement | `role="alert"` on the banner `<div>` — screen readers announce it immediately when it appears |
| Docket + question fields | `<label for="...">` explicitly associated via `id` on each input |
| Metadata card fields | `<label for="...">` on each input; hint text is a `<span>` or `<p>` associated via proximity (not aria-describedby — consistent with existing pattern) |
| Touch targets | Start Run (min-height 44px), Save Metadata (min-height 44px), Cancel (min-height 36px inline), Start anyway (min-height 36px inline) |
| Focus ring | All inputs and buttons covered by `*:focus-visible` global rule in app.css |
| Preflight suppression | When warning banner appears, the native form submit is prevented via `onsubmit` intercept — keyboard users can still Tab to Cancel or Start anyway |
| Error alerts | `role="alert"` on all error `<p>` elements — existing pattern carried forward |
