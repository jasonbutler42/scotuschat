<objective>
Add full-stack multi-docket support so an argument can hold multiple docket numbers (for
consolidated cases), closing UAT Test 6 (major). The one-docket cap was intentional and
consistent across DB, schema, service, server action, and component — every layer must
change together or the feature is half-broken.

Purpose: Consolidated SCOTUS cases argue under multiple docket numbers. The operator needs
to record all of them. The current stack stores exactly one `source_docket` string.

Output: A new `source_dockets` text[] array column (backfilled from the existing
`source_docket`), array-aware schema/service/server-action/component, with the singular
`source_docket` column RETAINED as the canonical dedup key (= first docket).

LOCKED DESIGN DECISION (D-MULTI-DOCKET) — read before implementing:
  Do NOT drop or repurpose `source_docket`. It participates in the UNIQUE constraint
  `uq_arguments_source_docket_question` (source_docket, question_number) that ingest,
  the preflight duplicate check, and the parse step all rely on. Postgres cannot express
  that dedup over an array column cleanly.

  Instead: ADD a nullable `source_dockets text[]` column that holds the full ordered list.
  Keep `source_docket` in sync as `source_dockets[0]` (the primary/canonical docket used
  for dedup). This is the least-disruptive path that preserves every existing dedup code
  path unchanged and satisfies the CLAUDE.md constraint that Alembic is the sole DDL
  authority. A join table was considered and rejected — it would ripple through ingest,
  parse, and preflight for no gain over the array for this read-mostly field.
</objective>
