<objective>
Close the single gap in 24-VERIFICATION.md (CR-01): an operator-entered docket pill value
beginning with `-` or `--` is forwarded unsanitized into the spawned `python -m pipeline ingest`
argv, where argparse raises SystemExit(2) before run_ingest() runs. Because
pipeline_spawn.py spawns with stdout/stderr=DEVNULL, the failure is invisible and the
admin_jobs row is stranded at PENDING/INGEST forever with zero operator-visible error.

This plan applies BOTH prongs the verification report requires as one coherent fix:
1. Reject `-`-prefixed docket values at the FastAPI boundary (422), mirroring the existing
   `_validate_pdf_url` rejection precedent — primary defense that closes the argv-injection
   vector at the source.
2. Add a startup guard in `pipeline/__main__.py` that persists a best-effort FAILED status
   (scraping `--job-id` from `sys.argv`) even for argparse-level SystemExit — defense-in-depth
   observability so NO pre-run_ingest crash can ever silently strand a job again.

Purpose: Restore the "docket pills persist reliably for any operator-entered string" truth
that PLIST-02's must-haves commit to, and eliminate the silent-stuck-job failure class.
Output: Two production edits + two static-analysis test files that deterministically prove
both guards are present and behave correctly, runnable in <2s without a live DB.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SvelteKit form → FastAPI POST /api/admin/jobs | Operator-supplied docket pill strings cross here as repeated `source_dockets` form fields — untrusted input |
| FastAPI router → spawned `python -m pipeline ingest` subprocess argv | Normalized docket strings become process arguments (argv) — a CLI-argument-parsing boundary |
| Pipeline subprocess → admin_jobs table (Postgres) | The child process is the sole writer of job status; a crash before this write leaves the job in a stale state |
