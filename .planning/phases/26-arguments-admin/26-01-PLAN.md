<objective>
Rebuild the backend argument lifecycle around the three-state model (DRAFT / PUBLISHED / UNPUBLISHED) and start writing the ArgumentStatusLog audit trail for every transition.

Purpose: Phases 22 introduced the `unpublished` enum value and the `argument_status_log` table, but no service code writes status or log rows yet — publish/unpublish only touch `published_at`, the list query hides UNPUBLISHED, the delete gate and slug-freeze still key on `published_at`, and the log table is empty for everything created after the Phase 22 backfill. This plan makes the backend the source of truth for the lifecycle.

Output: Updated `admin_arguments.py` (publish/unpublish/list/delete/update), `admin_jobs.py` (approve_job "Created" log write), and the delete-route 409 copy in `admin.py`.
</objective>
