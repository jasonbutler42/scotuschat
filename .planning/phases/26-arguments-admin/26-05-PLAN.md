<objective>
Close the two confirmed verification gaps for Phase 26 without re-planning any of the four executed plans:

1. Tighten the backend delete gate so `delete_argument` enforces "DRAFT-only" (currently it blocks PUBLISHED/UNPUBLISHED but silently permits deleting a PIPELINE-status argument, which can permanently strand an active AdminJob). This is a broken-access-control finding: the client gate is correct but the server-side authorization check is incomplete.

2. Make the unified Speakers advocate role control safe for unresolved advocates. Every freshly-parsed advocate has `side = UNKNOWN`; the current three-option `<select>` has no match for UNKNOWN, so the browser silently defaults to PETITIONER and an accidental Save reclassifies the advocate. Make the unresolved state explicit AND authoritatively prevent a wrong-side write.

Purpose: restore the two must-haves this phase already declared ("delete allowed only for DRAFT" — AEDIT-09/D-03; "inline Save that persists accurate state" — AEDIT-06) and honor CLAUDE.md's apolitical, no-silent-inference constraint for speaker attribution.

Output: DRAFT-only delete gate + regression tests; an authoritative backend guard rejecting UNKNOWN/ADVOCATE advocate sides + a regression test; an explicit "Unresolved" placeholder and Save-disable on the advocate row.
</objective>

| Browser → SvelteKit `?/updateParticipantSide` action → FastAPI PATCH participant | Operator submits `{ participant_id, side, title }`; `side` is attacker/UI-controlled and crosses into a persisted attribution |
