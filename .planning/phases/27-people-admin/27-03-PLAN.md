<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated client → POST /people | New create-person endpoint; the phase's primary new attack surface (D-09) |
| request body → ORM insert/update | PersonCreateRequest / PersonUpdate fields become Person writes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-27-05 | Spoofing / Broken Auth | POST /people | high | mitigate | Route carries the identical admin-auth `Depends(...)` used by every other `/admin/people*` route; unauthenticated requests are rejected before create_person runs. No new/weaker auth path introduced. |
| T-27-06 | Elevation of Privilege (IDOR) | POST /people | high | mitigate | Deliberately does NOT reuse create_person_for_job's job-scoped participant-ownership guard (inapplicable). The endpoint creates only a standalone Person with no cross-entity linkage, so there is no object reference to confuse; the admin boundary is the sole and sufficient guard. |
| T-27-07 | Denial of Service | bulk junk-record creation via minimal D-08 validation | low | accept | Behind admin auth (single trusted operator); no public/anonymous path. Records are soft data (mergeable/deletable via existing Merge/Delete). Residual risk is within the existing admin trust boundary. |
| T-27-03 | Tampering | free-text appointment/name fields → stored value | medium | mitigate | SQLAlchemy parameterizes all writes; the admin UI (Svelte) auto-escapes on render. No raw HTML sink. |
| T-27-SC | Tampering | npm/pip/cargo installs | high | accept | No new dependencies installed in this plan. |
</threat_model>
