# Phase 27 — UI Design Contract

> Visual and interaction contract for `/admin/people/` (list, tabbed) and `/admin/people/[id]` + `/admin/people/new` (shared create/edit template). Generated by gsd-ui-researcher from `27-CONTEXT.md` decisions (D-01–D-19), the three operator mockups, and `.planning/codebase/DESIGN-SYSTEM.md`. Verified by gsd-ui-checker.

**Design system note:** This project has no shadcn, no Tailwind, no `components.json` — it is a hand-rolled inline-CSS system, consistently applied since Phase 5 (confirmed in `DESIGN-SYSTEM.md` and by direct inspection of `app/src/routes/admin/people/+page.svelte` / `[id]/+page.svelte`). The shadcn initialization gate does not apply (stack is SvelteKit, not React/Next/Vite, and the project has explicitly chosen not to adopt a component library). All values below are pulled directly from the existing codebase and `DESIGN-SYSTEM.md` — nothing here introduces a new token unless explicitly marked "**NEW**".

**Mockup usage discipline (operator's explicit instruction):** The three mockups (`create-person-bench-filled.png`, `create-person-bench-blank.png`, `create-person-advocate.png`) are read for **card structure, field grouping, and conditional-reveal flow only**. Every color, font-size, spacing, and radius value below comes from `DESIGN-SYSTEM.md` / the existing codebase, not from the mockups' literal pixel appearance.

## Spacing Scale

Declared values (multiples of 4, per existing codebase — source: `DESIGN-SYSTEM.md` § Spacing):

| Token | Value | Usage in this phase |
|-------|-------|-------|
| xs | 4px | Gap between missing-field pills; gap between tenure sub-card internal micro-elements |
| sm | 8px | Label-to-input gap; gap between inline buttons (Save Person / Cancel); table cell vertical padding |
| md | 16px | Field-to-field vertical margin within a card; grid gap in name-parts / Birth-Death-Date / tenure-field rows; gap between stacked cards |
| lg | 24px | Card internal padding (all cards, including the new Person Type / Bench Details card and tenure sub-cards); heading-to-content margin |
| 2xl | 48px | Page content top/bottom padding (list, create, edit — matches existing) |

`xl` (32px) and `3xl` (64px) from the template's default scale are **not used anywhere in the existing codebase and are not introduced by this phase** — do not add them.

**Exceptions:**
- Touch targets: all primary buttons and submit inputs are `min-height: 44px` (WCAG 2.1 AA) — Save Person, Cancel, Create person, Upload photo, Merge, Delete person, Bench/Advocate segmented toggle buttons, "+ Add Tenure Period" is a text link (no min-height requirement, not a button).
- Compact per-row buttons (Remove tenure period, missing-field filter pills) use `min-height: 36px`, matching existing dense-table/inline-button convention.
- Tenure sub-card "Remove" button (D-18): `min-height: 36px` (compact, matches existing "Remove tenure row" ✕-button precedent, not a full-width 44px button).

## Interaction Contract — Click-to-Filter Missing-Field Pills (D-04, Claude's Discretion, resolved)

This section resolves the first open discretion item from `27-CONTEXT.md`.

- Each missing-field pill (Name, Photo, Bio, Birthdate, "No tenures" on Bench; Name, Photo, Bio on Advocate — per D-05/D-06) is rendered as a `<button>`, not a `<span>`, using the **exact existing pill visual style verbatim** (bg `rgba(245,158,11,0.15)`, border+text `#f59e0b`, radius 4px, padding 4px 8px, 14px/400/1.4).
- **Single-select filter, toggle behavior:** clicking an inactive pill sets it as the active filter (navigates via `goto()` to `?tab=bench&missing=birthdate`, same query-param pattern as the existing `?incomplete=1` toggle). Clicking the currently-active pill again clears the filter (navigates back to `?tab=bench`). Only one missing-field filter can be active at a time — selecting a different pill replaces the previous filter, it does not combine them.
- **Active-state styling:** the active pill inverts to a solid fill — `background-color: #f59e0b; color: #0f1117; border: 1px solid #f59e0b; font-weight: 600` (600 is the only bold weight in the type system) — so it reads as "engaged" without introducing a new color.
- **Hover state (inactive pills):** `cursor: pointer`, add `box-shadow: 0 0 0 1px #f59e0b inset` on hover/focus — no new color introduced, communicates interactivity.
- **Clear affordance:** a persistent `Filtering by: {label} · Clear filter` line appears directly above the table whenever any missing-field filter (or the existing "Justices with tenure gaps" toggle) is active — "Clear filter" is an accent-colored (`#93c5fd`) text link that resets to the bare `?tab=` URL. This exists in addition to the toggle-by-reclicking behavior, not instead of it, per D-04's explicit "click again / a visible 'Clear filter' control" wording (both affordances required).
- **Accessibility:** each pill button gets `aria-pressed={isActive}` and `aria-label="Filter by {field}"`; the "Clear filter" link gets `aria-label="Clear missing-field filter"`.

## Screen Contract — People List (`/admin/people/`)

- Page header: `<h1>People</h1>` (PDIR-01), no breadcrumb (this is the root page).
- Tabs (D-01, D-02, D-03): two tab buttons, "Bench" and "Advocate", styled as a segmented toggle identical in visual treatment to the Person Type toggle on the create/edit page (selected = solid accent fill + dark text; unselected = card-bg + border + primary text). Bench is default when `?tab=` is absent (D-03). Tab click navigates via `goto()`, same pattern as existing toggles.
- "Create person" button (PDIR-07): positioned top-right of the header row, next to the tabs — accent-bordered button style (matches "Save Person" visual treatment), navigates to `/admin/people/new`.
- "Justices with tenure gaps" toggle (PDIR-06): retained exactly as it exists today, **Bench tab only** — hidden entirely when Advocate tab is active.
- The old "Show incomplete only" toggle is **removed** (D-04) — do not render it on either tab.
- **Bench tab columns** (PDIR-03): Name (with existing "Justice" badge chip), Tenure coverage (e.g. `1972–2005`, or `1986–present` for an open-ended tenure, or `No tenure` in muted text when zero rows), Tenure gap indicator (muted `—` when no gap; `⚠ Gap` in Warning `#fbbf24` text when the "Justices with tenure gaps" logic flags this person), Missing fields (click-to-filter pills per D-06's field list: first name, last name, photo, bio, birthdate, "No tenures"), Actions ("Edit person" link, accent color, unchanged).
- **Advocate tab columns** (PDIR-04): Name, Argument count (plain integer, muted text, right-aligned like other numeric-style columns), Missing fields (click-to-filter pills per D-05's field list: first name, last name, photo, bio), Actions ("Edit person" link).
- Argument count computation (Claude's discretion, resolved): count **distinct arguments** the person appears in as a participant (not total participation rows), since an operator scanning this column is asking "how many arguments feature this advocate," not "how many rows exist" — distinct-count avoids double-counting a person listed twice on one argument (unlikely but not guaranteed impossible given multi-docket consolidated arguments from Phase 24).
- Table empty states: see Copywriting Contract above — four distinct states (tab-with-no-people, missing-field-filter-empty, tenure-gaps-filter-empty, and the pre-existing structure is reused, just re-scoped per tab).

## Screen Contract — Create / Edit Person (`/admin/people/new` and `/admin/people/[id]`, shared template — D-07)

Card order top to bottom (D-13, mirrors mockup structure exactly; colors/spacing per tokens above, not mockup pixels):

1. **Page header** — breadcrumb (`People > Create Person` or `People > {full name}`) above the `<h1>`. This is a **new pattern for this phase**, replacing the existing plain `← People` back-link (see Copywriting Contract; adopted per the third discretion item below).
2. **Identity card** (renamed from "Basic Info") — Full name (single text input), then First / Middle / Last / Suffix in the existing 4-column-desktop / 2-column-mobile grid (unchanged layout, unchanged sentence-case labels). The "Is Justice" checkbox is **removed from this card** — superseded by the Person Type toggle (item 4 below).
3. **Photo card** — unchanged from today's implementation (avatar circle with initials fallback, Upload file / Enter URL tabs, "Upload photo" button per PEDIT-05/D-17). Hidden entirely on `/admin/people/new` until first save, OR rendered with an empty-initials placeholder and disabled submit until a person exists — **planner's call**, both are visually identical from the Photo card's own styling standpoint; this spec only fixes the card's internal visual contract, not the create-page's pre-save gating mechanics.
4. **Biography card** — unchanged from today's implementation (textarea, placeholder "Enter a short biography...").
5. **Person Type card** (new, visible H2 title "Person Type" — internally the "Bench Details card" per `27-CONTEXT.md`'s narrative naming, D-13):
   - Bench/Advocate segmented toggle (replaces "Is Justice" checkbox) — sets `is_justice`.
   - When **Bench** is selected: Birth Date + Death Date (2-column grid, `md` 16px gap) appear below the toggle, followed by the "Tenure Periods" sub-heading and the repeatable tenure list, animated in with Svelte's `slide` transition per D-11 (card container stays put, content grows/shrinks — not a fade).
   - When **Advocate** is selected: none of the above render (D-15) — the card only contains the toggle.
   - Each **Tenure Period row** is its own bordered sub-card (D-18): background `#0f1117` (dominant/inset), border `1px solid #334155`, radius 6px (matches input radius, distinct from the outer card's 8px), padding `lg` (24px), margin-bottom `md` (16px) between sub-cards. Sub-card field layout: Start Date + End Date (2-col row), Appointing President (full-width row, free-text input per D-16), President's Party + Reason Left (2-col row, Reason Left disabled per D-19), Remove button (right-aligned below the fields, destructive-red, compact 36px height).
   - "+ Add Tenure Period" link sits below the full list, accent-colored, 14px/400.
6. **Merge card** ("Merge into another person") — unchanged from today. **Hidden on `/admin/people/new`** (resolves the second discretion item: nothing to merge before the person exists).
7. **Delete card** — unchanged from today. **Hidden on `/admin/people/new`** (same reasoning — nothing to delete before the person exists).
8. **Form-level action row** — "Save Person" (primary, accent) and "Cancel" (secondary, muted-border) side by side, `sm` (8px) gap, per mockup layout — replaces today's full-width stacked "Save changes" button.
