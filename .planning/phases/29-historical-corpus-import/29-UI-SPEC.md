# Phase 29 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope reminder:** Phase 29 is overwhelmingly a backend/pipeline phase (a one-time bulk-import CLI command). This contract covers ONLY the two frontend surfaces in scope:

1. **Attributions/License page** — new small, static route (D-26). Must exist before any corpus-imported argument goes live, even as draft. Credits Oyez.org, Cornell ConvoKit, and SCDB (D-23); states the Oyez CC BY-NC 4.0 license fact (D-24).
2. **Per-argument attribution note** — a small indicator on corpus-sourced argument pages, distinguishing them from manually-ingested (PDF pipeline) arguments (D-22), linking out to the Attributions page.

Not covered here (explicitly out of scope): the CLI import tool itself, any admin review screens (existing admin/publish UI is reused as-is), the deferred stage-direction/paragraph-splitting toggle.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — `bits-ui` is used elsewhere in the app (e.g. `Popover` on the argument view) but is not needed for either surface in this phase's scope |
| Icon library | none — this codebase has no icon library anywhere; affordances are text + the existing `→` arrow-link convention (see `admin/pipeline/+page.svelte`: `"View existing argument →"`) |
| Font | `system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif` (declared in `app/src/app.css` `:root`) |

**Detection notes:** No `components.json` exists anywhere in the repo — this project has never adopted shadcn across 7 prior UI phases (22–28). The entire frontend uses a manual, inline-`style`-attribute system with hardcoded hex values that mirror the CSS custom properties in `app.css` (Tailwind is configured in `tailwind.config.js` but its utility classes are not actually used in practice — every surveyed component uses `style="..."` directly). Given the established 7-phase precedent and this phase's tiny scope (one static page + one text note), introducing shadcn now would be a scope-inconsistent deviation, not a genuine improvement. **Tool: none** carries forward the existing convention; this was not asked as an open question because the codebase itself already answers it unambiguously.

## Typography

Sizes/weights below reuse the exact values already established across the codebase (no new sizes introduced) — see `ChatBubble.svelte`, the argument page header (`cases/[slug]/arguments/[id]/+page.svelte`), and `admin/arguments/[id]/+page.svelte`'s badge styling.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.6 |
| Label | 14px | 400 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Caption *(repurposes template's "Display" row — this phase needs a small muted-caption size, not a large display size)* | 13px | 400 | 1.4 |

- **Body (16px/400/1.6):** Attributions page intro paragraph, license-callout paragraph text.
- **Label (14px/400/1.4):** Credit block names ("Oyez.org", "Cornell ConvoKit", "Supreme Court Database"); per-argument attribution note text; new "Attributions" TopNav link.
- **Heading (20px/600/1.2):** Attributions page `<h1>` — matches the existing single-H1-size convention used on the argument view page's case-name heading. No sub-headings needed; the page is short enough for label-weight (14px/400, uppercase-tracking optional) section dividers instead of a heading hierarchy.
- **Caption (13px/400/1.4):** ConvoKit academic-citation lines, SCDB data-lineage clarification line — secondary/muted supporting text, styled identically to the existing "section label" pattern (`color: #94a3b8`).

Exactly 2 weights used across this phase: 400 (regular) and 600 (semibold, heading only) — no bold (700) anywhere.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0f1117` | Page background — Attributions page body, argument page background (unchanged, existing) |
| Secondary (30%) | `#1e293b` | License-callout card surface; credit-block card surfaces on the Attributions page — matches existing card/surface convention (`RunStatusCard`, argument header bar) |
| Accent (10%) | `#93c5fd` | Reserved for: the "View attributions →" link inside the per-argument note; the three outbound credit links on the Attributions page (Oyez.org, ConvoKit GitHub/paper links, SCDB); the new "Attributions" link added to `TopNav` (public variant) |
| Destructive | `#ef4444` | Not used this phase — no destructive actions in scope. Documented for consistency with the rest of the app only. |

Accent reserved for: outbound/cross-page links only (the 3 credit links + the "View attributions →" link + the TopNav entry point). Never apply accent to body text, headings, or the license-callout box border — those stay in the neutral palette (`#e2e8f0` primary text / `#94a3b8` secondary text / `#334155` border) to keep the attribution note visually quiet rather than promotional, matching the apolitical, non-editorializing house tone.

## Implementation Notes (non-template, for planner/executor)

- **New route:** `app/src/routes/attributions/+page.svelte` (static — no `+page.server.ts` needed unless the planner wants to source citation text from a shared constant rather than inlining it in the template; either is fine, this is an implementation detail, not a design-contract concern).
- **Modified file:** `app/src/lib/components/TopNav.svelte` — add the "Attributions" link inside the existing `variant === 'public'` nav bar, positioned after "Cases" and before the right-aligned "Admin" link (`margin-left: auto` stays on "Admin" only).
- **Modified file:** `app/src/routes/cases/[slug]/arguments/[id]/+page.svelte` — add the per-argument note as a new line directly below the existing Bench/Advocates roster grid, inside the same header `<div style="max-width: 1200px; margin: 0 auto;">` block, so it reads as part of the argument's metadata rather than an intrusive banner.
- **Visibility condition (planner to wire to the actual backend signal, e.g. `argument.oyez_transcript_id !== null` or a `pipeline_run.strategy === 'convokit_import'` flag surfaced through `+page.server.ts`):** the note must render ONLY on corpus-sourced arguments and must NOT appear on manually PDF-ingested arguments — this is the core requirement of D-22, not a cosmetic choice.
- The Attributions page and the per-argument note intentionally share the same muted, neutral visual weight as the rest of the public site's metadata (no colored badge, no icon, no attention-grabbing treatment) — this is a legal/academic credit, not a marketing callout, consistent with the apolitical framing constraint that governs every other surface in this app.
