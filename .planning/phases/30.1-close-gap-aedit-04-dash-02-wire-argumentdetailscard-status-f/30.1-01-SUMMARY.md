# Phase 30.1 Plan 01: Wire status filter through arguments list Summary

**GET /api/admin/arguments now accepts an allow-list-guarded `?status=` query param that narrows results to a single status end-to-end, with a new segmented filter control, active-filter indicator, and filtered empty-state on the `/admin/arguments` list page (DASH-02).**

## Accomplishments
- `list_arguments(db, status=None)` narrows to DRAFT/PUBLISHED/UNPUBLISHED via an allow-list-guarded `.where()` clause; unrecognized/absent values (including `pipeline`) fall through to the full unfiltered list with no error
- `GET /arguments` forwards a new `status` query param to the service with no new route/path segment
- Arguments list `load()` reads `?status=`, forwards it to FastAPI, and returns `status` in the page payload
- List page header gained a 4-option segmented filter (All/Draft/Published/Unpublished) with per-status selected-fill colors, an active-filter indicator (`Showing: {Status} arguments · Clear filter`), and a filtered empty-state (`No {Status} arguments.`)
- Route-resolution regression test proves `?status=draft` and `?status=bogus` both return 401 (not 422) without a valid token
