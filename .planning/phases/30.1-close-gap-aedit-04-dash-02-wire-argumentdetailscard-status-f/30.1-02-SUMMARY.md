# Phase 30.1 Plan 02: Wire ArgumentDetailsCard into /admin/arguments/[id] Summary

**`/admin/arguments/[id]` now renders the shared `ArgumentDetailsCard.svelte` component as a true second consumer, with the old hand-rolled docket/date form reduced to a small "Case" identity card whose `?/save` action no longer touches `argued_date` (AEDIT-04).**

## Performance

## Accomplishments
- `load()` now builds `savedValues` (`dockets`/`question_number`/`argued_date`) and `hints` (`dockets`/`question_number`(frozen null)/`argued_date`/`case_name`) from the already-fetched `ArgumentDetail`, mirroring the pipeline job detail page's Plan 23-03 derivation with the `source_dockets?.length` fallback (Pitfall 3)
- New `saveArgumentDetails` form action PATCHes the existing `PATCH /arguments/{id}/metadata` endpoint, derives the argument id solely from `params.id` (IDOR guard), never sends `case_name`, and returns `{ saved: true }` with no redirect so the component's own "Saved." message renders
- Existing `save` action (Case card) no longer reads or sends `argued_date` — it now PATCHes only `case_name` + `docket_number`
- Combined Card 1 split: a small "Case" card (heading renamed "Case", docket label renamed "Case docket number", `argued_date` input deleted entirely, `margin-bottom` raised 16px→24px) followed immediately by `<ArgumentDetailsCard>` rendered unmodified as a second consumer (`readonly={false}`, wired to `savedValues`/`hints`/`action="?/saveArgumentDetails"`/`form`)
- Zero backend changes — reuses `PATCH /arguments/{id}/metadata`, `update_argument_metadata()`, `MetadataUpdate`, and `ArgumentDetailsCard.svelte` exactly as they already existed

- `app/src/routes/admin/arguments/[id]/+page.svelte` - Imported `ArgumentDetailsCard`; renamed Card 1 to "Case" (docket label "Case docket number"), deleted the `argued_date` date input, raised its `margin-bottom` to 24px; rendered `<ArgumentDetailsCard>` immediately below as a second consumer; removed the now-dead `toDateInputValue` helper

## Decisions Made
- Argument id in `saveArgumentDetails` derived solely from `params.id`, never from a form field — matches every other action on this page and the project's IDOR convention (T-30.1-04)
- `case_name` intentionally omitted from the `saveArgumentDetails` PATCH body — the Case card's `?/save` remains the sole owner of `case_name` (T-30.1-05 / WR-02)
- `argued_date` deleted (not hidden) from the Case card's form and action, matching the "delete not hide" guidance in Pitfall 2
- `savedValues.dockets` uses the `source_dockets?.length ? ... : (source_docket ? [source_docket] : [])` fallback rather than a bare `??`, since `source_dockets` defaults to `[]` (never `null`)
- `hints.question_number` frozen to `null` per the existing project-wide 23-04 convention (question_number is operator-editable, not an immutable extraction source)
- Removed the now-unused `toDateInputValue` helper since its only caller (the deleted `argued_date` input) no longer exists
