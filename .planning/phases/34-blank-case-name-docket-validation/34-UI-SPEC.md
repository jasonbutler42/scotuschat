# Phase 34 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Existing project-native Svelte components and inline styles; no external design system |
| Preset | not applicable |
| Component library | none |
| Icon library | none; retain the existing text `×` pill-removal control |
| Font | System stack: `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` |

Phase 34 is an error-state refinement inside the existing Case form and shared `ArgumentDetailsCard`; it must not introduce a new card, banner, modal, toast, or page layout. Reuse each form's existing inline `role="alert"` region. The shared `DocketPillInput` remains the only docket-collection control.

### Interaction Contract

| State or event | Required behavior |
|----------------|-------------------|
| Valid case name or docket | Trim leading and trailing whitespace on submission; preserve internal whitespace; proceed through the existing saving and success behavior. |
| Blank case name | Keep the attempted blank value visible, render **“Case name is required.”** in the Case form's existing alert, mark the case-name input invalid, and focus the case-name input. |
| Blank native case docket | Keep the attempted blank value visible, render **“Add at least one docket.”** in the Case form's existing alert, mark the docket input invalid, and focus it unless case name is also invalid. |
| No docket pills | Keep the pill collection visibly empty, render **“Add at least one docket.”** in `ArgumentDetailsCard`'s existing alert, mark the pill text input invalid, and focus that text input. Never restore the saved docket after failure. |
| Multiple required failures | Show every field-specific message together in DOM/form order; focus the first invalid field, not the alert. Case form order is case name then case docket. |
| Mixed valid and blank docket entries | Drop blank entries, de-duplicate valid trimmed entries in first-seen order, keep the first valid entry canonical, and do not show an error when at least one valid docket remains. |
| Failed submission | Preserve all attempted values, including blank invalid fields, empty pill state, and otherwise-valid companion fields. The operator changes only the failed field. |
| Client-side pill validation | Prevent the enhanced submission when no pills exist, expose the same docket copy through the existing alert, and focus the pill text input. Server validation remains authoritative. |
| Read-only shared card | Do not add required styling or errors; the control remains disabled and no save action is present. |

Use `aria-invalid="true"` only while the corresponding required error is active. Associate each invalid control with the existing alert using `aria-describedby`; when multiple messages share one alert, render them as separate text lines or list items without bullets. Error state must not rely on color alone: alert text plus `aria-invalid` are mandatory. Preserve the global 2px light-blue focus-visible outline.

After a failed submission, the first invalid field and its adjacent inline error are the primary visual anchor. The invalid border, exact error sentence, and keyboard focus must direct attention there before the operator scans later invalid fields; no banner, heading, or card-level treatment may compete with that anchor.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Hint-to-control and compact inline gaps |
| sm | 8px | Label gaps, pill gaps, alert message separation |
| md | 16px | Field spacing and alert-to-button spacing |
| lg | 24px | Card padding, heading-to-form spacing |
| xl | 32px | Reserved layout gap; no new Phase 34 usage |
| 2xl | 48px | Existing page top/bottom padding |
| 3xl | 64px | Reserved page-level spacing; no new Phase 34 usage |

Exceptions: Existing 44px minimum submit touch target and 28px pill-removal target are retained as control-size accessibility exceptions, not spacing tokens. Phase 34 does not govern pre-existing component-internal padding or glyph spacing; any spacing added or changed for validation feedback must use only the declared scale. Do not move fields or introduce layout shift when alerts appear.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Supporting / helper text | 13px | 400 | 1.5 |
| Label / inline alert | 14px | 400 | 1.5 |
| Body / input / button | 16px | 400 or 600 | 1.5 |
| Section heading | 20px | 600 | 1.2 |

Only two weights are permitted: 400 and 600. Required-error copy uses 14px/400 in `ArgumentDetailsCard` and may retain the Case form's existing 16px/400 alert treatment; do not bold errors, capitalize them as headings, or add an error title.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0f1117` | Page background and input wells |
| Secondary (30%) | `#1e293b` | Existing cards, header, pills, and button surfaces; borders use `#334155` |
| Accent (10%) | `#93c5fd` | Submit-button borders, links, and focus-visible outlines only |
| Destructive / error | `#ef4444` | Required-error text and invalid input border only |

Accent reserved for: submit-button borders, links, and keyboard focus outlines. For an invalid field, change its 1px border from `#334155` to `#ef4444`; retain the dark input background and primary text. Do not add a red background, error icon, card border, or page-level warning treatment. The error color is semantic validation feedback here, not a destructive-action affordance.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — Case form | `Save changes` / saving state `Saving…` |
| Primary CTA — shared metadata form | `Save Argument Details` / saving state `Saving…` |
| Empty docket helper | `Type a docket number and press Enter to add it.` |
| Case-name required error | `Case name is required.` |
| Docket required error | `Add at least one docket.` |
| Multiple errors | Render both exact field-specific sentences together, in field order; do not replace them with a generic summary. |
| Other save error | Retain the existing surface-specific generic or conflict copy; required failures are selected from structured Pydantic `loc` values, never message text. |
| Empty state heading | None; this phase has no data-empty page state. |
| Empty state body | None; an empty pill collection is an invalid attempted form value, not an empty-state component. |
| Destructive confirmation | None; this phase adds no destructive action. |

Do not add “required” to persistent labels, placeholder text, or helper copy. Required feedback appears after an invalid submission and uses the exact decision-locked sentences above.

## Responsive and Accessibility Contract

- Preserve the existing single-column card layout and 640px maximum content width on the argument editor and the existing pipeline job-detail layout.
- Alerts wrap naturally within the card at narrow widths; each complete sentence stays readable without horizontal scrolling.
- The first invalid control receives focus after the failed enhanced action has updated the DOM. Do not focus the alert for required-field failures.
- For the pill control, expose an imperative focus target or equivalent component API so the parent form can focus the visible docket text input after both client- and server-detected failures.
- Pressing Enter in the docket text input continues to add a nonblank pill and must not submit the form. Attempting to submit with no pills triggers required validation.
- Native and pill-based docket controls use equivalent `aria-invalid`, alert association, copy, border treatment, and recovery behavior.
