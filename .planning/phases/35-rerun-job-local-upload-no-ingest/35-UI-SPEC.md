# Phase 35 — UI Design Contract

> Visual and interaction contract for removing the pipeline-job rerun capability. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Existing project-local Svelte components and inline styles; no new design-system dependency |
| Preset | not applicable |
| Component library | Existing Svelte 5 components; Bits UI remains installed but is not needed for this phase |
| Icon library | None; preserve existing text and Unicode status glyphs |
| Font | `system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif` |

This is a subtractive phase. Do not introduce, restyle, or replace any visible component. The current job-detail hierarchy, card layout, status badges, failed-step guidance, source-PDF links, polling, and Danger Zone remain visually unchanged. No `components.json` or shadcn installation is present or required; the shadcn initialization gate does not apply to this SvelteKit application.

### Interaction and Layout Contract

1. The job-detail page must expose no button, menu item, link, form, dialog, keyboard action, or other affordance that recreates the current job from the same source.
2. Remove the hidden SvelteKit `rerun` form action and its `rerunError` response contract. Do not replace them with disabled controls, explanatory banners, compatibility notices, or a `410 Gone` presentation.
3. A historical job remains an ordinary job-detail page. Its header, run-status card, argument details, step cards, resolve card, participant summary, and Danger Zone keep their present order and styling; no rerun provenance or retired-capability placeholder appears.
4. Failed-step recovery remains inside the failed step card. Preserve the human-readable guidance, the underlined `Start a new run` link to `/admin/pipeline/`, the expandable `Technical details` disclosure, and distinct ingest/parse/resolve guidance.
5. Preserve source-PDF access anywhere it already appears, including `View source PDF` and job-detail `pdfHref` behavior. Links continue to open the PDF in a new tab with `noopener noreferrer` where currently specified.
6. Preserve existing 44px minimum targets for actionable controls. This phase introduces no new interaction state, animation, loading state, modal, toast, or focus-management requirement.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Status-glyph gaps and compact label separation |
| sm | 8px | Compact controls, confirmation-row gap, and guidance heading separation |
| md | 16px | Default card-to-card gap, header vertical padding, and internal grouping |
| lg | 24px | Card padding and page horizontal padding |
| xl | 32px | Existing participant-summary separation |
| 2xl | 48px | Job-detail page top and bottom padding |
| 3xl | 64px | Reserved page-level spacing; no new Phase 35 use |

Exceptions: existing 12px local spacing inside step cards and failed guidance is preserved; interactive controls retain a 44px minimum target height. Do not alter spacing merely to remove the hidden server action.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Supporting / label | 14px | 400 | 1.5 |
| Body / action | 16px | 400 | 1.5 |
| Section heading / emphasized action | 20px | 600 | 1.2 |
| Page heading | 20px | 600 | 1.2 |

Only two weights are permitted in this phase: regular 400 and semibold 600. Preserve the existing monospace family for raw technical-error text; it is a content treatment, not an additional UI type role. No replacement copy may visually imply that same-source rerun remains available.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0f1117` | Page background and nested dark surfaces |
| Secondary (30%) | `#1e293b` | Header, cards, and status-badge background; `#334155` for their borders |
| Accent (10%) | `#93c5fd` | Text links, running-state border/text, and keyboard focus outline only |
| Destructive | `#ef4444` | Existing failed status, raw error text, and Delete run confirmation only |

Primary text remains `#e2e8f0`; secondary text remains `#94a3b8`. Existing completed (`#4ade80`) and paused (`#fbbf24`) status semantics remain unchanged.

Accent reserved for: `Start a new run`, `View source PDF`, other existing navigation links, the running status, and focus-visible outlines. Do not add accent-colored rerun remnants. The destructive color must not be used to advertise removal of the capability; removal is represented by absence, not a warning state.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Start a new run` |
| Empty state heading | Preserve the pipeline-list empty state; no new job-detail empty state is introduced |
| Empty state body | `Start a new run above to begin ingesting a transcript.` |
| Error state | Preserve step-specific recovery guidance and the fallback: `Correct the issue, then start a new run from the pipeline page.` |
| Destructive confirmation | No rerun-related destructive confirmation. Preserve the unrelated existing `Delete run` → `Confirm delete` / `Cancel` interaction unchanged. |

### Required and Forbidden Language

- Use `Start a new run` for recovery and ordinary job creation. This means navigating to `/admin/pipeline/` and creating a genuinely new run.
- Preserve `This run failed`, `Technical details`, and the distinct backend-provided ingest/parse/resolve recovery guidance.
- Do not use `Rerun`, `Re-run`, `Run again`, `Retry this job`, `Use same source`, or copy that implies the current job can be recreated in place.
- Do not display a notice that rerun was removed. Old callers receive the framework's normal `404 Not Found`; active UI contains no retired-capability message.

---

## Accessibility and State Contract

- Removing the action must not disturb existing keyboard order because no visible rerun control currently exists.
- Preserve `aria-live="polite"` on the step-card container, the failed-summary `role="alert"`, link semantics for recovery/PDF navigation, visible focus outlines, and text-plus-glyph status communication.
- Do not rely on color alone for job states; retain status labels and glyphs.
- A 404 from the retired API is an API contract, not a page-level error state. Do not add client interception or special recovery UI for it.
- Existing historical jobs must render without rerun metadata, without a null-state placeholder for rerun, and without layout gaps left by action removal.
