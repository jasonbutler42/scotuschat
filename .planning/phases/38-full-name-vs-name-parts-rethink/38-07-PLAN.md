<objective>
Close UAT gap G-38-6 at its authoritative boundary: create one canonical docket-value
rule and enforce it at the FastAPI `create_job` route so an operator-supplied docket
value can never reach the ingest subprocess (and therefore never reach
`pipeline/commands/ingest.py`'s filename construction) carrying a filesystem path
hazard or an unbounded length.

This is the load-bearing fix for G-38-6 — on its own it stops both the reported
`[Errno 22]` crash and the confirmed path-traversal / arbitrary-file-write primitive.
Plans 38-08 (pipeline-side independent hardening) and 38-09 (operator-facing feedback)
are defense-in-depth and UX layers built on the module this plan creates.

Purpose: an authenticated-admin arbitrary-file-write primitive currently exists because
`primary_docket` / `source_dockets` have no character allow-list and no length cap
anywhere between the browser and `Path("data/pdfs") / f"{primary_docket}-q{n}.pdf"`.
Output: `api/domain/docket_values.py` (canonical rule), a shared accept/reject fixture,
its unit tests, and the wired 422 guard at the `create_job` boundary.
</objective>

  <files>api/domain/docket_values.py, api/tests/fixtures/docket_value_cases.json, api/tests/test_docket_values.py</files>
  <behavior>
    - "22-915", "14-556", "71", "1955-71", "22O141", "23A994", "job-1120", "14-556-TEST-SEED", "14_556", "bananas" all normalize to themselves unchanged.
    - "  14-556  " normalizes to "14-556" (surrounding whitespace stripped, same as the existing callers already do).
    - A 64-character alphanumeric value is accepted; a 65-character one raises code length_exceeded.
    - "   " (whitespace only) and None raise code empty.
    - A value containing a double quote raises code invalid_characters.
    - "/etc/cron.d/evil" raises code invalid_characters (POSIX absolute path).
    - "C:\\Windows\\System32\\evil" raises code invalid_characters (Windows drive path).
    - "../../../tmp/evil" and ".." raise code invalid_characters (traversal segments).
    - "22-915\\evil" and "22-915/evil" raise code invalid_characters (separator inside a path component).
    - "22 915" raises code invalid_characters (embedded space — the class of value that produced the reported [Errno 22]).
    - A value containing a NUL character raises code invalid_characters.
    - "--dockets" and "-1" raise code invalid_characters (the leading character must be alphanumeric, so the domain rule independently subsumes the argv-flag class as well).
    - The verbatim string reported in 38-UAT.md Test 6 (68 characters, contains double quotes) is rejected; because it is over the length cap and the length check runs before the pattern check, its code is length_exceeded.
    - Ordering is a hard determinism contract the fixture depends on: blank check, then length check, then pattern check.
  </behavior>
  <action>
    Create `api/domain/docket_values.py` as a pure domain module with the exact same
    structural conventions as `api/domain/person_names.py`: a module docstring stating
    it has no FastAPI/SQLAlchemy/Alembic imports and must stay importable by API
    services, pipeline commands, and tests without initializing the app or a DB; then
    module-level constants, then the error class, then the public function.

    Export:
      - `DOCKET_VALUE_MAX_LENGTH = 64` — the accepted-length cap.
      - `DOCKET_VALUE_PATTERN` — the plain string literal `^[A-Za-z0-9][A-Za-z0-9_-]*$`.
        Keep it as a module-level *string* constant (not only a compiled object) because
        plan 38-09's TypeScript mirror must declare the byte-identical literal and a
        contract test asserts the two literals are equal.
      - `DOCKET_VALUE_ECHO_LIMIT = 32` — bounded-echo budget for error messages.
      - `DocketValueError(ValueError)` with a `code` attribute, constructed exactly like
        `PersonNameError(code, message)`. Stable codes: `empty`, `length_exceeded`,
        `invalid_characters`.
      - `normalize_docket_value(raw: Optional[str]) -> str` — strips `raw or ""`; raises
        `DocketValueError("empty", ...)` when the stripped value is blank; raises
        `DocketValueError("length_exceeded", ...)` when it exceeds
        `DOCKET_VALUE_MAX_LENGTH`; raises `DocketValueError("invalid_characters", ...)`
        when `re.fullmatch(DOCKET_VALUE_PATTERN, value)` does not match; otherwise
        returns the stripped value. Use `fullmatch` (not `match`) so a trailing newline
        cannot slip past the anchors — this is also what keeps Python and JavaScript
        verdicts identical for the same literal.

    Message text is owned here and nowhere else, so both enforcement layers and the
    operator-facing copy stay consistent. Bound every echoed value to the first
    `DOCKET_VALUE_ECHO_LIMIT` characters followed by a single ellipsis character when
    truncated — mirroring the T-24-10 bounded-message precedent in
    `pipeline/__main__.py::_write_early_failure`, so a multi-kilobyte submitted value
    cannot inflate a 422 body or an `admin_jobs.error_message` column.

    Why an allow-list of characters rather than a strict SCOTUS docket-shape regex such
    as the cover extractor's `\d{1,2}-\d+`: record this rationale in the module docstring.
    Post-ingest editing already accepts any non-blank docket string
    (`ArgumentUpdate.docket_number`, `MetadataUpdate.source_docket`), the ConvoKit
    historical importer legitimately writes shapes like `71` and `1955-71`, ingest itself
    generates synthetic `job-{id}` dockets, and `data/pdfs/` already holds operator-created
    files such as `bananas-q1.pdf` and `0-9999-q1.pdf`. A strict shape regex would reject
    values the rest of the system accepts and already stores; the character allow-list plus
    length cap closes the entire path-hazard class (no separator, no dot, no quote, no
    whitespace, no control character can match) without contradicting any existing
    accepted shape.

    Then create `api/tests/fixtures/docket_value_cases.json` following the shape of
    `person_name_cases.json`: a `metadata` object recording the description, `max_length`,
    `pattern`, and the documented check ordering; a `valid_cases` array of
    `{name, value, normalized}` objects; and an `invalid_cases` array of
    `{name, value, code}` objects. Cover every behavior listed above, one case per
    behavior, naming the UAT case `uat_reported_quoted_string` and carrying the reported
    string verbatim. Do NOT hand-count the 64/65-character boundary literals into the
    fixture — construct those two cases inside the test module from a repeated character
    so the boundary can never drift from `DOCKET_VALUE_MAX_LENGTH`.

    Then create `api/tests/test_docket_values.py`: load the fixture, assert
    `metadata.pattern` equals `DOCKET_VALUE_PATTERN` and `metadata.max_length` equals
    `DOCKET_VALUE_MAX_LENGTH` (so the fixture can never silently diverge from the module),
    drive every `valid_cases` entry through `normalize_docket_value` asserting the returned
    value equals `normalized`, drive every `invalid_cases` entry asserting
    `DocketValueError` is raised with the expected `code`, and add the two constructed
    length-boundary tests. Include one test asserting every raised message is no longer
    than a small bound (so the bounded-echo behavior is actually enforced, not just
    intended). No DB, no ASGI client, no network — this file must pass with no
    DATABASE_URL set, like `api/tests/test_docket_arg_safety.py` does.
  </action>

|----------|-------------|
| Admin browser → SvelteKit action → FastAPI `create_job` | Operator-typed docket strings are untrusted despite admin-token auth |
| FastAPI route → spawned ingest subprocess argv | Accepted docket values become CLI arguments and later filesystem path components |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-38-20 | Tampering | `api/routers/admin.py::_normalize_dockets` | high | mitigate | Shared `normalize_docket_value` allow-list plus 64-character cap raises 422 before job creation and before `spawn_pipeline_step`, closing the authenticated-admin arbitrary-file-write primitive at its authoritative boundary (G-38-6) |
| T-38-21 | Denial of Service | over-length docket values | medium | mitigate | 64-character cap enforced at the boundary; error messages bounded to a 32-character echo so a multi-kilobyte value cannot inflate a 422 body or `admin_jobs.error_message` |
| T-38-24 | Information Disclosure | 422 detail text | low | accept | The 422 detail echoes a bounded prefix of the operator's own submitted value on an admin-token-gated route; no server-side state, path, or credential is revealed |
| T-38-25 | Tampering | divergent copies of the rule | medium | mitigate | One canonical module (`api/domain/docket_values.py`) plus a fixture that asserts its own declared pattern and cap equal the module constants, so a second enforcement point cannot silently carry a weaker rule |
