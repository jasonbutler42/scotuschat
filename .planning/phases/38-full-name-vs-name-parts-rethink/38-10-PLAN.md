<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: Operator re-runs the UAT Test 6 reproduction on the Pipeline Runner</name>
  <what-built>
    Three layers now guard operator-supplied docket values, closing UAT gap G-38-6:
    (1) `api/domain/docket_values.py` is the single canonical rule — a docket value may
    contain only letters, numbers, hyphens, and underscores, must start with a letter or
    number, and may not exceed 64 characters; (2) the FastAPI `create_job` boundary rejects
    anything else with a 422 before an admin job row exists and before the ingest subprocess
    is spawned, and `pipeline/commands/ingest.py` independently refuses to build a filename
    or case slug from an unsafe value and asserts the resolved PDF path stays inside
    `data/pdfs`; (3) the Pipeline Runner's docket input now shows an inline error the moment
    an invalid value is added, and the SvelteKit action re-checks the submitted values with
    docket-specific copy.
  </what-built>
  <how-to-verify>
    Start the stack (Postgres, then FastAPI, then SvelteKit — `dev-start.ps1` if you use it)
    and open the Pipeline Runner at `/admin/pipeline`.

    1. Reproduce the original report. In the Docket number field, type the exact string from
       38-UAT.md Test 6 — the sentence about whether there is a limit to how long the docket
       "numbers" can be, including the double quotes — and press Enter.
       Expect: no pill is created, an inline red message appears below the input, and the
       text you typed is still in the field so you can edit it. Expect NO job to start and
       NO `[Errno 22] Invalid argument` anywhere.

    2. Try the traversal case. Clear the field, type `../../../tmp/evil` and press Enter.
       Expect: the same inline rejection, no pill.
       Then confirm nothing was written outside the PDF directory — there should be no new
       file anywhere under `/tmp` (or your platform's equivalent) and no new entry in
       `data/pdfs`.

    3. Try the absolute-path case. Type a value beginning with a drive letter and a
       backslash (for example a path into a Windows system directory) and press Enter.
       Expect: the same inline rejection.

    4. Confirm the happy path still works. Type a real docket such as `22-915`, press Enter
       to create the pill, provide a supremecourt.gov PDF URL or an uploaded PDF, and start
       the run.
       Expect: the run starts exactly as it did before, and the downloaded PDF lands in
       `data/pdfs` as `22-915-q1.pdf` (with your chosen question number).

    5. Confirm the metadata editor was left alone. Open any existing argument's edit page
       and check its docket pills render and save exactly as before — including any
       historical or unusual docket value already stored on that argument.

    6. Confirm the server-side layer. With the docket field left empty in the browser, there
       is nothing to bypass; instead simply confirm that when a run does fail for a
       non-docket reason (for example a bad PDF URL) you still get the familiar generic
       "could not start the run" message rather than docket wording.
