<objective>
Extend the existing offline importer so the historical data that is already sitting in
`data/corpus/supreme_court_justices_sections.csv` actually lands in the database: birthdate,
death date, and the reason each tenure ended. This is a straight column-to-column import
with a null-only backfill guard — not a new data-entry effort and not a derivation step.

Purpose: the popover has nothing to show without this. All three columns exist in the CSV
for every one of the 121 data rows; the importer has simply never read them.
Output: `python -m pipeline import-justices` populates all three fields, safely, repeatably.
</objective>

Add a module-level `_REASON_LEFT_CSV_MAP` dict near `_SECTION_OFFICE_VALUES`, mapping the
five recognised raw cell values to canonical values or `None`: `"Died"` → `"died"`,
`"Retired"` → `"retired"`, `"Promoted to Chief Justice"` → `"promoted"`,
`"Still in Office"` → `None` (D-02 — an open tenure has no reason), `""` → `None`
(defensive; the current file has no blank cells). Add a docstring/comment recording the
verified per-value counts from this plan's `<verified_csv_facts>` block so a future reader
can tell whether the source vocabulary has drifted.

In `run_import_justices_csv()`:

1. Alongside the existing four per-row field reads (`Judicial Oath Taken`,
`Date Service Terminated`, `Appointed by`, `Party`), read the three new columns:
`birthdate = _parse_optional_date(row.get("Birthdate", ""))`,
`death_date = _parse_optional_date(row.get("Death Date", ""))`, and
`reason_left_raw = row.get("Reason Left", "").strip()`. Note that `birthdate` must be read
per-row before the person branch runs, because the person branch consumes it.

2. Resolve the reason with an explicit **membership check**, not `.get()`:
if `reason_left_raw in _REASON_LEFT_CSV_MAP`, take the mapped value; otherwise set the
resolved value to `None`, increment a new `reasons_unmatched` counter, and record the raw
string in a `set` of unmatched values. `.get()` would make "recognised value that maps to
None" indistinguishable from "value nobody has ever seen", which is exactly the silent
data loss this project's conventions forbid.

3. In the `if person is not None:` upgrade-in-place branch, after the existing blank-only
name-part prefills, add two blank-only prefills following that identical shape:
set `person.birthdate` only when it is currently `None` and the CSV value is not `None`;
set `person.death_date` under the same two conditions. Never overwrite a non-`None` stored
value (D-06 — the same blank-only rule Phase 38 established for name parts). Do NOT touch
`name_extraction_metadata` or `name_needs_review` here.

4. In the `else:` new-person branch, pass `birthdate=birthdate` and `death_date=death_date`
to the `Person(...)` constructor (D-05 — a brand-new row always takes the CSV values).

5. Pass `reason_left=<resolved value>` to the `CourtTenure(...)` constructor in the
`if existing_tenure is None:` branch.

6. Add the currently-absent `else:` arm to that same `if existing_tenure is None:` block.
Today the existing-tenure case silently no-ops on every field. The new arm performs exactly
one write, blank-only: set `existing_tenure.reason_left` only when it is currently `None`
and the resolved CSV value is not `None`. Do not backfill `end_date`, `appointed_by`, or
`appointing_president_party` here — those are outside this phase's scope and touching them
would change established Phase 29/27 behaviour.

7. Extend the closing `print(...)` summary with the counts of fields actually backfilled
(person birthdate, person death date, tenure reason) and, when `reasons_unmatched` is
non-zero, a second printed line naming the count and the sorted set of unrecognised raw
values so the operator sees them.

Add no derivation logic of any kind: do not compare `end_date` against `death_date`, do not
detect an Associate-to-Chief transition, do not adjust which tenure row a value lands on.
The CSV's own per-row cell is authoritative (D-03). In particular, the three
`Promoted to Chief Justice` cells sit on Associate-Justice rows in the source file and must
be imported onto exactly those rows.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CSV file → database | An operator-supplied, gitignored file on local disk is read by an offline CLI that writes directly to PostgreSQL, bypassing the API's Pydantic layer entirely. |
| Importer → operator-authored data | The importer writes to columns an operator may have already edited by hand through the admin editor. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-39-05 | Tampering | `Person.birthdate` / `Person.death_date` / `CourtTenure.reason_left` (operator data) | medium | mitigate | Every backfill write is guarded by an `is None` check on the stored value, so a re-run can only fill blanks and can never destroy operator-authored data (D-06). Pinned by two explicitly-named regression tests whose RED state is observed during Task 2. |
| T-39-06 | Tampering | CSV → `court_tenures.reason_left` | medium | mitigate | This writer bypasses Pydantic, so the DB `CheckConstraint` from Plan 39-01 is the enforcement boundary. Additionally, the importer maps through a closed 5-key dict and counts anything outside it rather than passing it through — an adversarially-edited CSV cannot introduce a novel stored value. |
| T-39-07 | Information Disclosure | importer summary output | low | accept | The new summary line prints unrecognised `Reason Left` cell values to the operator's own terminal. These are historical-record strings from a file the operator supplied; no credential or PII surface exists. Accepted. |
| T-39-08 | Elevation of Privilege | `python -m pipeline import-justices` | low | accept | Unchanged posture: the pipeline is offline-CLI-only by hard constraint (CLAUDE.md) and this plan adds no HTTP surface, no route, and no API trigger for it. |
| T-39-SC | Tampering | npm/pip/cargo installs | n/a | accept | No package installs. `39-RESEARCH.md` §"Package Legitimacy Audit" records zero new packages; `python-dateutil` and `csv` are already in use by this exact file. |

No `high`-severity threat is present in this plan.
</threat_model>
