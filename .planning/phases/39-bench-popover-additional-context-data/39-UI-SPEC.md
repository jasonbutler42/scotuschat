Every public-UI component in this repo (`SpeakerPopover.svelte`, the argument page, `ChatBubble.svelte`, `StageDirection.svelte`) uses scoped `<style>` blocks and inline `style="..."` attributes driven by the CSS custom properties declared in `app/src/app.css`, not Tailwind utility classes or a shadcn preset — confirmed by direct inspection; Tailwind is installed but has zero utility-class usage anywhere in `app/src`. Phase 38's `38-UI-SPEC.md` (same repo) independently reached and documented the identical "no shadcn" conclusion. Introducing a component library for one popover enhancement would be a deviation from 38 phases of established convention — extend the existing pattern instead.

## Component and Layout Contract

### Popover structure (bench/Justice card)

Restructure `SpeakerPopover.svelte` from its current "avatar beside a single text column" flex-row into a **header row + stacked full-width sections**, so new content reads left-to-right without cramming it into a narrow column beside the avatar:

1. **Header row** (horizontal flex, avatar + name stack) — unchanged avatar treatment (60px circle, photo or initials fallback, existing `onerror` → initials logic untouched), name (16px/600), and the role/title projected as a **pill** (see below) directly under the name. This row stays horizontal at every viewport width — remove the existing `@media (max-width: 767px) { flex-direction: column }` override, since it was sized for the old cramped layout and a 60px avatar never needs to drop below a short name/pill stack.
2. **Birth/death line** (bench only, full width, below the header row) — shown only when at least one of `birthdate`/`death_date` is non-null; each half omitted independently when null (see Copywriting Contract).
3. **Bio paragraph** (bench and advocate alike, full width) — clamped with a "Read more" toggle; shown only when `bio_text` is non-null/non-empty.
4. **Advocate descriptor placeholder** (advocate only, full width, directly under the role pill, before the bio paragraph) — static placeholder text, no real data this phase (D-16).
5. **Tenure list** (bench only, full width, below bio, separated by the existing top border) — one block per tenure entry, each block three lines (office+dates / president+party / reason), ordered exactly as returned by the API (most-recent tenure first, matching current `speaker.tenure` array order — no client-side re-sort).

Order for a bench card top-to-bottom: avatar+name+pill → birth/death line → bio → tenure list. Order for an advocate card: avatar+name+pill → descriptor placeholder → bio. This matches the reviewed mockups' visual order (Rehnquist bench card, Bopp advocate card) described in `39-CONTEXT.md`'s Specifics section.

### Role/title pill

Convert the existing plain-text `role_name` line (13px muted text under the name) into a pill/badge: `display:inline-block; border:1px solid var(--color-border); border-radius:9999px; padding:2px 10px; font-size:12px; font-weight:600; line-height:1.2;` — text color and border tint follow the existing side-based tokens already used for the avatar (`var(--color-text-secondary)` `#94a3b8` for bench, `var(--color-text-advocate)` `#93c5fd` for advocate). This is a side (bench/advocate) distinction that already exists in the codebase for the avatar background — it is not a party-affiliation distinction and does not violate the apolitical constraint. Render nothing (no empty pill) when `role_name` is null, exactly as today.

### Bio text clamp + expand

- Default (collapsed) state: `-webkit-line-clamp: 3;` (`display:-webkit-box; -webkit-box-orient:vertical; overflow:hidden;`) at 14px/400/1.5 line-height, in `var(--color-text-secondary)`.
- A `Read more` text button (13px, `var(--color-text-advocate)` accent, underline, no background/border) appears directly below the paragraph **only when the bio text is actually long enough to be clamped** — do not show the toggle for short bios that fit in 3 lines. (Executor may use a `scrollHeight > clientHeight` check after mount, or simply always render the toggle if `bio_text.length` exceeds a conservative character threshold — either approach is acceptable; the important contract is that a short bio never shows a "Read more" link with nothing to expand.)
- Clicking `Read more` toggles a local `$state<boolean>` (mirrors the existing `showInitials` idiom already in this file), removes the clamp, and reveals the full text inline (no modal, no navigation, no animation — instant show/hide, respecting `prefers-reduced-motion` trivially since nothing animates). The button label becomes `Show less` and re-applies the clamp on click.
- `aria-expanded` on the toggle button reflects the current state; the paragraph itself needs no `aria-live` (a manually-triggered content reveal, not an async update).

### Multi-tenure list layout (Pitfall 6 resolution)

- Widen the card slightly to reduce total wrapped-line height: `min-width: 300px; max-width: 400px;` (up from the current 280–360px), full width available for tenure/bio text now that it is a stacked full-width section rather than a narrow column.
- Each tenure block is 3 lines at 13px/400/1.5, separated from the next block by `16px` margin (no divider rule between individual tenure blocks — the existing single `border-top` above the whole tenure section is sufficient framing; adding a rule per entry would visually fragment a 2-entry list unnecessarily).
- Safety backstop for the rare 3+-tenure case (returning Justices are historically rare but exist): apply `max-height: min(560px, 80vh); overflow-y: auto;` to the **`Popover.Content` wrapper** in `app/src/routes/cases/[slug]/arguments/[id]/+page.svelte`, not to `.popover-card` itself — this keeps the card's own border/padding intact and only introduces scrolling when content genuinely exceeds a sane popover height. Do not truncate or hide any tenure rows to avoid the scroll case; every tenure the API returns must render.

### Advocate descriptor placeholder (D-16)

- Render unconditionally for every advocate speaker (not conditionally hidden), directly beneath the role pill, at 13px/400, italic, `var(--color-text-secondary)`.
- Copy: exactly `Coming soon` — reusing the identical string already established in this codebase for other not-yet-wired fields (the two disabled admin-editor inputs this same phase activates use `placeholder="Coming soon"`). Do not invent plausible-looking placeholder data (e.g. a fake city/title) — an obviously-generic, already-precedented string avoids implying this is real per-advocate data before the extraction pipeline exists.

### Field omission rules (no data → no line, never a "N/A"/"Unknown" placeholder)

Consistent with the apolitical framing constraint's "identical treatment, no differential emphasis" and this codebase's existing convention (`role_name` is only rendered `{#if speaker.role_name}` today):

| Field | When null/missing | Rendered as |
|-------|--------------------|-------------|
| `birthdate` | null | Omit "b. …" segment; if `death_date` also null, omit the whole birth/death line |
| `death_date` | null | Omit "d. …" segment only (living Justice — the common case) |
| `bio_text` | null/empty | Omit the entire bio paragraph and its toggle — no "No bio available" placeholder |
| Per-tenure `appointed_by` | null | Omit the president/party line entirely for that tenure (do not show "Unknown · {party}" or "{president} · Unknown") |
| Per-tenure `appointing_president_party` | null but `appointed_by` present | Show `{appointed_by}` alone on that line, no trailing separator |
| Per-tenure `reason_left` | null | Omit the reason line entirely — applies both to open tenures (`end_date` null, expected) and the 2 historical rows with a genuinely blank CSV value (never render "Unknown reason") |

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Role/title pill | 12px | 600 | 1.2 |
| Metadata line (birth/death, tenure office+dates, president+party, reason) | 13px | 400 | 1.5 |
| Bio paragraph, Read more/Show less toggle | 14px / 13px (toggle) | 400 | 1.5 |
| Speaker name | 16px | 600 | 1.2 |

Exactly four sizes (12/13/14/16), two weights (400 regular, 600 semibold) — matches this project's existing established scale (same four sizes locked in Phase 38's `38-UI-SPEC.md` for the admin side of the same codebase). Do not introduce a third weight or a fifth size for any new element in this phase.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0f1117` (`--color-bg`) | Page background behind the popover |
| Secondary (30%) | `#1e293b` (`--color-surface`) with `#334155` (`--color-border`) border | Popover card surface, tenure-block top divider, role pill border (bench) |
| Accent (10%) | `#93c5fd` (`--color-text-advocate`) | `Read more`/`Show less` toggle text, advocate avatar/pill border, focus-visible outline (existing global rule) |
| Destructive | Not used this phase | No destructive action exists in the public popover; the app's existing `#ef4444` token is untouched |

Accent reserved for: the bio expand/collapse toggle and the pre-existing advocate side-accent (avatar background + new pill border) only.

**Apolitical rendering contract (hard constraint, verified explicitly at Dimension 3 review):**
- The appointing president's party ("Republican"/"Democratic"/etc.) renders in the same neutral `var(--color-text-secondary)` (`#94a3b8`) as every other metadata line, for every Justice, regardless of which party it names. No color-coding, no red/blue mapping, no bold/emphasis difference by party value.
- The three `reason_left` display strings (`Retired`, `Died in office`, `Promoted`) render in that identical neutral color too — no color or weight differentiation by which reason applies (e.g. no red for "Died in office").
- The role/title pill's bench-vs-advocate accent (slate vs. blue) is a **side** distinction that already exists in this codebase pre-Phase-39 (avatar background color) — it is not, and must never become, a per-party or per-Justice distinction.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | None added this phase — the popover remains a read-only informational card, no new action/button beyond the bio toggle |
| Reason-left: died | `Died in office` |
| Reason-left: retired | `Retired` |
| Reason-left: promoted | `Promoted` |
| Birth/death line format | `b. {short month} {day}, {year}` and, when known, ` · d. {short month} {day}, {year}` — e.g. `b. Oct 1, 1924 · d. Sep 3, 2005`, matching the reviewed Rehnquist mockup exactly. Use `Intl.DateTimeFormat('en-US', { month: 'short', day: 'numeric', year: 'numeric' })`; this intentionally differs from the case-header's full-month `formatDate()` helper on the same page — the compact form exists specifically for the tighter popover card and is not meant to replace the header's format. |
| Tenure office+dates line | `{office title} — {start year}–{end year or "present"}` (unchanged from current code — `officeTitle()` projection, year-only granularity) |
| Tenure president+party line | `{appointed_by}` alone, or `{appointed_by} · {appointing_president_party}` when both known. Render `appointed_by` exactly as stored — do not parse/truncate it to a surname-only form; no new name-parsing logic is introduced by this phase (mirrors D-03's "no derivation" posture applied to display, not just data). |
| Bio expand toggle | `Read more` (collapsed) / `Show less` (expanded) |
| Advocate descriptor placeholder | `Coming soon` (italic, see Component contract above) |
| Empty state | Not applicable — every new field is independently omitted when null (see Field omission rules); there is no card-level "no data" state to design copy for |
| Error state | Not applicable — no new network call is introduced (all data arrives with the existing page load); the existing photo `onerror` → initials fallback is unchanged and needs no new copy |
| Destructive confirmation | Not applicable — no destructive action exists in this phase |

Use sentence case throughout, consistent with the existing popover (`Chief Justice`, `Associate Justice`).

## UI Considerations

Applicable state considerations resolved: 7 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | tenure list (list-collection) | ✅ covered | A Justice with zero tenure rows renders no tenure section at all (existing `{#each}` over an empty array already produces nothing); no "no tenure data" placeholder is added |
| empty | photo (media) | ✅ covered | Unchanged existing behavior — missing/broken photo falls back to initials circle |
| loading | popover overall (interactive-control) | ✅ covered | Dismissed — no async fetch happens after the popover opens; all speaker data is already present in page data from server load, exactly as today |
| error | photo (media) | ✅ covered | Unchanged existing `onerror` → `showInitials` fallback |
| error | reason-left / office display-title lookup (static-content) | ✅ covered | Degrades to omitting the affected line rather than crashing the popover, mirroring the existing `office_title()`-style `except KeyError: return None` backend pattern (RESEARCH.md Security Domain) |
| populated | tenure list (list-collection) | ✅ covered | Documented layout for the common 1–2 tenure case (Component and Layout Contract) |
| partial | bench card (form-like static content) | ✅ covered | Field omission rules table covers every combination of missing birthdate/death_date/bio_text/appointed_by/party/reason |
| overflow / long-text | bio paragraph (static-content) | ✅ covered | 3-line clamp + Read more/Show less toggle |
| zero-one-many | tenure list (list-collection) | 🧪 backstop | 3+ tenure case has no dedicated automated test in this repo (no frontend test framework exists per RESEARCH.md); the `max-height`+scroll backstop on `Popover.Content` is a documented visual safeguard, verified only by manual UAT against at least one multi-tenure Justice (e.g. Rehnquist, 2 tenures) — a true 3+-tenure case should be spot-checked if a convenient real example exists, otherwise this remains a backstop assumption |
