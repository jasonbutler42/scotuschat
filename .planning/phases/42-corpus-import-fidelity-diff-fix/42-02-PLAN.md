<objective>
Build the purpose-built fixture delete routine that makes the CORPUS-14 fix-then-reverify
cycle possible, and prove the full round trip (delete → re-import → identical state)
before any importer fix is written.

Purpose: corpus import is idempotent-SKIP, not idempotent-upsert. `_import_conversation`
returns early on an existing `oyez_transcript_id` match, so re-running the importer after
a fix silently no-ops. The one existing delete path,
`api/services/admin_arguments.py::delete_argument`, returns `False` for any argument whose
status is not DRAFT, and every corpus-imported argument starts at `status=pipeline`. So
neither existing code path can clear this fixture. Without this routine, CORPUS-14's
"verified by re-importing the fixture cleanly" is unachievable.

Output: `scripts/delete_fixture_argument.py`, its test coverage, and a demonstrated
round trip that leaves the fixture back in the database in its original shape.
</objective>
