- [ ] CONSTRAINT: dev-server-network-split — Dev tooling run through this WSL-based session lands processes in WSL's network namespace; anything launched via `powershell.exe`/a Windows `.exe` lands in Windows' namespace. The two cannot reach each other over `localhost`. — Always start BOTH the FastAPI backend and the SvelteKit frontend as native Windows processes via `powershell.exe -NoProfile -Command "Start-Process -FilePath ... -WindowStyle Hidden -RedirectStandardOutput ... -RedirectStandardError ..."`, never via plain WSL bash `npm run dev` / `python -m uvicorn`. Verify reachability with `powershell.exe -NoProfile -Command "Invoke-WebRequest ..."` against `127.0.0.1` (not `localhost` — a DNS quirk on this box makes `localhost` unreachable from PowerShell even when the server is healthy; `curl` from WSL cannot reach a Windows-native listener at all). Note: a one-shot process invoked directly via `.venv/Scripts/python.exe` from WSL bash (e.g. running pytest) is NOT subject to this split — WSL interop launches it as a real Windows process, so its outgoing DB connections work fine without a powershell wrapper. The split only bites long-running LISTENERS (dev servers) being reached cross-namespace.
- [ ] CONSTRAINT: rushed-fix-introduces-new-regression — Every fix in this session's earlier rounds that was written from a guess (rather than from having read the actual relevant code end-to-end first) either missed the real root cause or introduced a new, different regression the operator then had to catch live. ## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| WSL/Windows network split | A long-running process started via plain WSL bash and one started via `powershell.exe` live in different network namespaces and cannot reach each other over `localhost`. A one-shot Windows `.exe` invoked directly from WSL bash (pytest via `.venv/Scripts/python.exe`) is unaffected — WSL interop runs it as a real Windows process. | blocking | Always launch both dev servers as native Windows processes via `powershell.exe -NoProfile -Command "Start-Process ..."`; verify with `Invoke-WebRequest` against `127.0.0.1`, never `localhost`, never `curl` from WSL. |
| Ambiguous `side='UNKNOWN'` | `ArgumentParticipant.side` defaults to `SideEnum.UNKNOWN` at the DB level, AND an operator's own "confirm generic Advocate, no specific role yet" action (`confirmSide`) also writes the literal string `'UNKNOWN'`. There is no way to distinguish "never touched" from "explicitly confirmed as generic advocate" from the stored value alone. | advisory | Any new logic that gates on `side` must treat this ambiguity as unresolvable from `side` alone — look for a second signal (e.g. `person_id != null`) before treating `UNKNOWN` as confirmed. See `sideGateConfirmed`'s seeding logic in commit `2be6f8aa` for the established pattern. |
| Two-phase person matching | A person pick in the Resolved-As dropdown (`rowMatchStates[label].personId`) is CLIENT-SIDE ONLY — it does not write to `ArgumentParticipant.person_id` until the batch `?/resolve` submission commits all rows at once. Anything reading `row.person_id` / `row.bench_role` / `row.missing_tenure` (server props) will not reflect a live, uncommitted pick. | resolved | Closed this round by the tenure-preview endpoint (`GET /api/admin/jobs/{job_id}/people/{person_id}/bench-role-preview`) + `benchRolePreview` client state in `ResolveCard.svelte`, guarded so a preview is only trusted when it matches the row's *current* pick (see `benchRoleState`'s `preview?.personId === personId` check). |
| Untyped `discrepancies` JSON | `AdminJob.discrepancies` is `Optional[list[dict]]` with no Pydantic sub-schema and no DB-level JSON schema — new keys can be added to pipeline-built discrepancy dicts with zero migration. But `pipeline/tests/test_import_convokit_adminjob.py` has an exact `set(d.keys()) == expected_keys` assertion that WILL break the moment a new key is added there, and must be updated in the same change. | advisory | When adding a new field to a discrepancy dict, grep for `expected_keys`/`set(d.keys())` in the test suite before considering the change done. Not touched this round (the tenure-preview endpoint reads `CourtTenure`/`Argument`, not the discrepancy blob). |
