<objective>
Fix the one genuine backend behaviour bug the reconciliation surfaced — a bench write silently
destroying the stored descriptor — and lock the one behaviour the reconciliation flagged as its
largest correctness risk but which research proved already correct: live tenure-derived bench roles on
every read, including for published arguments.

Purpose: these are the only two service-layer concerns in the 44-05..44-09 set, and neither touches
`ResolveCard.svelte`, so this plan runs in parallel with the structural rework in 44-05. The
descriptor fix has to be a write-path change, not a render change: `44-05-RESEARCH.md` traced
`api/services/admin_jobs.py:820` and found the descriptor column is overwritten with null the first
time an operator toggles a row to Bench, so the value is already gone from the database by the time
any UI rule could hide it. The tenure work is deliberately a regression test rather than a fix —
research verified both read paths already issue a fresh `court_tenures` query per request and call the
identical helper, so the risk here is a future change silently introducing a snapshot, not today's
behaviour.

Output: a write path that omits the descriptor column on a bench write, an inverted test that says so,
and a new DB-gated regression file proving a post-publication tenure correction reaches both read
paths.

Decisions implemented:
- RESOLVE-13, server half (44-FIGMA-RECONCILE.md canonical point 6, diff row 7) — the stored descriptor is preserved, not wiped, when a row switches to Bench — Tasks 1 and 2. The client half (suppressing the bench descriptor hint line) is 44-08's Task 2.
- RESOLVE-11 (canonical point 5, diff row 9) — bench role and missing-tenure state are live-derived on every read, identically on both paths, including for published arguments — Task 3. The `Edit person` new-tab markup half is 44-08's Task 1.
- Supersession recorded, not an oversight: this reverses Phase 25's PJOB-15 decision that a bench row must never carry an advocate descriptor. PJOB-15's *display* intent survives (the read path still reports null for bench rows); only its destructive storage half is reversed.
</objective>

## Deltas resolved here (reconciliation-doc gaps, not re-asks)

1. **Does the read path need changing too?** Diff row 7 says "keep stored value, don't render on
   bench, don't wipe on advocate→bench" and asks the plan to verify the save path. Verified while
   planning: `list_resolve_rows_for_job` already hard-codes `descriptor: None` and
   `descriptor_hint: None` for every bench row, and returns `participant.descriptor` for non-bench
   rows. So "don't render on bench" is already true at the API layer and "keep stored value" becomes a
   pure write-path change. Resolution: do not touch the read path or its docstring's PJOB-15 note —
   that note describes the read behaviour, which stays correct.
2. **Which bench test inverts.** `test_admin_jobs_phase25.py` has two bench-descriptor tests. The
   first sends `descriptor=None` on a bench write and asserts null comes back — that assertion holds
   under preservation too (nothing was there to preserve), so it stays. Only the second, which sends a
   real descriptor on a bench write and asserts the service discards it, encodes the reversed rule.
   Resolution: invert exactly that one, and extend it with the round-trip the requirement actually
   describes.
3. **What "no code change needed" means for RESOLVE-11.** Research's Pitfall 1 warns that a task
   phrased as "make bench_role recompute live" will find nothing to fix and risks an executor adding
   a cache to show progress. Resolution: RESOLVE-11's service-layer work in this plan is a
   regression test only, and that is stated in the task name. The one RESOLVE-11 *code* change in the
   whole set is the `Edit person` link's new-tab attributes, which belongs with the other markup work
   in 44-08.
