<objective>
Make the operator's remaining work visible at all times, and mark which rows the machine guessed at
versus which rows are waiting on a human.

Purpose: these are the last two items in the reconciliation and the only two that add something rather
than change something. Both are pure client-side derivations over data the card already holds — the
review set is the discrepancy list and the per-row state is `rowMatchStates` — so no fetch, prop, or
endpoint is added. Sequencing them last is deliberate: the row cue tags replace the disclosure the
Corrected banner used to provide before 44-05 deleted it, and both features depend on the single
`personId` predicate that 44-05's state-machine deletion left as the one source of truth for "is this
row reviewed".

Output: a persistent header progress line, an always-visible Continue button that states why it is
disabled, per-row `AUTO-MATCHED` / `NEEDS YOU` tags, and operator sign-off on the whole reconciled card.

Decisions implemented:
- RESOLVE-15 (44-FIGMA-RECONCILE.md canonical point 8, diff row 11) — persistent `N of M` progress plus an always-visible, reason-disabled Continue — Task 1.
- RESOLVE-16 (canonical point 9, diff row 12) — `AUTO-MATCHED` / `NEEDS YOU` row cue tags — Task 2.
- Closes the disclosure gap 44-05's threat register recorded as T-44-19: the Corrected banner's job of distinguishing a suggestion from a decision moves to the row cue tag.
</objective>

## Deltas resolved here (reconciliation-doc gaps, not re-asks)

1. **Copy at zero remaining.** Canonical point 8 gives `N of M speakers still need review` but not what
   the line says once N reaches zero. Resolution: `All M speakers reviewed`. Leaving the countdown copy
   at `0 of M …` would read as a stuck state at the exact moment the operator has finished.
2. **The empty review set.** A paused job can have an empty discrepancy list, which the existing WR-04
   rule already treats as fully resolved so Continue still renders. Resolution: the progress line
   renders only when the review set is non-empty; the Continue button renders whenever the job is
   paused, enabled. A line reading `All 0 speakers reviewed` would be noise.
3. **Tag colour tokens.** The reconciliation names the tags but not their colour. Resolution:
   `NEEDS YOU` uses the existing warning token and `AUTO-MATCHED` uses the existing muted token. The
   accent token is not used: the UI-SPEC reserves it for interactive elements and states it is never
   used for non-interactive text, and a tag is non-interactive. This keeps the palette guard green with
   no new hex value.
4. **Which state wins when a row is both gated and carries a suggestion.** A suggested-but-not-auto-resolved
   row is still behind the side gate. Resolution: the needs-attention case is checked first, so such a
   row reads as needing the operator rather than as already handled. Mutual exclusivity comes from the
   check order, not from a separate guard.
