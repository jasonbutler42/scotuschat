Vite's own troubleshooting documentation names this exact configuration as the cause of WSL2 HMR unreliability and recommends relocation as the fix, with polling as the fallback. Uvicorn's `watchfiles` backend documents the same class of problem and the `WATCHFILES_FORCE_POLLING` escape hatch.

    This is 46-RESEARCH.md's Open Question 1 and Assumption A3. 46-CONTEXT.md's D-01 decided to move *processes* WSL-native but never discussed moving the *repository*, so this is genuinely undecided rather than settled — and it is the difference between "reload sometimes lags" and "reload reliably fires", which is squarely the friction this phase exists to remove. Deciding it silently in either direction would be the planner overstepping.

    Note the interaction with 46-CONTEXT.md's Deferred Ideas: a full stack rework was explicitly deferred. Relocation is smaller than that but larger than D-01 describes, and it changes how Windows-side editors and tools reach the files.
  </context>

      <name>Polling flags, repository stays on /mnt/c (recommended default)</name>

      <cons>Costs some CPU (both watchers poll rather than receive inotify events). Reload latency stays higher than on native ext4. Does not eliminate the root cause — 46-RESEARCH.md is explicit that this treats the symptom.</cons>

  <action>
Create `scripts/dev-start.sh`, executable (`chmod +x`), with a `#!/usr/bin/env bash` shebang and `set -euo pipefail`. Derive `REPO_ROOT` from `BASH_SOURCE` so the script works from any working directory, and `cd "$REPO_ROOT"` before doing anything else. Support three invocations: no arguments (start), `--stop`, and `--help`; reject any other argument with a usage message and exit 2. Put a top-of-file usage comment mirroring the convention in the current PowerShell script.

Implement these functions and call them in this order for the start path.

`resolve_win_host_ip` — runs `ip route show default | awk '{print $3}'`, assigns the result to `WIN_HOST_IP`, and exits 1 with an error on stderr if empty. Never read `/etc/resolv.conf`; never accept a cached or hardcoded address.

`sync_env_db_host` — reads the host component of `DATABASE_URL` and `TEST_DATABASE_URL` from `.env`. If a host already equals `WIN_HOST_IP`, do nothing. If it differs AND matches the WSL2 NAT private-range pattern `^172\.(1[6-9]|2[0-9]|3[01])\.`, copy `.env` to `.env.bak`, rewrite only the host component of those two variables in place with `sed`, and print a single line naming the old and new address — never print the surrounding DSN, which carries a password. If it differs and does NOT match that pattern, refuse: print an error explaining that the configured host does not look like a WSL2 NAT gateway, that the script will not rewrite a `.env` pointing somewhere unexpected, and exit 1. Honour an opt-out: when `SCOTUS_DEV_NO_ENV_SYNC` is set to a non-empty value, skip the rewrite entirely and only warn on mismatch. This function embodies the project's established "derive, compare explicitly, refuse loudly rather than silently proceed" convention from `scripts/provision_test_db.py`.

`probe_postgres` — a bash `/dev/tcp` reachability probe against `$WIN_HOST_IP:5432` wrapped in `timeout 5`, since this distro has no `pg_isready`. On failure, exit 1 with an error that enumerates all three independent gates by name — the `postgresql-x64-18` service being running, a `pg_hba.conf` host rule covering the WSL subnet, and a Windows Firewall inbound rule for TCP 5432 — because 46-RESEARCH.md Pitfall 4 records that all three fail with an identical symptom. Reference `.planning/phases/46-dev-environment-reliability/46-WINDOWS-POSTGRES-SETUP.md` in the message.

Activate the virtualenv by sourcing `"$REPO_ROOT/.venv/bin/activate"`, erroring out with a pointer to plan 46-02's venv creation if it is absent. Then run `alembic upgrade head`, and on non-zero exit print an error naming `DATABASE_URL` and Postgres reachability and exit 1 — the same fail-fast shape the PowerShell script uses today, and the ordering CLAUDE.md's sole-DDL-authority rule requires (migrate before the API starts).

Ensure `npm` is available: if `command -v npm` fails, source `${NVM_DIR:-$HOME/.nvm}/nvm.sh` when it exists and re-check; if it still fails, exit 1 with an error. This matters because the PowerShell wrapper invokes the script non-interactively, where nvm's PATH additions are not present.

`mkdir -p .dev-logs`. Export `WATCHFILES_FORCE_POLLING=true` for the uvicorn child only (unless Task 1 selected option-c, in which case omit this export) — set it in the script's environment, never in `.env`, because 46-RESEARCH.md classifies it as runtime tool config rather than application settings.

Launch both services with `setsid` so each becomes its own process-group leader, redirecting stdin from `/dev/null` and stdout/stderr to separate files under `.dev-logs/`. The API: `setsid uvicorn api.main:app --host 0.0.0.0 --port 8000 --reload --reload-exclude '.claude/worktrees/*' --reload-exclude '.planning/*' --reload-exclude '.dev-logs/*'`, capturing `$!` as `API_PGID`. The `--host 0.0.0.0` binding is required so the Windows-side browser can reach the WSL-native server; the `--reload-exclude` entries address the stray-worktree reload churn named in 46-CONTEXT.md. The frontend: `setsid bash -c 'cd app && npm run dev'`, capturing `$!` as `APP_PGID`. Capturing the process-group id rather than a bare PID is load-bearing — `uvicorn --reload` forks a reloader child and `npm run dev` forks vite, and killing only the parent orphans them, which is precisely the untraceable-listener failure mode this phase exists to eliminate.

`wait_for_http <url> <label>` — polls with `curl -sf --max-time 2` once a second up to 30 times, returning success on the first 200 and failing with a message that names the label and points at the matching `.dev-logs/` file. Call it for `http://127.0.0.1:8000/health` after the API launch and `http://127.0.0.1:5173/` after the frontend launch. No `sleep N` guesses anywhere — 46-RESEARCH.md lists that explicitly as an anti-pattern.

`cleanup` — sends `TERM` to each captured process group with the negative-PID form, waits briefly, then sends `KILL` to any group still alive, tolerating already-dead groups. Register it with `trap cleanup INT TERM EXIT`. Register the trap before the first `setsid` launch so a failure during health-check polling still tears down whatever already started. After both health checks pass, print a ready banner naming both URLs and how to stop, then `wait`.

`stop_ports` (the `--stop` path) — for TCP ports 8000 and 5173, find owning PIDs with `ss -ltnpH` and parse the `pid=` field, `TERM` then `KILL` each, and report exactly what was terminated. Exit 0 when nothing is listening, printing that nothing was found. This gives the operator a deterministic answer to "what is holding this port", which was the concrete failure that motivated D-01.

Then replace the body of `scripts/dev-start.ps1` with a thin wrapper: compute the repository root from `$PSScriptRoot`, then invoke `wsl.exe --cd "$RepoRoot" -- bash ./scripts/dev-start.sh @args` so `--stop` and `--help` pass through, and propagate `$LASTEXITCODE` as the script's exit code. Keep a top-of-file usage comment, updated to state that the real implementation is the bash script and that the stack now runs WSL-native against the Windows PostgreSQL service. Remove the portable-cluster start block, the PowerShell job launches, and the `Receive-Job` loop — none of that has a role once the bash script owns the lifecycle.

Finally, add two entries to `.gitignore` under a clearly labelled comment: the `.dev-logs/` directory the script writes (it currently contains untracked API and frontend logs that could carry DSNs or tokens from server output) and the `.env.bak` file `sync_env_db_host` creates (a copy of a secrets file). Do not reorganise the rest of `.gitignore`.
