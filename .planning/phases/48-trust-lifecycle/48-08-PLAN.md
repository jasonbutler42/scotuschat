<objective>
Give the operator a way to see why a publish was blocked and to deliberately override it,
on the page that already exists.

Purpose: without this the gate is a dead end. An uncertain argument would be unpublishable
through the app with no recourse, and the operator would see only a generic "Could not
publish this argument. Try again." — the least actionable possible response to a deliberate,
reasoned block. D-19 makes this the only frontend work in the phase.

Output: a branching publish action, a block-reason panel with an override field on the
Status card, and a static source contract locking both.
</objective>

| admin browser -> SvelteKit server action | Form data crossing into a server-side fetch; the action holds the admin token, the browser never does |
