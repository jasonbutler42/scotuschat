<planner_decisions>
**D-31b — the authority ladder's return shape: a three-way `WriteDecision` enum, not a boolean pair.**
D-31b left this to the planner with one hard constraint (a single accept/reject boolean is insufficient, because D-16 requires a discrepancy even on outright rejection). The three-way enum is chosen because all three outcomes are genuinely reachable and the fourth combination is one that must never exist:
- `ACCEPT` — the values agree after normalization (or the stored side is empty). Write, no record.
- `ACCEPT_AND_RECORD` — the incoming value strictly outranks the stored one and they differ. Write, and record the discrepancy so the overwritten value survives somewhere.
- `REJECT_AND_RECORD` — the incoming value ranks equal-or-lower and they differ. Keep the stored value, record the disagreement (D-16, and REVIEW-02's core rule).
A `(accepted, should_record)` tuple would make `(False, False)` — reject silently — expressible, which is exactly the behavior D-16 forbids. The enum makes it inexpressible, and it mirrors `derive_tier`'s one-enum-out shape rather than diverging from the module family's discipline.

**`decide_write` is field-agnostic; the caller decides what "differs" means.**
Normalization is field-specific (name parts have their own normalizer; `side` and `person_id` do not), so `decide_write` takes a `values_differ: bool` the caller computes. This keeps `api/domain/authority.py` pure, dependency-light, and exhaustively testable as a rank×rank×differ matrix, and keeps the REVIEW-01/encoding contract in one named helper at the call site.

**Service-level commit ownership (carried from 49-01).** RESEARCH's "the caller commits" claim is contradicted by the source: `publish_argument`, `update_participant_side`, `update_resolve_row_for_job`, and `update_person` each call `db.commit()` themselves. The rule this plan follows: **the public service entry point commits exactly once at the end; `apply_participant_value_change` / `apply_person_value_change` / `record_value_discrepancy` / `close_open_discrepancies` are composable helpers and MUST NOT commit.**
</planner_decisions>
