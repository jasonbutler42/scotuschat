<planner_decisions>
**The rename stops at operator-facing COPY. It does not touch the API schema, the service vocabulary, or any wire code.** Stated explicitly because 49-UAT.md's G-49-4b asked for the call to be made and justified:

- `no_constituents` is a **wire code**, not copy. `api/services/trust.py:152` emits it; three SvelteKit files consume it (`review/+page.svelte:209`, `arguments/+page.svelte:155`, `arguments/[id]/+page.svelte:104`); four test modules assert it, two of them from Phase 48 (`test_phase48_list_publish_override_ui_contract.py:169`, `test_phase48_publish_override_ui_contract.py:140`). The operator never sees the code — `blockerSentence` renders it as the prose "this argument has no utterances yet". So renaming it costs a nine-site cross-phase contract change and buys zero operator-visible improvement.
- `ReviewQueueConstituent` and the `constituents` response field are **admin-only internal API symbols**. `api/tests/test_trust_public_leak_ban.py` names `ReviewQueueConstituent` in four places as the D-34 false-green guard — the guard's entire job is to prove that the admin schema DOES carry `review_state` while every public model does not. Renaming a symbol a security guard keys on, for a vocabulary preference, is the wrong trade.
- The project already tolerates internal vocabulary that differs from display vocabulary, deliberately: `SideEnum.ADVOCATE` carries the comment "legacy — never remove (PG cannot drop enum values)" and `argument_status`'s `'pipeline'` value is dead-but-permanent. Internal-vs-display divergence is an established, documented condition here, not a new compromise.

The residual risk of stopping at copy is that the word survives in the codebase and can leak again. That is what the per-line source gate in Task 1 and Task 2 is for: it exempts comments, the wire code, and property accessors, and fails on anything else.

**The chosen labels are `Edit pipeline run` and `Edit argument`, branching on the same `admin_job_id !== null` test the href branches on.** Derivation, not invention:
- "Edit pipeline run" is the operator's own phrasing ("Edit pipeline makes sense since it takes you to the pipeline run for it"), completed to name the destination noun exactly as `admin_job_id` implies.
- "Edit draft" was rejected by the operator: the row they were looking at read status `Candidate`, and a lifecycle-state label would have to track four statuses to stay true.
- 49-UI-SPEC.md's "Resolve speaker" is rejected too, and this is a deliberate deviation from that spec: it names a single action, but both destinations are whole pages — `/admin/arguments/{id}` has the Speakers card as one card among several — so it would over-promise on one branch and mislead on the other.
- The label helper deliberately takes the same argument shape and tests the same condition as `argumentEditHref`, and a contract test asserts that parity. That is the actual defect being closed: not "the word Edit is wrong" but "one static string was serving two destinations."

**No tracer task in this plan.** TRACER_MODE is on, but 49-01's tracer already threaded this phase's architecture end to end and every layer this plan touches is wired and shipped. A vertical slice here would be a rendered string — there is no new layer to thread and a tracer would add no information. Task ordering is by file instead, which is what actually matters for the wave assignment (49-08 must wait on this plan's release of `review/+page.svelte` and `test_phase49_review_ui_contract.py`).

**The zero-one-many rewrite copies the dashboard's shape verbatim rather than inventing a third one.** `admin/+page.svelte:353-355` already renders `data.reviewStats.total === 1 ? '1 item needs review' : \`${...} items need review\``. `attentionCountText` becomes the same shape with the same subject noun swapped in, so the two surfaces cannot disagree again.
</planner_decisions>
