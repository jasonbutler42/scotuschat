## D-35 (locked 2026-08-24, operator, during Phase 49 gap-closure execution)

**Decision, verbatim:** *"If an argument is currently published, the data for that argument is locked. If an argument is in any other state, I expect the data to be editable and have almost the exact interface."*

**Selection:** *"Converge both surfaces."*

**Author / date:** the operator, 2026-08-24, during Phase 49 gap-closure execution, at the G-49-3 checkpoint originally raised by plan 49-09.

**Status:** LOCKED. Not to be re-litigated. No task in this plan may emit a checkpoint asking it again. The three mechanisms previously offered (`deep-link`, `port-control`, `defer`) are all superseded — including `deep-link`, which the prior plan recommended.

**Consequence for `T-15-02-BENCH` — retirement on satisfaction, not relaxation.**
The threat, minted in Phase 15 (`15-02-PLAN.md:207`, Tampering, medium, mitigate: *"Service raises ValueError when side == BENCH → 422; BENCH is not operator-settable on advocates"*), is not a principle Phase 25 upheld. Phase 25 avoided the work: `25-01-SUMMARY.md:177` records that `update_resolve_row_for_job` *"is intentionally a new function/endpoint rather than an extension of admin_arguments.update_participant_side, because that existing endpoint explicitly rejects BENCH by design (T-15-02-BENCH) — reusing it would require weakening an existing security guard."* A second endpoint was cheaper than a shared control.

The guard's real concern is not *"bench must never be settable"* — the Resolve card sets it every day. Its concern is *"bench must not be settable **without the reconciliation the Resolve card performs**."* Under D-35 that concern is met at the new call site, so the guard becomes **obsolete rather than relaxed**:

1. **An explicit confirmation before a boundary crossing** — Task 3's two-step confirm, serving the same purpose as `needsSideGate`/`confirmSide`.
2. **No fabricated bench role** — the read path derives `bench_role` from a `CourtTenure` date-window lookup with NO fallback (`_bench_role_and_missing_tenure`, D-15) and reports *Missing tenure* otherwise. A reclassified advocate cannot acquire a Justice title by being reclassified; it acquires a visible warning.
3. **No silent carry of a mismatched person link** — the same read path turns a non-Justice person on a bench row into the Missing-tenure affordance plus a link to the person editor. This is RESOLVE-09's disjoint-pool concern answered by the read path rather than by a client-side clear, because this surface has no person picker to clear (see `<planner_decisions>`).
4. **The published lock from 49-09** — the strongest control, and new: a reclassification from this surface can never mutate live public data. It can only affect a candidate, draft, or unpublished argument, which must still pass the publish trust gate.

**Honest boundary of that argument:** the retirement is *strictly stronger* where the threat's impact lives (published data) and *deliberately permissive* on unpublished data, which is precisely the authority D-35 grants the operator. It is not stronger everywhere, and this plan does not claim that it is.

<planner_decisions>
**Why the extraction is a shared module and not a shared component, and exactly what moves.**
The parent direction was to prefer extracting shared logic over writing a second implementation, citing the open todo `2026-08-12-speaker-popover-frontend-duplication-cleanup.md`. Reading both cards, only part of the logic is genuinely shared:

- Extractable and pure: the five canonical side values, the `SIDE_LABEL` display map (`ResolveCard.svelte:336-343`), `specificAdvocateRole` (`:204-206`), and `sideBucket` (`:256-258`). These move.
- NOT extractable: `clearPersonOnSideBucketChange` mutates `lastSideBucket` and `rowMatchStates`; `toggleSide` / `confirmSide` / `needsSideGate` depend on `isPaused`, `row.discrepancy`, the batch form refs, and `flushSync`. These are component state and belong where they are. Moving them would be worse engineering, not better.

Extracting a whole shared *component* was considered and rejected: `ResolveCard.svelte` is 1545 lines stabilised over nine Phase 44 plans, its side control is a segmented toggle inside a batch form while the Speakers card is a one-form-per-row POST, and the operator's UAT currently passes on it. Restructuring it to consume a new component is a large, high-risk diff for no behavioural gain.

**The cost of the extraction is exactly one assertion, and I verified which one.** `api/tests/test_phase44_resolve_table_contract.py::test_side_bucket_helper_treats_all_advocate_roles_as_one_bucket` asserts `"function sideBucket(" in source` against `ResolveCard.svelte` — that single assertion breaks. Everything else survives, because it asserts CALL SITES rather than declarations: `test_phase49_cleanup_contract.py:120` asserts `lastSideBucket[participantId] = sideBucket(side);` (a call), `:1932` asserts `specificAdvocateRole(row.side)` (a call), `:989` is a NEGATIVE grep for `SIDE_LABEL` inside `sideScopedCandidates`, and the `clearPersonOnSideBucketChange` / `toggleSide` / `confirmSide` declaration assertions all target functions that stay. So the assertion is re-pointed at the new module with its contract intact, and nothing is deleted.

**Why the person-link reconciliation is a read-path answer here, not a client-side clear.**
The Resolve card clears a *pending, uncommitted* `personId` because it owns a person combobox. The Speakers card has no person control at all — its Name column is plain text (`:658-660`). There is nothing to clear. What it has instead is a *committed* person link, and the read path already reconciles it: a bench row whose person has no covering `CourtTenure` renders *Missing tenure* plus an Edit-person link, because `_bench_role_and_missing_tenure` applies no fallback (D-15). A reclassified advocate therefore lands in a visibly unreconciled state with the remedy linked, which is RESOLVE-09's concern answered in the idiom this surface actually has. Inventing a client-side clear would mean writing `person_id`, a third value column, from a surface that does not offer person selection — strictly worse.

**Why the bench one-way trap is fixed in the page and not in the service.**
`_speaker_rows` short-circuits to `(None, False)` for a BENCH participant with `person_id IS NULL` (`api/services/admin_arguments.py:288-296`), and its docstring states the reason: there is no person to flag as missing tenure data, mirroring `list_resolve_rows_for_job`'s identical handling. That is internally consistent and not a lie — `missing_tenure` is a statement about a person's tenure, and there is no person. Flipping it would overload the field, break the deliberate parity with the resolve read path, and produce the wrong operator copy (*Missing tenure* when the real problem is *no person*). `person_id` is ALREADY on `SpeakerRow`, so the page can render the correct distinct affordance with no service change and no schema change. The service and the schema keep their current contract.

**Why one row template instead of two patched branches.** Patching both sides of the `speaker.is_bench` branch to equal depth leaves two places that can drift, and the apolitical constraint would then be a convention rather than a structure. Collapsing to one template makes the constraint unfalsifiable-by-drift, and it makes the win executable: a region-scoped assertion that the Speakers row markup contains no per-class branch at all. The companion detail that genuinely differs (tenure role / missing tenure / no person) is driven by the operator's CURRENT selection rather than by the stored `is_bench`, which is also more correct — the companion should follow what the operator is choosing, not what was last saved.

**The descriptor round trip is the sharpest defect in this convergence and it is not obvious.** RESOLVE-13 means a bench write PRESERVES the stored descriptor, and the read path reports `descriptor: null` for bench rows — so the page cannot see it. Naively, a later bench→advocate move would render an empty Title input and submit an empty string, clobbering the value RESOLVE-13 protected. The service already has the correct escape: it documents that `descriptor` is written ONLY when the caller passes a non-None value, and omitting it leaves the column unchanged. So the fix is for the form action to OMIT descriptor when the row's committed side was bench. The first save then sets only the side; the row re-renders as an advocate row with its real descriptor visible; a second save can edit it. This is the same class of defect ResolveCard's `lastDescriptorValue` (`:155-165`) exists to prevent, reached by a different route, and it needs a live round-trip assertion — `test_phase44_argument_role_roundtrip.py` already proves the analogous property on the resolve path and is the model to mirror.

**Out of scope, stated loudly rather than buried: the second `is_bench` source of truth.** Admin derives bench from `side == SideEnum.BENCH`; the public chat page derives its own from `tenure.length > 0` (`app/src/routes/cases/[slug]/arguments/[id]/+page.server.ts:36`), and `api/services/speakers.py` falls through to `ADVOCATE_LABEL_MAP` when the bench branch is skipped — so a BENCH participant with no tenure reads bench in admin and **Counsel** in public. This is the open todo `2026-08-12-speakers-bench-classification-silent-fallback.md`. Reconciling it touches the public read path, outside Phase 49's boundary. **This plan makes the divergence MORE reachable**, because it turns a data accident into something an operator can produce by design. That is a real consequence of D-35 and it is recorded as an accepted threat with that sentence in it, not softened. Partial mitigation: 49-09's published lock means the divergence cannot be introduced on an already-published argument — it has to be created in draft and then published, and the publish trust gate does not currently check tenure coverage.

**No migration.** Every column read or written already exists; the guard removed and the guard added both read existing state. Alembic's sole-DDL-authority rule is not engaged. If any executor believes a migration is needed, HALT and say so rather than writing one.

**No tracer task.** 49-01's tracer already threaded this phase's architecture; every layer here is shipped.
