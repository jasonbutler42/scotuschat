  <decision>Freeze the exact field list, ordering, serialization and empty-input semantics of the D-13 utterance content digest, before any `import_run.content_digest` value is written.</decision>
  <context>
D-13 leaves the digest algorithm and its exact tuple to the planner, and states in the same breath that the definition must stay frozen once shipped — changing it later reads as a universal diff across every argument in the corpus. Every stored digest will have been produced by whichever definition ships here, so this is a one-way door and it gets an explicit sign-off rather than a code review after the fact.

**The proposed contract (PD-01):**

- Algorithm: `hashlib.sha256`, lowercase hex digest, 64 characters, stored in `import_run.content_digest` as `String(64)`.
- Input: the ordered incoming utterance rows for ONE argument, in the exact order `_import_utterances` would write them (after `_split_turn_into_rows` expansion), ascending `sequence` starting at 1.
- Per-row fields, in exactly this order: `sequence` (int), `raw_speaker_label` (str or None), `text` (str), `is_stage_direction` (bool).
- Serialization: `json.dumps` of a list of 4-element lists, `ensure_ascii=False`, `separators=(",", ":")`, no key sorting, UTF-8 encoded. JSON framing rather than a delimiter join, so a separator character inside `text` can never forge a row boundary.
- Normalization: NONE. Byte-exact. A whitespace-only change in `text` IS a content change and does trigger a rewrite. (`_values_differ`'s normalization governs authority comparisons; this governs content replacement — two different questions.)
- Empty input: an empty row list hashes to the digest of the two-byte JSON document for an empty list — a real, stable, non-empty digest, never NULL and never the empty string, so "this argument has zero utterances" is a distinguishable state rather than "unknown".
- `DIGEST_VERSION = 1`, a module constant documented as frozen.

**Deliberately EXCLUDED, with reasons:**

- `person_id` and `side` — both participant-derived and authority-governed. Including them would make an operator's participant reassignment or side edit read as a transcript-content change and trigger a full utterance-set rewrite on the next import: exactly the clobber IMPORT-04 forbids.
- `section_hint` — derived by the importer's own section state machine from resolved sides, so it inherits the same problem.
- `id`, `argument_id`, `import_run_id` — identity, not content.

This differs from 50-RESEARCH.md's `[ASSUMED]` shape (assumption A1) only by dropping `side`, for the reason above.
