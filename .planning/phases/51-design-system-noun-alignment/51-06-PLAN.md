## Testing-policy note (deliberate, not an omission)

The project Testing Policy bans static source-text contract tests for frontend behaviour. This
plan therefore does NOT assert primitive behaviour by grepping `.svelte` files. `Card` and `Input`
get real adoption sites so a real browser exercises them; `Button` and `Badge` are verified here
by typecheck plus an operator comparison against their Figma frames, and behaviourally in plans
51-08 and 51-09 where they acquire real call sites, and at the plan-51-10 UAT.

Two presence greps were deliberately REMOVED from this plan's acceptance criteria and must not be
reintroduced: a `{@render children` count on `Card.svelte`, and a `touch-target` count on
`Button.svelte`. A token name appearing twice in a source file proves nothing about a rendered
44px hit area — that is the precise shape that produced 28 green tests against a fully broken
button on this project. The snippet-API guarantee is carried instead by `npm --prefix app run
check` exiting 0, which a mixed snippet-and-slot component fails. The touch-target guarantee is
carried by the plan-51-09 backstop that checks a `Button` and a `Badge` with over-long labels
against the 44px/36px rule in a real browser, by the plan-51-09 accessibility audit, and by the
plan-51-10 walkthrough at 375px.

Absence sweeps stay, and are not the same thing: no raw hex, no numeric `font-size`, no
`--color-status-*` on a public component, no cross-surface import. Proving a forbidden literal
reaches no surface across a computed file set is exactly what source text CAN prove, and is the
narrow structural-ban exception the Testing Policy names.
</flagged_assumptions>
