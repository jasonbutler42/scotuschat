# Phase 51 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — **shadcn is not applicable to this project.** shadcn's component preset generation is built on Tailwind; D-01 removes Tailwind entirely (operator: *"I kind of hate tailwind"*). CSS custom properties are the token layer instead. |
| Preset | not applicable |
| Component library | `bits-ui` (headless primitives — already a dependency, currently used only by `SpeakerPopover`) + a new hand-rolled primitive set (`Button`, `Badge`, `Input`, `Card`) in `lib/primitives/` per D-17 |
| Icon library | **Undecided — see "Dependency Candidates (D-18)" below.** No icon library exists today; the codebase has near-zero icon usage (2 files touch an SVG/icon concept at all). Operator decision needed before Wave 1 component work. |
| Font | `system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif` — unchanged, already declared once in `app/src/app.css`, inherited everywhere via `font-family: inherit` |

### Figma & Token Architecture (D-02, D-05, D-06, D-07)

- **Figma first, code follows.** The token set and component library are designed in Figma before implementation lands. Work happens in the operator's personal "Jason Butler's team" (Full seat) — never in "Offen Petroleum Design Team" (View-only, and this is a personal project, not Offen work).
- **Figma Variables (not Styles)** hold color/space/type, because Variables export cleanly to CSS custom properties.
- **Figma pages mirror the code layout, verbatim:**

| Figma page | Code destination |
|---|---|
| `Tokens` | `app/src/app.css` `:root` |
| `Primitives` | `app/src/lib/primitives/` |
| `Public` | `app/src/lib/public/` |
| `Admin` | `app/src/lib/admin/` |

- A component's Figma name equals its file name, so drift is visible rather than silent.
- **Two-layer token architecture (D-02):** a primitive palette (raw hex, private to the token file) feeds semantic role names (what components actually reference). Only semantic names are ever written in component code — never `--color-slate-800`, always `--color-surface`.
- **Dark only, structured for light later (D-02).** Ship only dark values this phase. The two-layer structure is what makes adding a light theme later a contained addition (a second value set) rather than a rewrite — do not collapse to a flat single-layer token set.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between pills/chips/badges; tight inline flex gaps |
| sm | 8px | Label-to-input gap; gap between inline buttons; table cell horizontal padding |
| md | 16px | Field-to-field vertical margin within a card; margin between stacked cards |
| lg | 24px | Card internal padding; heading-to-content margin |
| xl | 32px | Layout gaps between major page regions (new — not yet a named token, but already implied by existing spacing math; formalize it) |
| 2xl | 48px | Page content top/bottom padding |
| 3xl | 64px | Page-level spacing for the largest public reading surfaces (new — reserved for the redesigned public listing/transcript vertical rhythm per D-09; not required for admin) |

Exceptions: touch targets — buttons and inputs are `min-height: 44px` (WCAG 2.1 AA), except compact per-row inline buttons inside dense admin tables, which stay at `min-height: 36px`. This exception is carried forward unchanged from the existing system; do not regress it during token conversion.

## Typography

D-03 locks a **tight named type scale of ~5 semantic steps**: caption / body / lead / heading / display. Today's 9 raw sizes (11, 12, 13, 14, 16, 18, 20, 28, 32px) and 3 weights (400/500/600) collapse onto this scale and 2 weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Caption | 14px | 400 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Lead | 18px | 400 | 1.6 |
| Heading | 20px | 600 | 1.2 |
| Display | 32px | 600 | 1.2 |

**Weights: exactly 2 — regular (400) and semibold (600).** No 500 anywhere at phase end.

**Collapse mapping (executor reference, not exhaustive per-instance — verify each site visually during conversion):**

| Today | Collapses to |
|---|---|
| 11px, 12px, 13px | Caption (14px) — these three were already tightly clustered meta/label sizes |
| 14px | Caption (14px) |
| 16px | Body (16px) — unchanged |
| 18px | Lead (18px) — unchanged; reserved for public reading surfaces (see below) |
| 20px | Heading (20px) — unchanged |
| 28px, 32px | Display (32px) |
| weight 500 (2 sites, both in `ResolveCard.svelte`) | weight 600 — verify visually, since 500 may have been intended as a deliberate mid-weight; if the operator disagrees on sight, it becomes a D-08 "surfaced artifact," not a silent revert |

**Where Lead is used:** Lead (18px/400/1.6) is reserved for the redesigned public reading layer per D-09 — transcript utterance body text and term-list case names on the public listing. It is not an admin size; admin draws from the small end of the scale (Caption/Body/Heading), public from the full range (Caption through Display).

**Where Display is used:** page-level titles only — an argument's case name headline on the transcript page, an October Term heading on `/arguments/term/{year}`. Not used in admin.

Any remaining stray hex values found during the D-04 inline-style conversion sweep must be mapped onto one of these primitives or explicitly flagged as a new one — never left as a bare hex in a component.

### Semantic roles — the 60/30/10 split

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-bg` = `var(--slate-950)` `#0f1117` | Page background, everywhere |
| Secondary (30%) | `--color-surface` = `var(--slate-800)` `#1e293b` | Cards, header bar, nav, table row default background |
| Accent (10%) | `--color-accent` = `var(--blue-300)` `#93c5fd` | Primary CTA buttons/borders (Save, Publish, Create), all inline/nav links, `:focus-visible` outline, active-tab indicator |
| Destructive | `--color-destructive` = `var(--red-500)` `#ef4444` | Delete buttons/borders, error text/messages, delete-confirmation copy — never anything else |

Accent reserved for: primary action buttons, links, focus rings, active nav/tab state — **never** status badges, table headers, muted text, or general emphasis. This discipline is pre-existing and must survive the token conversion unchanged.

### Additional semantic roles (outside the 60/30/10 split, but required by existing screens — carry forward, do not drop)

| Semantic token | Value | Usage |

| `--color-text-secondary` | `var(--slate-400)` `#94a3b8` | Field labels, meta/secondary text, table header text |
| `--color-side-bench` | `var(--slate-400)` `#94a3b8` | Bench/justice avatar fill + side indicator only (shares a primitive with `--color-text-secondary` — pre-existing overlap, not a new decision) |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **None by design.** `/arguments` (term index) and `/arguments/term/{year}` (term detail) are pure browse/navigation surfaces per D-14 — the interaction is following a link (a term name, or an argument row), not a button-style call to action. Do not invent a "View arguments" button; a row/link IS the action. The admin refactor introduces no new CTA this phase (D-08: refactor, not redesign). |
| Empty state heading | "No arguments published yet" (renamed from today's "No cases loaded" per DS-01's noun alignment) |
| Empty state body | "Check back soon — new oral arguments are added regularly." Replaces today's "Run the ingest and parse pipeline steps to add cases," which is operator/pipeline jargon leaking onto a public-facing page — flagged as an incidental copy fix in UI Considerations below, not a new decision. |
| Empty state, term-scoped | For a real, existing term with zero published arguments (distinct from an unknown/out-of-range year, which is a genuine 404): "No arguments published for October Term {year} yet." |
| Error state | "Unable to load arguments right now. Try refreshing the page." — generic public-facing fetch failure, no technical detail (no stack trace, no HTTP status number) surfaced to the public reader. |
| Destructive confirmation | No new destructive actions this phase (D-08: admin is refactored, not redesigned). Reuse existing admin wording verbatim, only the styling migrates to tokens: "Delete argument: This action cannot be undone." |

## Dependency Candidates (D-18)

D-18 is a standing rule: identifying candidates is Claude's job; adopting a dependency is the operator's call. Present tradeoffs, do not decide.

### Icon library — needed for Wave 1 primitives (chevron/disclosure on term rows, popover close affordance, nav hamburger, admin action icons D-08 may surface)

| Candidate | Tradeoffs |
|---|---|
| **`lucide-svelte`** | MIT, ~1,500 tree-shakable Svelte icon components, actively maintained, zero CSS-framework coupling (fits post-Tailwind D-01). Matches the "one SVG per icon" shape the two existing hand-rolled icon sites already use. Adds one new dependency; each imported icon is its own small component so bundle cost scales with actual usage, not the whole set. |
| **`@iconify/svelte`** | Access to effectively every open icon set through one dynamic component. Heavier for this project's actual need (a handful of icons): the dynamic-lookup model is less tree-shakable per-icon than `lucide-svelte`'s discrete components, and pulls in a runtime resolver this project doesn't otherwise need. |
| **Continue hand-rolled inline SVG (status quo, zero new dependency)** | Consistent with today's near-zero icon footprint (2 files) and D-01's anti-bloat spirit. Scales worse if D-08's admin-refactor surfacing pass turns up many action icons across the 15 existing components — each one becomes a hand-maintained inline `<svg>` block with no shared sizing/stroke convention. |

**Non-binding lean:** if the primitives pass (`Button`, `Badge`, `Input`, `Card`) needs more than ~5 distinct icons (loading spinner, chevron, close/X, external-link arrow, checkmark), `lucide-svelte` is the better fit. Below that, hand-rolled stays proportionate. Raise this at the Wave 1 checkpoint rather than deciding silently either way.

### Popover / overlay primitives — already resolved, no new decision needed

`bits-ui` is already a dependency and already proven on `SpeakerPopover` for exactly the case D-18 names as legitimate: focus management, keyboard navigation, and ARIA state that are genuinely hard to hand-roll under the project's WCAG 2.1 AA commitment (Phase 4). Continue using it for any **new** focus-managed control this phase introduces — a disclosure/toggle on the D-16 advocate-name row variant, if the visual decision needs one, is the most likely candidate. Do not hand-roll a second focus-trap implementation.

## UI Considerations

Applicable state considerations resolved: 9 covered, 2 backstop, 1 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | `/arguments` term index (list-collection) | ✅ covered | Renders the "No arguments published yet" / "Check back soon…" copy above when zero terms have any published argument. |
| empty | `/arguments/term/{year}` (list-collection) | ✅ covered | A real term with zero published rows renders "No arguments published for October Term {year} yet." — distinct from the 404 case below. |
| error | `/arguments/term/{year}` with an out-of-range/unknown year | ✅ covered | A genuinely invalid year (e.g. before 1955 or after the latest term, or non-numeric) is a real 404, not an empty state — SvelteKit's standard error page, not the empty-state copy. |
| error | Both listing pages, generic fetch failure | ✅ covered | "Unable to load arguments right now. Try refreshing the page." — no technical detail exposed publicly. |
| zero-one-many | `/arguments` term index counts | 🧪 backstop | Each term row must read correctly at 0/1/many arguments ("1 argument" vs "12 arguments") — needs a real-browser or unit check on the pluralization helper, not a source-text grep per the Testing Policy. |
| zero-one-many | `/arguments/term/{year}` heading | 🧪 backstop | Same singular/plural requirement on the term-detail page heading. |
| overflow | `/arguments/term/{year}` row list at term scale | ✅ covered | D-14 caps any single page at ~150 rows by construction (grouped by term); no pagination widget is needed or should be designed. |
| long-text | Term-list row case name | ✅ covered | Consolidated-case names (multiple parties joined by "v.", "et al.") must wrap, never truncate — the docket number is the Court's own disambiguator and must always stay visible; do not let a long case name push the docket off-screen or clip it. |
| long-text | Stage-direction / speaker-name text in the transcript reading-polish pass (D-09) | ⚠ unresolved | D-09 redesigns vertical rhythm and speaker-change emphasis but the CONTEXT.md does not specify a wrap/truncate rule for an unusually long stage direction or an unusually long full name. Planner should treat "wrap, never truncate or clip" as the working assumption (consistent with the case-name row above and the apolitical no-editorializing constraint — truncating a transcript is itself a form of altering content) unless the operator says otherwise during the Figma pass. |
| populated | Term-list row, both D-16 variants | ✅ covered | Variant A (case name + argued date + docket) and Variant B (A + advocate names) both render from `CaseItem` at typical volume; Variant B requires a join through `argument_participants` → `people` whose query cost at term scale (~150 rows/page) must be checked before it is proposed as the shipped variant. |
| populated | Admin refactor surfaces (D-08) | ✅ covered | The refactor pass must produce a running list of surviving visual/UX artifacts it encounters (not silently preserve them) — this is a process requirement, not a rendered UI state, but it gates whether the "populated, happy path" admin screens ship as-is or get a follow-up decision. |
| loading | Both public listing pages | ✅ covered | Both load via `+page.server.ts` (SvelteKit SSR), which blocks render until data is ready — no client-side skeleton/spinner state is needed or should be built for these two pages. |

## Appendix — Phase-Specific Notes for the Planner

These don't fit the fixed template shape above but are load-bearing for `/gsd-plan-phase 51`:

1. **D-11 amends DS-01.** No `/cases` → `/arguments` redirects are needed — the app has never been deployed (DEPLOY-01 is still unchecked, no deploy config exists), so "preserve every previously shareable URL" has no real URLs to preserve. The planner should strike the redirect clause from `DS-01` in `.planning/REQUIREMENTS.md` and `.planning/ROADMAP.md` and record this rationale, per D-11's explicit instruction — do not silently implement redirects nor silently leave the requirement text disagreeing with the implementation.
2. **D-16's two term-row variants are a Figma-first visual decision, not a coin flip.** The operator will not commit to Variant B (advocate names) without seeing it rendered. Both variants must exist in Figma before any `/arguments/term/{year}` code lands, and the plan should treat "which variant ships" as an operator checkpoint, not an assumption.
3. **`term` is a reserved slug word (D-13).** `Argument.slug` generation (D-12, new migration required — Alembic only) must refuse to mint a slug that collides with the literal path segment `term`.
4. **Apolitical framing applies to D-16's advocate-name variant.** Advocate names are permitted (advocates and justices get identical treatment); utterance counts, speaking time, and duration remain banned as derived statistics anywhere in this phase's UI, including any new admin surface the D-08 refactor touches.
5. **Trust-tier / review-state colors from Phases 48–49 must never appear on any public component this phase creates or restyles** — the public-leak ban (`api/tests/test_trust_public_leak_ban.py`) is the enforcement mechanism; extend its scope if a new public response model is added, never build a parallel check.
