<objective>
Flip justice identity from a `full_name` string match to a verified `oyez_speaker_id` join, end
to end, and prove it on one justice before expanding.

Purpose: This is the architectural spine of Phase 52. Every other plan in the phase depends on
the column, the index and the mapping this plan lands. The riskiest pieces — a partial unique
index with **zero in-repo precedent**, and a dedup-key flip in a 1391-line-tested importer — are
retired here first, on the executor's best early-context tokens.

Output: the verified mapping artifact, migration 0032, the importer keyed on `oyez_speaker_id`,
`speaker_name` coalescing to the corpus form, and three test modules that pin all of it.

**Reversibility — `costly`, rated deliberately.** Migration 0032 was considered as a `one-way`
door and rejected as one. The taxonomy's test is whether undoing it requires a data migration or
breaks a published contract; neither holds here. The column is nullable, `downgrade()` drops the
index and the column with no data transformation, the reseed-don't-migrate doctrine means there is
no stored state to transform, and there is no external consumer whose contract breaks. What it
does cost is coordination — the Alembic chain plus every reader of `display_name` — so it is
`costly` and flagged, not gated. No `checkpoint:decision` is inserted, and none would be
appropriate even at `one-way`: JUSTICE-05 names the partial unique index as the requirement and
D-04 names `IS NOT NULL` as the predicate that lets Barrett and Jackson exist, so the door is
already chosen, and `CLAUDE.md` § Defect Policy states that re-asking a settled locked decision is
itself a defect in how the work is being done.

**Assumption-delta decision (detector fired: `pluralization` on "a second row").**
- Primary noun: **the corpus speaker identity (`oyez_speaker_id`)**, not the person's name string.
- Decision: **promote**. `oyez_speaker_id` is promoted from an unused nullable side-column to the
  primary identity key for every corpus-resolved person; `full_name` string equality is demoted to
  the fallback branch used only by people with no corpus id (D-04's Barrett and Jackson, and
  advocates). This is not add-alongside: after this plan there is exactly one preferred key, and
  `import_convokit::_resolve_person` already encodes that preference order (id first, name second)
  — this plan makes `import_justices_csv` converge on it rather than keeping two rival keys.
- Companion invariant test: `pipeline/tests/test_justice_identity_mapping.py` (Task 3) plus the
  DB-level duplicate refusal in Task 1 go red the instant a future phase reintroduces the
  name-string-as-identity assumption.

**Flagged planner assumptions (unresolved probe rows — not silently dropped):**
- **JUSTICE-02 / unclassified** — the edge probe could not classify this requirement and the
  planner did not auto-resolve it. Carried forward unresolved: the requirement is about which key

- **JUSTICE-05 / unclassified** — likewise unresolved. The partial index's behaviour is pinned by

  reported rather than invented.
