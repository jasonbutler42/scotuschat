<objective>
Move avatar initials from two byte-identical client-side string splitters to one server-side
derivation over structured name parts, and prove the `JI` -> `JH` fix in a real browser.

Purpose: JUSTICE-06 is the visible symptom; the cause is that the browser was guessing at name
structure the database already knows. D-12 removes the guess. Doing it once server-side also
makes it impossible for a third splitter to be added by accident later.

Output: `derive_initials` in `api/domain/person_names.py`, an `initials` field on
`SpeakerPopoverEntry`, a `speaker_initials` field on `UtteranceResponse`, both frontend helpers
deleted, and a real-Chromium regression test.

**Reversibility — costly (D-12's own rating), no checkpoint.** Adding a field to two public
response schemas touches the frontend contract in two places. It is not one-way: the field is
additive, optional on the utterance side, and removing it would be a local edit in four files
with no migration and no stored data. Flagged here so the weight is visible; execution proceeds.

**Testing Policy compliance.** `CLAUDE.md` forbids static source-text contract tests for frontend
*behavior* — asserting a string appears in a `.svelte` file proves a declaration exists and
proves nothing about the rendered page (28 green tests against a fully broken button, Phase 44).
JUSTICE-06's acceptance is therefore a **real-Chromium** test following the existing
`app/tests/tenure-public-title.browser.test.mjs` harness, which already spawns Vite, serves a mock
FASTAPI backend, clicks a bench speaker's avatar and asserts rendered text. The one source-text
assertion this plan does use is a **structural ban sweep** — proving the retired `getInitials`
identifier reaches no frontend file — which the Testing Policy explicitly permits, because absence
across a computed file set is exactly what source text can prove.
</objective>

  <behavior>
    - `derive_initials(first_name="John", last_name="Harlan", name_suffix="II")` returns `"JH"`.
    - `derive_initials(first_name="Oliver", last_name="Holmes")` returns `"OH"`.
    - Structured parts win: when `first_name` and `last_name` are both present, `full_name` is never parsed.
    - Fallback (D-13): with no parts and `full_name="John Marshall Harlan, II"`, the suffix token `II` is dropped and the result is `"JH"`.
    - Fallback: with no parts and `full_name="Oliver W. Holmes, Jr."`, the result is `"OH"`.
    - Single token: `full_name="Cher"` returns `"CH"` — the existing first-two-code-points behaviour, unchanged.
    - Blank/None: no parts and a blank or `None` `full_name` returns `None`.
    - Case and encoding: the result is `str.upper()` of the first code point of each NFC-normalized token; a lowercase or accented leading character is uppercased by that same call and not stripped of its mark.
    - Pure and deterministic — repeated calls on the same input return the same value, and nothing is mutated.
  </behavior>
  <action>
Add a single public function `derive_initials` to `api/domain/person_names.py`. It belongs in this
module and nowhere else, because this is where `_KNOWN_SUFFIXES` already lives and D-13's fallback
is defined in terms of that exact vocabulary — co-locating the derivation with its suffix set is
what prevents a fourth splitter appearing somewhere else later.

Signature: `derive_initials(*, first_name: Optional[str] = None, last_name: Optional[str] = None,
name_suffix: Optional[str] = None, full_name: Optional[str] = None) -> Optional[str]`. Two
branches, in this order:

1. **Structured branch.** When `first_name` and `last_name` are both non-blank after stripping,
   return the first code point of each, NFC-normalized and `str.upper()`-ed, concatenated.
   `name_suffix` is accepted and deliberately ignored — a suffix is never an initial. This is the
   branch every justice takes, because their parts come from the CSV.
2. **Legacy fallback (D-13).** Otherwise, when `full_name` is non-blank: split on whitespace after
   stripping a trailing comma from each token, drop any token whose comma-stripped form is in
   `_KNOWN_SUFFIXES`, then take the first code point of the first and last surviving tokens. One
   surviving token yields its first two code points. Zero surviving tokens, or a blank/`None`
   `full_name`, returns `None`.

Do NOT reuse `split_legacy_full_name` for the fallback: it deliberately refuses a suffix without a
leading comma, a single-part name and a particle name, and returning `None` for those shapes would
regress people who render correctly today. `derive_initials` is deliberately more permissive than
`split_legacy_full_name` because it produces a two-character display glyph, not stored name parts —
say that in the docstring so the asymmetry reads as intentional. Do not add a second suffix set and
do not widen `_KNOWN_SUFFIXES`.

Write the `<behavior>` list as tests in `api/tests/test_person_names.py` first, watch them fail,
then implement. Add the tests to the existing module rather than creating a new file.
  </action>
