<objective>
Make the bench survive a reset. `reset_to_fixture` TRUNCATEs `people` and `court_tenures` and
never puts the justices back, so the People directory reads empty after every reset; this plan
inserts the justice seed step in the one correct place and fixes the timestamp skew that shares
the function.

Purpose: JUSTICE-04 and Success Criterion 3. It is also what makes the corpus importer's
`oyez_speaker_id` lookup actually hit during a reset — without a seeded bench, `_resolve_person`
falls to its name branch and the whole phase's identity work is bypassed in the one code path the
operator exercises most.

Output: a seed step at the D-16 insertion point, a pre-flight that refuses before it destroys, a
non-skewed `created_at`, and tests that pin all three.

**Scope discipline.** D-17 puts the per-writer tier-recompute optimisation in Phase 54. Measure
the reset's duration with the seed step added and record the number in the summary; do not
optimise it here. The `speaker_alias` non-restoration documented in this module's own comments is
deliberate, separately-scoped pre-existing behaviour — do not restore it.
</objective>

  <action>
PostgreSQL's `now()` returns **transaction-start** time, so every `server_default=func.now()`
column written late in `reset_to_fixture`'s long-lived transaction carries the timestamp from when
that transaction opened. The observed result is a `draft` row inserted after a `candidate` row and
stamped 49 seconds earlier. This is a correctness defect and therefore Claude's under the Defect
Policy — fix it, report it in one line in the summary, do not raise it as a question.

Take the cheapest correct fix the todo itself names: commit the shared `db` session between the
fixture-verification loop and the state-realization block, and again between the per-fixture state
transitions, so `now()` advances for each. Do NOT wrap the whole reset in a single
session-level transaction block — the module docstring is explicit that this session boundary never extends into
pipeline's own engine, and that recovery from a partial state is re-running the reset. Do NOT
replace `server_default=func.now()` on the model columns; that would change behaviour for every
writer in the application to fix one batch caller.

Add the invariant assertion the todo names as the thing that silently broke: a test asserting
`argument_status_log.created_at` is monotonic with `argument_status_log.id` for every argument the
reset seeds. That assertion is the regression guard — without it, a future refactor that restores
one long transaction reintroduces the skew invisibly.
  </action>
