# Phase 52 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase is overwhelmingly a data-correctness phase (JUSTICE-01/02/04/05 are
schema, migration, and pipeline work with no UI face at all). Only three surfaces have a visual
delta, and all three are amendments to *existing* pages — there is no new page, no new route, and
no new design-system decision to make:

1. **Admin person detail page** (`app/src/routes/admin/people/[id]/+page.svelte`) — two new
   read-only fields in the Identity card (D-09, D-10).
2. **Admin dashboard "Dev Tools → Reset to Fixture" section** (`app/src/routes/admin/+page.svelte`)
   — amends `43-UI-SPEC.md`'s locked Interaction & State Contract and Copywriting Contract per
   D-14/D-15 (per-fixture progress, evidence-based error copy replacing the "no third variant"
   lock).
3. **Avatar initials** (`SpeakerPopover.svelte`, `arguments/[slug]/+page.svelte`, 7 call sites
   total) — JUSTICE-06 is a pure correctness fix. **Zero visual delta.** The circular avatar
   markup, its size, its font tokens, and its fallback rendering are all unchanged; only the
   *value* fed into that markup changes, from two independent client-side string-splits to one
   server-computed field (D-12/D-13). Nothing in this document governs how it looks — only that
   the input changes from `John Marshall Harlan, II` → `JI` (wrong, today) to `JH` (correct).
   No further UI-SPEC coverage is needed for this item.

Design basis: `.planning/codebase/DESIGN-SYSTEM.md` (current as of the Phase 51 token
conversion — read in full before implementing; not re-derived here) and
`.planning/milestones/v1.7-phases/43-dev-only-reset-to-fixture/43-UI-SPEC.md` (the contract
being amended). `52-CONTEXT.md` D-09 through D-17 are the locked decisions this spec operationalizes.

## Layout & Placement Contract

### Admin person page — two new read-only fields (D-09, D-10)

Placed inside the existing Identity card (`app/src/routes/admin/people/[id]/+page.svelte`),
**immediately below the existing Full Name `<output>` readout and above the editable Name Parts
inputs** (First/Middle/Last/Suffix). This groups "generated, read-only" outputs together before
the operator reaches editable fields — the same ordering principle the Full Name readout already
establishes.

Each field is its own row using the **identical markup and box treatment as the existing Full
Name readout** (`<output>`, `aria-labelledby` pointing at a label span + explanation span,
`aria-live="polite"`, same border/background/padding/border-radius): a caption-size label +
explanation line, then a body-size value box (`background-color: var(--color-bg); border: 1px
solid var(--color-border); border-radius: 6px; padding: var(--space-sm) var(--space-md);`). This
is a **read pattern reuse, not a new component** — do not introduce a new field-row primitive for
two fields.

Field order and content:

1. **Corpus Display Name** (`display_name`)
2. **Oyez Speaker ID** (`oyez_speaker_id`)

Both are **never** added to `PersonUpdate`'s allow-list and **never** rendered as an `<input>` —
they are `<output>` elements exactly like Full Name, with no submit path. Shown unconditionally
for every person (not gated on `is_justice`) — advocates and non-corpus-resolved people show the
blank-value treatment described in the Copywriting Contract below, which is itself informative
(it tells the operator this person has no corpus join).

### Reset to Fixture — Running state (D-15)

The existing single status line (`◌` spinner + text, `app/src/routes/admin/+page.svelte` ~line
442-450) is **not restructured** — same flex row, same spinner glyph and animation, same
`--font-size-body` / `--color-text-secondary` text styling. Only the **text content** changes,
updating in place as the backend reports each step (transport mechanism — polling vs. streamed
response — is a planning/implementation decision, not a UI-SPEC concern; the visual contract is
that the line's text swaps in place with no layout shift, exactly as it does today for its single
static string).

### Reset to Fixture — Error state (D-14)

Same position and same `role="alert"` treatment as today (directly below where the button/status
row was; `color: var(--color-destructive); font-size: var(--font-size-caption);`). What changes
is that there are now four possible outcomes instead of two, because the frontend action re-reads
fixture state before rendering anything — see Copywriting Contract. **One of the four outcomes
renders no error at all**, reusing the existing Success markup instead (see below) — this is the
direct fix for the false-alarm case the folded todo identified.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (unchanged) | "Reset to Fixture" |
| Corpus Display Name — label | "Corpus Display Name" |
| Corpus Display Name — explanation | "The corpus's own name form. Drives utterance attribution; falls back to Full Name when blank." |
| Corpus Display Name — empty value | "Not in corpus" — rendered in `--color-text-secondary`, italic, identical treatment to the existing Full Name "N/A" state |
| Oyez Speaker ID — label | "Oyez Speaker ID" |
| Oyez Speaker ID — explanation | "The corpus join key. Blank means this person has not been matched to a corpus speaker." |
| Oyez Speaker ID — empty value | "Not in corpus" — same treatment as above (identical wording is deliberate: both fields are blank for exactly the same reason, and the operator should read them as one fact, not two) |
| Reset — Running, step 1 | "Seeding justices…" |
| Reset — Running, steps 2–5 | "Reseeding fixture 1 of 4…" / "Reseeding fixture 2 of 4…" / "Reseeding fixture 3 of 4…" / "Reseeding fixture 4 of 4…" (declaration order, per D-15/D-16 — justices seed once, after TRUNCATE and before the four fixture reseeds) |
| Reset — Error, re-read confirms full success | **No error is shown.** Render the existing Success state verbatim (badge + 4-fixture list) — the transient request-level failure is not surfaced to the operator once the follow-up read proves the database is fully and correctly reseeded. |
| Reset — Error, re-read confirms partial state | "Reset failed partway through. A follow-up check found the database only partially reseeded — do not use it until you run Reset to Fixture again." |
| Reset — Error, re-read itself inconclusive | "Reset failed partway through, and a follow-up check could not confirm the database's state. The database may be in an inconsistent state. Check server logs before retrying." (this is the original `RESET_MID_ERROR` string, verbatim — it is now the true fallback, used only when no evidence could be obtained, rather than the default for every failure) |
| Reset — Error, environment/route refusal | "Reset failed: this action is not available in this environment." (unchanged — `RESET_ENV_ERROR`, D-07 defense-in-depth) |
| Destructive confirmation (unchanged) | "Reset to Fixture": two-step inline Confirm reset / Cancel, full wipe-scope statement shown before the destructive action runs — no type-to-confirm input |

**This table amends `43-UI-SPEC.md`'s Copywriting Contract**, whose comment on the two error rows
read "No third variant is ever returned." That lock is explicitly lifted by D-14 — there are now
four outcomes, three of them error-shaped and one of them not, each driven by what the re-read
actually finds rather than by which code path failed.
