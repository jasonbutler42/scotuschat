<objective>
Store the source-sentinel fact on the utterance at import and make the trust floor read it:
a source-unattributed turn contributes PROVISIONAL instead of UNCERTAIN, and an argument more
than half undetermined is held behind the existing typed-reason override.

Purpose: this is the phase's data spine. SPEAKER-01's Treatment D (plan 53-03), the public
payload (53-02) and the admin blocker sentence (53-05) all read the fact this plan stores. The
fact also closes the asymmetry RESEARCH.md found: the participant branch of `_load_constituents`
already lifts a NULL-person floor on a stored fact, the utterance branch never could.

Output: migration 0033 (all three of this phase's utterance columns, so the phase has exactly one
DDL unit), the importer storing `speaker_undetermined`, the PROVISIONAL branch, the majority rule
as a pure domain function, and tests that pin all of it.

**Reversibility — `costly`, rated deliberately.** Migration 0033 is not a one-way door: the columns
are nullable, `downgrade()` drops two constraints and three columns with no data transformation,
and the reseed-don't-migrate doctrine means no stored state needs converting. What it costs is
coordination — the importer, the trust service and the public payload all read these columns —
so it is flagged, not gated. No `checkpoint:decision` is inserted.

**Column-shape decision (Claude's discretion per CONTEXT.md).** Two independent booleans plus one
text column, not a single enum, because a known speaker's inaudible turn (D-04) has
`speaker_undetermined = false` but `is_inaudible_marker = true`, while the ~5,860 double-unknown
turns have both true (RESEARCH.md Assumption A3). Nullable with no database-side default follows
migration 0030's stated precedent: an ADD COLUMN default would write a value into every existing
row, which is a backfill; NULL honestly means "recorded before 0033", and every consumer treats
NULL as not-a-sentinel, which fails closed (the row keeps flooring UNCERTAIN as today). The
digest contract in `api/domain/content_digest.py` is frozen and untouched: the new columns sit
outside its four fields, so a pre-0033 database keeps sentinel rows at NULL until it is reseeded
— the accepted D-10 cost.

<assumption_delta_decision>
- Noun now primary: **the utterance's speaker attribution** — previously two-state
  (resolved `person_id` / unresolved NULL), now three-state: resolved, unresolved-but-real, and
  "the source says it does not know".
- Decision: **add-alongside**. `person_id` stays the single identity key and stays NULL for a
  sentinel row; `speaker_undetermined` is added beside it as a stored provenance fact explaining
  *why* it is NULL. The detector's lexical hit ("not chosen") was a false positive on rejected
  mockup prose; this is the genuine adjacent question.
- Rationale: every existing reader of `person_id` (trust, admin resolve flows, the public avatar
  path) keeps its meaning unchanged, and the CHECK constraint makes "undetermined implies no
  person and not a stage direction" structural.
- What would force a later **promote** to a single `attribution_state` enum: a fourth NULL cause
  on utterances — e.g. an operator "confirm unattributable" action at the utterance level (the
  participant branch already has one), or the PDF path (Phase 999.11) producing its own
  unattributed-speaker marker. At that point two booleans plus NULL stop being orthogonal and an
  enum becomes the honest shape.
</assumption_delta_decision>
