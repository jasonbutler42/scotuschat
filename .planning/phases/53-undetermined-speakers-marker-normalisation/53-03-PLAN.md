<objective>
Render a source-unattributed turn honestly on the public transcript (Treatment D at rest), and
render a whole-turn inaudible body as the transcriber's note inside whatever bubble carries it.

Purpose: SPEAKER-01's visible half and the render side of SPEAKER-06/07. The payload already carries
`speaker_undetermined` and `is_inaudible_marker` (plan 53-02); this plan turns them into the
UI-SPEC's locked geometry, tokens and copy, and records the new type axis in the design system as
D-02 requires. Hover/tap reveal and the explanation card are plan 53-04.

Output: `UndeterminedBubble.svelte`, a third `renderItems` kind, the three new tokens, one shared
body-style rule used by both bubble components, the design-system record, and a real-Chromium test
built on a shared transcript harness.

**Defect fixed as a side effect (Defect Policy, one line in the summary):** two consecutive
undetermined rows both carry `raw_speaker_label === null`, so today's run-continuation check merges
them into one run. Classifying the undetermined kind before run continuation makes each its own
item, which S5 already requires.

**Pitfall 6, resolved by test-first:** Task 1's browser test is written first and run RED against
today's route, with one fixture row deliberately carrying the sentinel string in
`raw_speaker_label`. Record in the summary, in one line, which path rendered it (bubble name row,
roster, row aria-label) — then the fix closes the page by construction (the route never hands an
undetermined row to `ChatBubble` or the roster) and the fixture proves it defensively.

**Styling decision (Claude's discretion, D-12/D-13 "one rule").** The inaudible-body treatment is one
global rule in `app/src/app.css` — `.utterance-body` sets the ordinary ink and style, and
`.utterance-body.is-inaudible-marker` sets `--font-style-italic` and `--color-stage-text` — applied
by both bubble components. Colour moves off the `<p>`'s inline style because an inline `color` would
outrank the class, the same reason the `.speaker-*` rules exist (DESIGN-SYSTEM.md, "Transcript
variant axes"). One rule means the two bubbles cannot drift.

**Flagged planner assumptions:**
- The UI-SPEC's Typography table lists the explanation card's paragraphs as Body while its Layout
  section says Caption; this is plan 53-04's concern and is resolved there toward the Layout section.
- `--bubble-max-width-undetermined` is fixed at the UI-SPEC's 67% / 93%. The operator-only
  `data-width` variant switcher redefines `--bubble-max-width` but not this token, so under a width
  variant the Treatment D ratio no longer tracks 0.928. Recorded in DESIGN-SYSTEM.md; adjustable if
  the operator's eye check says it reads wrong.
</objective>
