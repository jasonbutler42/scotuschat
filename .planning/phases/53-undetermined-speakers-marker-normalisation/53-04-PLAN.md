**Mechanism decisions (Claude's — WCAG and correctness, not taste, per D-16):**
- Reveal is CSS on the row: hover inside `@media (hover: hover)`, `:focus-within` for keyboard, and a
  `data-revealed` attribute for touch — one row-level rule reveals both avatars, so a one-sided reveal
  is structurally impossible. Pseudo-classes cannot be written inline, so this component carries the
  codebase's one component-scoped `<style>` for public transcript interaction; DESIGN-SYSTEM.md
  records the exception.
- Touch is detected by the event's own `pointerType === 'touch'` on a `pointerup` handler, not by a
  media query read at tap time, so a hybrid touch laptop behaves correctly and the handler does not
  trip the click-without-keyboard a11y lint (keyboard users get the same reveal through focus).
- The 120ms opacity transition is an inline value, as the UI-SPEC states — no motion token exists.

**Flagged planner assumptions (surfaced, not silently decided):**
- **SPEAKER-02 / unclassified** (unresolved edge-probe row, carried forward). Covered by the truths
  above; the probe category stays unresolved.
- **Card typography.** The UI-SPEC's Typography table lists the card paragraphs as Body, its Layout
  section as Caption. Resolved toward the Layout section — Caption / regular / `--line-height-body` /
  `--color-text-secondary`, identical to the speaker-bio card's bio paragraph, which is the stated
  analog. The title is Body / semibold / `--color-text-primary`.
- **Card dividers.** Each of the three paragraphs carries the bio card's section divider
  (`border-top` + `margin-top` + `padding-top` at `--space-lg`), so the title is separated from
  paragraph 1 as the bio card separates its header from its first section. The Figma node `33:62`
  was not reachable while planning; the human-check below compares against it.
