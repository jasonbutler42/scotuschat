# Phase 53 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Of SPEAKER-01…08, three (SPEAKER-03, SPEAKER-04, SPEAKER-05) are stored-fact and
trust-floor work with no visual face of their own — they change what data a row carries and how
the publish gate reads it, not what renders. The remaining five have a real visual delta, all on
surfaces that already exist — there is no new page and no new route:

1. **Treatment D — the undetermined-speaker bubble** (SPEAKER-01, SPEAKER-02) — a new rendering
   branch on the public argument transcript (`app/src/routes/arguments/[slug]/+page.svelte`),
   alongside the existing attributed-bubble and stage-direction branches. New component(s); no
   existing component's rest-state markup changes.
2. **The explanation card** (SPEAKER-02) — a new popover, same shape and trigger mechanism as
   the existing `SpeakerPopover.svelte` (shared page-level `Popover.Root`), reached from either
   dashed avatar of a Treatment D bubble.
3. **Attributed-bubble inaudible body** (SPEAKER-07, SPEAKER-08) — `ChatBubble.svelte`'s existing
   `<p>` gains one conditional style branch (italic, muted ink) when its body is a whole-turn
   inaudible marker. Everything else about that bubble — name, avatar, side, rail — is unchanged.
4. **Canonical marker form** (SPEAKER-06) — a copy-only change: `StageDirection.svelte` and the
   Treatment D / attributed-bubble marker body both render the value `detect_stage_direction`
   already computes, instead of the raw verbatim segment they render today. No new component, no
   new visual treatment beyond what each already has.
5. **Admin "why blocked" panel — new blocker sentence** (SPEAKER-05, D-18) — one new branch inside
   the `blockerSentence()` function that exists, verbatim-duplicated, in three admin files
   (`admin/arguments/+page.svelte`, `admin/arguments/[id]/+page.svelte`, `admin/review/+page.svelte`).
   Renders through the exact same `<li>` the other blocker sentences already use — no new markup.

Design basis: `.planning/codebase/DESIGN-SYSTEM.md` (current as of the Phase 51 token
conversion), `.planning/notes/undetermined-speaker-display.md`,
`.planning/notes/transcript-rendering-decision-tree.md`, and Figma `KICu66PtMLHk4fmxJYPggx` ›

### New type axis (D-02) — additions to `app/src/app.css` and `DESIGN-SYSTEM.md`

Two new tokens, following the same "named axis" pattern as `--font-weight-regular` /
`--font-weight-semibold`:

| Token | Value | Usage |
|-------|-------|-------|
| `--font-style-italic` | `italic` | The "undetermined speaker" bubble label (D-02); the inaudible-marker bubble body (D-12); and the **pre-existing raw `font-style: italic;` literal at `StageDirection.svelte` line 29**, which this phase converts to the token in the same pass — same property, same value, the one spot Phase 51's conversion sweep did not reach because `font-style` was not yet a tracked property. |
| `--opacity-muted` | `0.7` | Reduced-emphasis label text — currently exactly one call site, the "undetermined speaker" label (D-02). A named semantic rather than an inline `0.7`, so a second future use (if any) references the same value instead of guessing a second one. |

The "undetermined speaker" label is `italic`, `70%` opacity, **regular weight** (400) — not
semibold — so it reads visibly differently from a real speaker name (which is caption/semibold,
opaque) at a glance, not just on close reading. This is a default resolving an open visual
question the CONTEXT.md decisions did not pin down; it is not itself a locked decision.

The inaudible-marker bubble body is italic at full opacity, in `--color-stage-text` (existing
token, see Color below) — a different treatment from the label, because it answers a different
question ("what was said" vs "who spoke").

## Layout & Placement Contract

### Treatment D bubble (SPEAKER-01) — new render branch

Slots into the transcript's existing top-level render loop
(`app/src/routes/arguments/[slug]/+page.svelte`'s `renderItems`) as a **third kind**, alongside
`'stage'` and `'run'` — keyed off the stored sentinel fact (D-05), never off
`raw_speaker_label` string content. **Consecutive undetermined utterances never merge into one
item** (S5 — "won't fix, shown honestly"): each is always classified as its own singleton, even
when two adjacent rows would otherwise share an equal `raw_speaker_label` (e.g. both the source's
`<INAUDIBLE>` sentinel). The existing `--space-2xl` "speaker change" gap between top-level items
applies between two consecutive Treatment D bubbles exactly as it does between any other pair of
top-level items — no special-cased smaller gap.

**Row structure** (a flex row, centred, three children, no sticky positioning):

```
[ rail-left: 40px ] gap [ bubble: centred, own max-width ] gap [ rail-right: 40px ]
```

- The row is `display: flex; justify-content: center; align-items: center; gap:
  var(--transcript-rail-gap);` — centering the whole three-part cluster centers the bubble
  between the two equal-width rails, which is what D-01 means by "centred."
- **Both rail columns are 40px wide, matching the existing rail column width** used for
  attributed runs — reusing the established gutter rather than inventing a new one.
- **Unlike an attributed run's rail, this one does not need `position: sticky` /
  `align-self: stretch` scroll-tracking.** That mechanism exists solely to keep a tall
  multi-utterance run's avatar visible while scrolling through it; a Treatment D "run" is always
  exactly one utterance (S5), so the rail is simply vertically centred against the bubble's own
  height — no scroll-tracking logic is needed or should be added.
- The bubble itself uses the same background/border/radius as any single-utterance `ChatBubble`
  (`--color-surface` fill, `--color-border` 1px border, `6px 6px 6px 6px` radius — the `single`
  entry in `ChatBubble`'s existing `RADIUS_BY_POSITION` table) and the same internal padding
  (`--space-sm` / `--bubble-pad-x`).

**Bubble width (D-01's "540px vs the standard 582px").** The Figma mockup's ratio is 540:582 ≈
0.928 — about 7% narrower than a standard bubble. Translated into this codebase's existing
percentage/ch-cap geometry (`DESIGN-SYSTEM.md` "Layout geometry"), rather than a hardcoded pixel
value that would not track a future change to `--bubble-max-width`:

| New geometry token | Desktop | ≤768px | Derivation |
|---|---|---|---|
| `--bubble-max-width-undetermined` | `67%` | `93%` | `--bubble-max-width` (72% / 100%) × 0.928, rounded |

Treatment D's max-width expression is `min(var(--bubble-max-width-undetermined), 63ch)` — the
same `min(percentage, ch-cap)` shape `ChatBubble` already uses, with its 68ch cap scaled by the
same 0.928 ratio (68 × 0.928 ≈ 63.1, rounded to 63ch). This is a default resolving CONTEXT.md's
explicit "Claude's Discretion" item on mobile/narrow-viewport geometry — prescriptive so the
executor is not left guessing, but adjustable if a real-browser check shows it reads wrong.

**Rest state — the label is always visible; the rail avatars are not.** At rest:
- The bubble shows the `italic` / `70%`-opacity / regular-weight "undetermined speaker" label
  (see Typography) in the position `ChatBubble`'s existing speaker-name row occupies today —
  above the body text, same `margin-bottom: var(--space-sm)`. Unlike an ordinary run, this label
  renders on **every** Treatment D bubble (never suppressed on a "continuation" bubble), because
  S5 guarantees there is never a continuation to suppress it for.
  - Body text below the label uses ordinary `--font-size-lead` / `--color-text-primary` styling,
    **unless** the row is also a whole-turn inaudible marker (D-15 / U3 in the decision tree), in
    which case the body gets the same italic/`--color-stage-text` treatment specified for the
    attributed-bubble case below (D-13: identical treatment regardless of which bubble it is in).
- **Both 40px rail columns render empty** — present in the DOM (for layout-shift-free reveal and
  keyboard reachability) but visually blank: no avatar shape, no fill, no border.

**Hover/focus/tap reveal (D-01, D-16) — see Interaction & State Contract below** for the full
state machine. Summary: a dashed, outline-only "?" avatar (32px, same size as every other rail
avatar) fades into **both** rail columns together, never one alone.

### Explanation card (SPEAKER-02, D-14/D-15)

Reuses the **same shared page-level `Popover.Root`/`Popover.Content`** instance the route already
declares once for `SpeakerPopover` — not a second popover instance, not a modal, not a new
dismissal mechanism. The route's existing `onAvatarClick`-style handler gains a second content
mode; whichever of the two dashed avatars (left or right) was activated becomes the
`customAnchor`, exactly like every existing avatar button.

- Card shape: identical to `.popover-card` — same `padding: var(--space-xl)`, same
  `Popover.Content` sizing (`min-width: 300px; max-width: 400px`), same
  `background-color: var(--color-surface); border: 1px solid var(--color-border); border-radius:
  8px;` wrapper the route already applies.
- Content: a title row (`Body`/semibold, matching `.popover-card`'s name-row typography) reading
  the exact copy in the Copywriting Contract below, then three fixed paragraphs (Caption/regular,
  matching `.popover-card`'s bio-paragraph typography), each separated by the same
  `border-top: 1px solid var(--color-border); margin-top: var(--space-lg); padding-top:
  var(--space-lg);` rule `.popover-card` already uses between its own sections.
- **No avatar/photo, no name, no role pill, no tenure list** — this card has none of
  `SpeakerPopover`'s per-person data, because there is no person. It is title + body only.
- **No truncation, no scroll, no clamp** — same P-06 rule `.popover-card` already honours.

### Canonical marker form (SPEAKER-06)

No new component and no new visual treatment. `StageDirection.svelte` and the marker-body branch
of `ChatBubble.svelte` continue to render their existing `<p>{utterance.text}</p>` unchanged —
what changes is only **which string the importer writes into that field**: the canonical form
`detect_stage_direction` already computes (D-08/D-09), not the raw verbatim segment. This phase's
UI contract is the canonical vocabulary itself (Copywriting Contract below), not a layout change.

### Attributed-bubble inaudible body (SPEAKER-07/08, D-12/D-13)

One conditional style branch inside `ChatBubble.svelte`'s existing `<p>` element — everything
else about the bubble (speaker name row, avatar, side, rail, radius) is untouched:

```
font-size: var(--font-size-lead);        /* unchanged */
font-weight: var(--font-weight-regular); /* unchanged */
line-height: var(--line-height-lead);    /* unchanged */
font-style: {marker body ? var(--font-style-italic) : normal};
color: {marker body ? var(--color-stage-text) : var(--color-text-primary)};
```

Driven by the stored whole-turn-inaudible-marker fact the utterance carries — never by
string-matching the body text client-side (same "stored, not re-derived" discipline as D-05).
Applies identically whether the bubble is an ordinary attributed bubble (D-4/E4 in the decision
tree) or a Treatment D bubble whose body happens to also be a marker (D-13/U3) — one rule, no
per-bubble-kind branch.

### Admin "why blocked" panel (SPEAKER-05, D-18)

No new markup. The new blocker code renders through the exact `<ul>`/`<li>` structure every other
blocker already uses in all three admin surfaces
(`font-size: var(--font-size-caption); color: var(--color-text-secondary); padding: var(--space-xs)
0;`) — only a new `if` branch inside each of the three duplicated `blockerSentence(code, count)`
functions, following the exact pattern the existing five branches already establish in that
function. The blocker payload needs one additional field beyond today's `{code, count}` to carry
the percentage; naming that field is left to planning (not a visual-contract concern), but the
**rendered sentence and its rounding are locked** — see Copywriting Contract.

### Public schema note (D-07 / PLUMBING-07)

Any new field this phase adds to the public utterance schema (`api/schemas/utterance.py`) to
drive Treatment D or the inaudible-body branch — the sentinel flag, the whole-turn-marker flag,
the canonical marker text — is a **rendering fact, not a trust fact**, and is expected to reach
the public response; PROVISIONAL/trust tier is what must never reach it (D-07, unchanged from
`test_trust_public_leak_ban.py`'s existing ban). If this phase adds a field not already covered by
that test's `PUBLIC_SCHEMA_MODULE_PATHS`, register it there in the same phase — the test does not
auto-discover.

## Interaction & State Contract

Applies to the Treatment D bubble's rail avatars (SPEAKER-02, D-01, D-16). No other element in
this phase has a non-trivial interaction state.

| State | Trigger | Behavior |
|---|---|---|
| **Rest** | default, every device | Both rail columns render empty (no shape, no border). The "undetermined speaker" label is always visible on the bubble itself — this is not part of the reveal. |
| **Reveal — hover** | `@media (hover: hover)`, pointer enters the Treatment D row (rails + bubble together, one hover target) | A dashed, 32px, outline-only "?" avatar fades into **both** rail columns simultaneously (`opacity: 0 → 1`, ~120ms ease; no motion token exists elsewhere in this codebase to reuse, so this is an inline value, not a new token). Never one side alone — D-01's whole point is declining to imply a side. |
| **Reveal — keyboard focus** | Either avatar button receives focus | Both avatars reveal together via `:focus-within` on the row, matching the hover behavior exactly — a keyboard user sees the same two-sided reveal a mouse user does, not a one-sided one. |
| **Reveal — touch** | `@media (hover: none)`, first tap anywhere on the row | Reveals both avatars exactly like hover. **Does not** open the card and **does not** navigate. Requires local per-bubble state (not a page-level flag) — each Treatment D bubble tracks its own revealed/not-revealed state independently. |
| **Activate** | Click/tap directly on either revealed avatar (any device) | Opens the explanation card, anchored to whichever avatar was activated, via the shared `Popover.Root` (same mechanism as every existing avatar). On touch, this is necessarily a **second, separate tap** — after the first tap has already revealed the avatars per the row above. |
| **Bubble body click** | Click/tap on the bubble itself, not an avatar | **Inert.** D-16: "the bubble does not open the card directly." No handler on the bubble body. |
| **Dismiss** | Escape / outside click, with the card open | Identical to the existing `SpeakerPopover` dismissal — no new behavior. |
| **Keyboard reachability** | Tab | Both avatar `<button>` elements are always present in the DOM and always in tab order (`opacity`/`pointer-events` control visibility, never `display: none` or `aria-hidden`) — the existing avatar-button pattern, extended, not a new one (D-16, WCAG). |

Both avatar buttons carry `aria-label="Undetermined speaker details"` — identical text on both
sides, since neither belongs to a specific speaker or side (unlike every other avatar's
`aria-label="View {name} details"`, which this one deliberately does not have a name for). The
Treatment D row's own wrapper carries `aria-label="Undetermined speaker"` in the same
`role="article"` pattern the existing bench/advocate row wrapper uses.

## UI Considerations

> Ran the compiled 8-category shape-rooted taxonomy (`ui-consideration-probe.cjs`) against six
> elements covering every new visual surface in this phase. Elements were classified by explicit
> override (`elements: [...]`), not the prose heuristic, since none of this phase's surfaces are a
> form, list-collection, media, or nav — the four kinds that make `empty` / `populated` /
> `partial` / `zero-one-many` applicable. Nothing here is a collection or a form, so none of those
> four categories are raised; only `loading`, `error`, `overflow`, and `long-text` ever apply,
> which is expected given the nature of these elements (fixed-copy displays and a hover/tap
> reveal, not data-fetching surfaces).

**Coverage:** 15 applicable · 15 resolved (11 explicit, 0 backstop) · 0 unresolved.

| Element | Category | Status | Truth / Reason |
|---------|----------|--------|----------------|
| E1 Treatment D bubble | `loading` | 🚫 dismissed | Renders synchronously from the transcript's own server-loaded utterance data (the existing `+page.server.ts` load) — no independent fetch, so no separate loading phase exists to contract. |
| E1 Treatment D bubble | `error` | 🚫 dismissed | No independent request can fail here; any page-load failure is the existing, unchanged route load-error handling, out of this phase's scope. |
| E1 Treatment D bubble | `overflow` | ✅ resolved (explicit) | The narrower max-width (desktop ~67%/mobile ~93%, scaled from the Figma 540:582 ratio) only changes cap width; no max-height, scroll, or clip is introduced. |
| E1 Treatment D bubble | `long-text` | ✅ resolved (explicit) | Body text uses the same `--font-size-lead` paragraph as ordinary `ChatBubble` content, wraps naturally, never truncates (P-06 unchanged). |
| E2 dashed avatar reveal | `loading` | 🚫 dismissed | A static reveal-on-hover/focus/tap affordance with no fetch behind it; nothing loads. |
| E2 dashed avatar reveal | `error` | 🚫 dismissed | Opens a popover of fixed literal copy (D-14/D-15); no network request exists that can fail. |
| E2 dashed avatar reveal | `long-text` | ✅ resolved (explicit) | The only text is a single fixed glyph, "?"; length cannot vary. |
| E3 explanation popover | `overflow` | ✅ resolved (explicit) | Same `Popover.Content` shape as `SpeakerPopover` (min/max-width 300–400px); P-06 already bans clamp/scroll/truncation on this card shape and this phase inherits that, not a new rule. |
| E3 explanation popover | `long-text` | ✅ resolved (explicit) | All body copy is fixed literal text (D-14's three paragraphs, with the D-15 sentence-1 swap); wraps naturally, no truncation logic added. |
