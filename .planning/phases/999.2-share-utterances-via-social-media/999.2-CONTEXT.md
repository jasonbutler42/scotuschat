## Phase Boundary

Let a visitor share a specific utterance (a single speaker turn) from a published oral argument to social media, to increase site exposure and utilization. This is a new public-facing capability — no such sharing/deep-link mechanism exists today on `/cases/[slug]/arguments/[id]`.

**Why this discussion is thin:** the user opened this session specifically to flag one risk (apolitical framing) before the idea sits in the backlog, not to lock an implementation design. All other gray areas below are explicitly unexplored and open for the next discussion.

## Implementation Decisions

**None locked.** The user declined to answer implementation-shape questions this session, on the record: *"I don't have an opinion just yet and want to re-discuss this when it goes into a phase for development."*

### Open Questions (re-discuss before planning — do not infer answers)

- **Apolitical safeguard (the one thing the user wanted captured):** An isolated quote pulled out of a full oral argument is exactly the editorializing risk PROJECT.md's apolitical-framing hard constraint exists to prevent — a single utterance shared without its surrounding context could read as commentary even though the underlying transcript text is unchanged. No decision on the mitigation (full-context deep link vs. quote card with nearby turns vs. quote card alone; neutrality caption or not; visual treatment) — must be discussed before this phase is planned.
- **Share mechanism:** deep-link/permalink into the full page (scrolled to the utterance) vs. a rendered shareable quote-card image vs. both. No per-utterance anchor exists today — see Existing Code Insights below.
- **Platform & trigger:** Web Share API vs. explicit per-platform buttons vs. plain "Copy link"; where the share control lives on `ChatBubble.svelte`, given a separate pending todo (see Reviewed Todos below) already wants to add an unrelated admin "Edit" affordance to the same component.
- **Social preview metadata:** whether this phase must add `og:title`/`og:description`/`og:image` tags (none exist on any public page today) or whether a bare link is acceptable for a v1.

### Claude's Discretion
None granted this session — every implementation question was explicitly deferred by the user, not delegated.

<code_context>
## Existing Code Insights

### Reusable Assets
- `app/src/lib/components/ChatBubble.svelte` — renders each spoken utterance; would be the natural home for a share affordance, but has no per-utterance DOM id today.
- `api/schemas/utterance.py` (`UtteranceResponse.id`) — utterances already carry a stable numeric `id` in the API response, even though the frontend doesn't currently expose it as a DOM anchor. A per-utterance deep link is feasible without backend schema changes.

### Established Patterns
- `app/src/routes/cases/[slug]/arguments/[id]/+page.svelte` — section-level anchors already exist (`id="section-{hint}-{sequence}"`, first utterance of each section only) with a `SectionRail`/`MobileNavBar` scroll-spy nav. This is the closest existing analog for "jump to a specific point in the transcript," but it operates at section granularity, not per-utterance.
- No social preview metadata (`og:*`/`twitter:card`) exists on any public route today — confirmed via codebase search. A share feature that wants a rich link preview starts from zero here.

### Integration Points
- Any per-utterance anchor/share-trigger addition to `ChatBubble.svelte` sits in the same file a separate pending todo (`2026-07-08-edit-affordance-on-utterances-and-speaker-popover.md`) wants to modify — see Reviewed Todos below. Sequencing matters if both land.

</code_context>
