# Positioning Backlog

This backlog is intentionally separate from the product and code backlog. Items
here are strategy, messaging, research, and design-rationale artifacts for
SCOTUS Chat. They should not be treated as implementation tasks unless they are
later promoted into a product phase.

## Backlog Items

### POS-001: Principles - Done

**Artifact:** `PRINCIPLES.md`

**Status:** Done

Define the durable rules that should govern product, design, and copy decisions.
Expected topics include neutrality, source fidelity, cognitive accessibility,
equal treatment of speakers, no editorial hierarchy, and no invented context.

**Why it matters:** This should become the document used to decide whether a
future feature, layout choice, or piece of copy belongs in SCOTUS Chat.

### POS-002: Voice - Done

**Artifact:** `VOICE.md`

**Status:** Done

Define how SCOTUS Chat should sound across the public site and internal product
language. The voice should be plain, careful, calm, useful, and never pundit-like
or breathless.

Include vocabulary guidance, preferred phrases, phrases to avoid, and examples
of acceptable versus unacceptable copy.

### POS-003: Audience - Done

**Artifact:** `AUDIENCE.md`

**Status:** Done

Document the honest starting point that SCOTUS Chat is first an audience-of-one
product, then define adjacent likely audiences as hypotheses. Potential
audiences include neurodivergent readers, legal students, researchers,
journalists, civic educators, and curious readers.

Also capture what is not yet known about external audience needs.

### POS-004: Homepage Brief - Done

**Artifact:** `HOMEPAGE-BRIEF.md`

**Status:** Done

Define the homepage's job before designing layouts. Capture content priorities,
primary user paths, what the first screen needs to communicate, and what the
homepage should avoid.

**Why it matters:** This is the bridge from positioning work into Figma and
implementation planning.

### POS-005: Messaging - Done

**Artifact:** `MESSAGING.md`

**Status:** Done

Develop reusable copy blocks and messaging options, including tagline
candidates, short product descriptions, About copy, footer copy, empty-state
copy, and a concise "what this is / what this is not" section.

### POS-006: Research Plan

**Artifact:** `RESEARCH-PLAN.md`

Define a future mini-project for testing whether the SCOTUS Chat interface
reduces working memory burden or reading friction for ADHD, AuDHD, and other
neurodivergent readers.

**Why it matters:** This keeps accessibility-forward public claims grounded in
evidence rather than assumption.

### POS-007: Decision Rubric

**Artifact:** `DECISION-RUBRIC.md`

Create a practical checklist for future product and design decisions. The rubric
should help evaluate whether a decision clarifies structure rather than
interpreting meaning, treats speakers equally, reduces cognitive burden, and
preserves trust in the source material.

## Suggested Order

4. POS-004: Homepage Brief - Done
5. POS-005: Messaging - Done
